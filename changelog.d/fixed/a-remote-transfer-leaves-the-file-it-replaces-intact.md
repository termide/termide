- **A remote transfer leaves the file it replaces intact until it is complete.** A download or an upload emptied the file it replaced first, wrote a download through a symlink found there, and left the file half-written when cancelled or cut off. Each now writes a hidden sibling that takes the old file's place at the end, keeping its permission bits. On SFTP the sibling of an upload is created with the replaced file's permission bits, so a private file's new content is never readable by others while it travels, and an upload that cannot keep them fails and leaves the old file rather than replacing it with a more open one; a symlink on the server is still written through, and on a server that offers `posix-rename@openssh.com`, OpenSSH among them, the sibling takes the name in one step, so the name is never empty. SMB, NFS and FTP downloads do the same on the local side. A directory download from SFTP, SMB or NFS refuses an entry name a server gives with a path in it, and one nested too deep fails instead of being skipped, so a move no longer deletes from the server what it did not bring down.
