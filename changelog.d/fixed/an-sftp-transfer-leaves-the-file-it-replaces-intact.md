- **An SFTP transfer leaves the file it replaces intact until it is complete.** A download or an upload emptied the file it replaced first and left it half-written when cancelled or cut off; each now writes a hidden sibling that takes the old file's place at the end, and an upload keeps the replaced file's permission bits (a symlink on the server is still written through): the sibling is created with them, so a private file's new content is never readable by others while it travels, and an upload that cannot keep them fails and leaves the old file rather than replacing it with a more open one. A directory download refuses an entry name a server gives with a path in it, and one nested too deep fails instead of being skipped, so a move no longer deletes from the server what it did not bring down.
