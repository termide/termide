# Удалённые файловые системы (VFS)

Termide содержит чистый Rust-слой VFS, позволяющий [файловому
менеджеру](file-manager.md) просматривать удалённые серверы как
обычные локальные каталоги. Файлы можно открывать в редакторе,
копировать между локальной и удалённой панелями, переименовывать и
т.д. — тот же интерфейс, с прогрессом в [панели
операций](operations.md).

Системные библиотеки не требуются: SFTP работает на `russh` +
`russh-sftp`, FTPS — на `rustls`, SMB — на `smb2`, NFS — на
`nfs3_client`. Статические сборки под Alpine / musl работают «из
коробки».

## Поддерживаемые протоколы

| Схема     | Протокол                                            |
|-----------|-----------------------------------------------------|
| `sftp://` | SSH File Transfer Protocol поверх SSH               |
| `ftp://`  | Обычный FTP                                         |
| `ftps://` | FTP поверх TLS (rustls)                             |
| `smb://`  | SMB 2 и 3: общие папки Windows, Samba и NAS         |
| `nfs://`  | NFS версии 3                                        |

Особенности этих двух — в разделе [SMB и NFS](#smb-и-nfs).

## Синтаксис URL

VFS URL имеет вид:

```
scheme://[user[:password]@]host[:port][/path]
```

Примеры:

```
sftp://nvn@example.com/home/nvn/projects
sftp://example.com:2222/srv/builds
ftp://files.example.com/pub
ftps://secure.example.com/uploads
smb://bob@nas.local/media/films
nfs://nas.local/srv/backup
```

Замечания:
- Не-ASCII символы в `path` поддерживаются; парсер percent-decode'ит
  их обратно в UTF-8 перед отправкой на сервер.
- Если пользователь или порт опущены, SFTP берёт их из настроек SSH
  (см. [Настройки SSH](#настройки-ssh-sftp)).
- Иначе для опущенного порта используется значение по умолчанию
  (22 / 21 / 990 / 445); NFS спрашивает порт у portmapper'а сервера.
- Пароль в URL не используется. Когда сервер требует пароль, Termide
  спрашивает его и может сохранить в [хранилище паролей](passwords.md);
  для SFTP по-прежнему лучше аутентификация по ключу.

## Открытие удалённой локации

Два пути к удалённой панели:

1. **Go to path** — открыть в файловом менеджере поле ввода
   `Go to path` и вставить / ввести VFS URL.
2. **Bookmarks** — сохранить часто используемые удалённые точки и
   возвращаться к ним через меню `Bookmarks`. Записи закладок
   принимают тот же URL-синтаксис; хранятся в
   `~/.config/termide/bookmarks.toml` в Linux, `~/Library/Application Support/termide/bookmarks.toml` в macOS, `%APPDATA%\termide\bookmarks.toml` в Windows (или в `.termide/bookmarks.toml`
   проекта, если нужны проектные shortcut'ы).

В обоих случаях открывается обычная панель файлового менеджера в
удалённом каталоге; всё остальное (раскрытие дерева, копирование,
переименование, свойства по `Space`) полностью совпадает с поведением
локальных панелей.

## Аутентификация (SFTP)

SFTP входит на сервер так же, как `ssh`, а способ выбирают
[настройки SSH](#настройки-ssh-sftp) хоста:

1. **SSH agent** — тот, что указан в `IdentityAgent` (путь к сокету или
   `$VAR` — сокет из этой переменной), иначе тот, на который указывает
   `SSH_AUTH_SOCK`. `IdentityAgent none` отключает agent.
2. **Ключи** — ключи `IdentityFile` этого хоста, затем дефолтные
   (`id_ed25519`, `id_rsa`, `id_ecdsa`, `id_dsa`).
   `IdentitiesOnly yes` пропускает agent и дефолтные ключи.
3. **Пароль** — если способы выше отклонены, Termide берёт пароль из
   [хранилища паролей](passwords.md) или спрашивает его.

`PreferredAuthentications` выбирает из них: без `publickey` agent и
ключи не пробуются; без `password` (или `keyboard-interactive`) пароль
не спрашивается, а отказ во входе сообщается ошибкой.

Зашифрованный ключ, которого нет в agent, просит свою парольную фразу,
когда ничто другое не подошло, — раньше пароля, если только
`PreferredAuthentications` не ставит `password` первым. Фраза берётся из
хранилища или спрашивается и хранится там под путём ключа, так что одна
запись служит всем серверам, которые открывает этот ключ.

FTP и FTPS входят под пользователем из URL; при отказе пароль
спрашивается так же. Без пользователя в URL вход анонимный.

## Настройки SSH (SFTP)

Хост в URL `sftp://` может быть алиасом `Host`: в закладке можно держать
короткий URL (`sftp://my-build-host/path`), а настоящие имя хоста, порт,
пользователя и ключ возьмутся из настроек SSH — как у CLI `ssh`.

Termide читает `~/.ssh/config`, затем `/etc/ssh/ssh_config` так же, как
`ssh`: для каждого параметра действует первое найденное значение,
шаблоны `Host` понимают `*`, `?` и отрицания `!`, а `Include`
выполняется (шаблоны в путях разрешены, относительные пути берутся от
`~/.ssh` или `/etc/ssh`). Используются параметры:

| Параметр | Действие |
|----------|----------|
| `HostName` | Сервер, к которому идёт подключение; `%h` — хост из URL. |
| `Port` | Используется, если в URL нет порта. |
| `User` | Используется, если в URL нет пользователя; без обоих — имя локального пользователя. |
| `IdentityFile`, `IdentitiesOnly` | Какие ключи пробуются и пробуются ли agent и дефолтные ключи. |
| `IdentityAgent` | Какой SSH agent используется; `none` — никакой. |
| `PreferredAuthentications` | Пробуются ли ключи (`publickey`) и пароль и что первым. |
| `UserKnownHostsFile`, `GlobalKnownHostsFile` | Где ищутся ключи серверов. |
| `HostKeyAlias` | Имя, под которым ключ сервера ищется и записывается. |
| `HashKnownHosts` | `yes` записывает запомненные ключи с хешированным именем хоста. |
| `StrictHostKeyChecking` | `yes` отклоняет неизвестный ключ сервера вместо вопроса. |
| `ProxyJump` | Промежуточные хосты, через которые идёт подключение; см. ниже. |

Порт или пользователь, указанные в URL, важнее `Port` и `User` — как в
командной строке `ssh`. Блоки `Match` пропускаются целиком, поскольку
не все их условия можно проверить. `ProxyCommand` не учитывается:
Termide не запускает команды из настроек SSH, поэтому к такому хосту
подключение идёт напрямую; используйте вместо него `ProxyJump`.
Остальные параметры тоже не учитываются.

`%`-подстановки раскрываются там, где их допускает `ssh_config(5)`:

| Подстановка | Значение |
|-------------|----------|
| `%h` | Хост, к которому идёт подключение (после `HostName`). |
| `%n` | Хост в том виде, как он записан в URL или в `ProxyJump`. |
| `%p` | Порт подключения. |
| `%r` | Удалённый пользователь. |
| `%u` | Имя локального пользователя. |
| `%d` | Домашний каталог. |
| `%k` | `HostKeyAlias`, иначе хост в записанном виде. |
| `%%` | Символ `%`. |

`HostName` принимает `%h` и `%%`; `ProxyJump` — `%h`, `%n`, `%p`, `%r` и
`%%`; `IdentityFile` и `UserKnownHostsFile` — все перечисленные.
Остальные подстановки (`%C`, `%i`, `%j`, `%L`, `%l`) остаются как есть.

### Промежуточные хосты

С `ProxyJump` (`[user@]host[:port]` или `ssh://[user@]host[:port]`,
несколько через запятую, обходятся по порядку) Termide по очереди входит
на каждый промежуточный хост, просит его открыть соединение со
следующим и запускает следующий SSH-сеанс внутри этого соединения — как
`ssh -J`. `ProxyJump none` отключает это для хоста.

- Каждый промежуточный хост определяется по собственной записи `Host`:
  `HostName`, `Port`, `User`, ключи и параметры `known_hosts`.
  Пользователь или порт, указанные в `ProxyJump`, важнее этой записи.
  У первого хоста списка может быть свой `ProxyJump`; остальные
  достигаются через предыдущие. Больше 8 промежуточных хостов на пути к
  одному серверу не допускается — это же останавливает зацикливание.
- Ключ каждого промежуточного хоста проверяется как любой ключ сервера
  (см. ниже) до того, как ему что-либо отправлено. Вопрос или отказ
  называет именно этот хост, а ответ записывается в его `known_hosts`.
- На промежуточные хосты Termide входит только через SSH agent и ключи
  без пароля. Отказ во входе на промежуточный хост сообщается
  ошибкой с его именем; пароль, который Termide спрашивает или берёт из
  хранилища, отправляется только серверу из URL. Парольная фраза
  зашифрованного ключа для промежуточного хоста не спрашивается:
  загрузите ключ в SSH agent.

## Ключи сервера (SFTP)

Прежде чем что-либо отправить SFTP-серверу — в том числе пароль, —
Termide проверяет ключ сервера так же, как OpenSSH: по файлам из
`UserKnownHostsFile` и `GlobalKnownHostsFile`, по умолчанию
`~/.ssh/known_hosts`, `~/.ssh/known_hosts2`,
`/etc/ssh/ssh_known_hosts` и `/etc/ssh/ssh_known_hosts2`. Сервер
ищется под своим `HostKeyAlias`, если он задан, иначе под `HostName`,
а на порту, отличном от 22, — как `[имя]:порт`. Понимаются
хешированные записи (`|1|…`), шаблоны и отрицания `!`.

- **Ключ записан** — подключение идёт дальше молча.
- **Неизвестный хост** — подключение останавливается, и диалог
  показывает хост, тип ключа и отпечаток SHA256 в том виде, в каком их
  печатает `ssh`. Сверьте отпечаток с заведомо верным и выберите:
  - **Принять и запомнить** — ключ дописывается в формате OpenSSH в
    первый `UserKnownHostsFile` (по умолчанию `~/.ssh/known_hosts`;
    если их нет, каталог создаётся с правами 0700, а файл — с 0600),
    при `HashKnownHosts yes` — с хешированным именем хоста, и
    подключение повторяется. В следующий раз — и здесь, и в `ssh` —
    оно пройдёт молча. При `UserKnownHostsFile none` запомнить ключ
    негде, работает только **Принять однократно**.
  - **Принять однократно** — ключу доверяют до выхода из Termide,
    ничего не записывается.
  - **Отмена** *(выбрана по умолчанию)* — подключения не будет. `Esc`
    делает то же самое.

  При `StrictHostKeyChecking yes` вопроса нет: подключение отклоняется,
  а сообщение показывает отпечаток. Любое другое значение (`ask`,
  `accept-new`, `no`, `off`) приводит к вопросу, как выше; без вопроса
  Termide неизвестный ключ никогда не принимает.
- **Ключ изменился** — если записанный ключ того же типа другой или
  ключ помечен `@revoked`, подключение отклоняется, а диалог называет
  файл `known_hosts` и строку. Обойти это нельзя: если замена ожидаема,
  удалите старый ключ командой `ssh-keygen -R`, которую называет
  диалог, и подключитесь снова.

## SMB и NFS

`smb://host/share/path` открывает общую папку по SMB 2 или 3, а
`smb://host/` показывает общие папки сервера как каталоги (скрытые
папки `$` и принтеры не показываются). Пользователь указывается в
адресе: `smb://bob@nas.local/media`, с доменом —
`smb://CORP;bob@server/media`. Когда сервер требует пароль, Termide
спрашивает его и может сохранить в [хранилище паролей](passwords.md).
Без пользователя вход идёт гостем, что сервер может отклонить; тогда
укажите пользователя.

`nfs://host/export/path` открывает экспорт NFSv3, а `nfs://host/`
показывает экспорты сервера как каталоги: экспорт `/srv/media` виден как
`srv` с `media` внутри. Пароля у NFS нет. Сервер доверяет
идентификаторам пользователя и группы, которые присылает клиент, поэтому
Termide присылает ваши — как системный клиент NFS, — а сервер
сопоставляет их по своим правилам (`root_squash`, `all_squash`). Порт в
адресе (`nfs://nas:2049/srv`) — это порт службы NFS; если у сервера нет
portmapper'а, служба монтирования ищется на том же порту, поскольку
серверы в контейнерах часто отвечают на нём обеим.

Два вида экспортов открыть нельзя, и панель говорит, какой и почему:

- **Экспорт, принимающий запросы только с привилегированного порта**
  (ниже 1024). Это умолчание Linux, `secure`, а Linux даёт такие порты
  только root; macOS начиная с 10.14 даёт их всем. Добавьте `insecure` в
  параметры экспорта на сервере или смонтируйте экспорт средствами
  системы и откройте точку монтирования.
- **Экспорт, требующий Kerberos** (`sec=krb5`, `krb5i` или `krb5p`).
  Смонтируйте его средствами системы и откройте точку монтирования.

Сервер, говорящий только на NFSv4, тоже недоступен; большинство серверов
отдают версию 3 вместе с ней.

## Поведение удалённых панелей

Все удалённые операции асинхронны:

- Первое чтение каталога показывает короткий спиннер; записи
  появляются как только сервер ответит.
- Раскрытие подкаталога вставляет маленький `…`-плейсхолдер; когда
  листинг придёт, он заменяется реальными детьми.
- Состояние дерева, курсор и выделение сохраняются между перезагрузками.

Размеры каталогов в wide view **не** считаются для удалённых панелей —
обход удалённого дерева ради одного столбца дороже, чем выгода.
Колонка размера для remote всегда пустая.

## Передача файлов

Выберите файлы в одной панели, нажмите `C` / `F5` (копирование) или
`M` / `F6` (перемещение), укажите назначение — локальный путь или
другую удалённую панель. Передача регистрируется как операция в
[панели операций](operations.md) со следующим:

- Реальный progress bar (байты + файлы), обновляемый воркером на
  каждый chunk.
- Pause / Resume действительно останавливает поток байт (paused
  uploads / downloads висят на worker'е; актор SFTP остаётся свободен
  для metadata-запросов других панелей).
- Cancel останавливает чисто между chunk'ами. Если осталась
  частичная копия на сервере, панель предложит её удалить — см.
  раздел очистки после отмены в [панели операций](operations.md).

Перемещение в пределах одного соединения выполняется переименованием на
сервере, а не скачиванием и повторной загрузкой; для SMB — в пределах
одной общей папки, для NFS — одного экспорта, как позволяют протоколы.
В остальных случаях перемещение копирует, а затем удаляет.

## Проекты

Раскладка проекта с удалённой панелью сохраняет URL точно так же, как
для локального пути. При следующем запуске Termide переподключается в
фоне и показывает панель с загрузочным placeholder'ом до прихода
листинга — остальной UI отзывается сразу.

### Обрыв соединения

Если удалённая сессия потеряна (таймаут простоя, обрыв сети),
следующая операция завершается ошибкой, и панель показывает диалог
восстановления с тремя вариантами: **Переподключиться** (свежая сессия
к тому же пути), **Открыть домашний (локально)** (сбросить соединение и
переключить панель на локальный домашний каталог) или **Закрыть
панель**. `Esc` закрывает диалог, оставляя панель на последнем листинге.
Бесконечного цикла ошибки больше нет.

Соединение, которое всё ещё открывается спустя `connection_timeout_secs`
секунд из `[vfs]` (по умолчанию `60`; в настройках **VFS → Таймаут
соединения (сек)**), прерывается, и панель сообщает об этом. Открытие архива —
локальная работа, тайм-аута у него нет; `Esc` отменяет его.

## Архивы

Файлы архивов открываются в файловом менеджере как каталоги: `Enter` на
архиве показывает его содержимое, а `..` (или `Backspace`) в корне
архива возвращает в каталог, где он лежит, с курсором на архиве. `F3`,
`F4` и `O` по-прежнему работают с архивом как с файлом.

| Формат | Имена |
|--------|-------|
| ZIP    | `.zip`, `.jar`, `.war`, `.apk`, `.whl` |
| tar    | `.tar`, `.tar.gz` / `.tgz`, `.tar.bz2` / `.tbz2`, `.tar.xz` / `.txz`, `.tar.zst` / `.tzst` |
| ISO 9660 | `.iso` |

Формат определяется по содержимому файла; имя решает только то, какие
файлы `Enter` открывает таким образом. При открытии один раз читается
оглавление архива — для большого сжатого tar это проход по всему файлу,
его можно прервать `Esc`. Если архив изменился на диске, пока он открыт,
при следующем обращении оглавление читается заново.

Архив в удалённой панели или внутри другого архива открывается так же:
сначала он целиком копируется во временный каталог (в строке статуса в
это время `Opening …`), а копия удаляется при выходе из архива.
Изменения удалённого файла, пока архив открыт, не отслеживаются.

Зашифрованный ZIP (ZipCrypto или AES) при открытии запрашивает пароль,
а после неверного — ещё раз. Пароль проверяется расшифровкой самой
маленькой зашифрованной записи и хранится только пока архив открыт.

Имена в ZIP читаются как UTF-8, если они корректны в UTF-8 (так их пишет
macOS, не отмечая этого). Старые архивы из Windows хранят имена в
системной кодировке: архив, имена в котором похожи на кириллицу в CP866,
читается как CP866, всё остальное — как CP437, кодировка, которую
называет формат ZIP.

Образ ISO показывает дерево Rock Ridge (POSIX-имена, права и
символические ссылки), если оно есть, иначе дерево Joliet (длинные
имена в Unicode), иначе голые имена ISO 9660 вида `README.TXT`. UDF не
читается: образ, который хранит файлы только в UDF (установочные образы
Windows, DVD-Video, Blu-ray), показывает лишь небольшую часть ISO 9660
рядом с ним — обычно одинокий `README.TXT`.

Архивы доступны **только для чтения**. Файл из архива открывается так же,
как удалённый (через временную копию), а копирование `C` / `F5` в
локальную панель распаковывает выбранные файлы и каталоги — с обычным
прогрессом, паузой и отменой в [панели операций](operations.md).
Создание, удаление, перемещение и переименование внутри архива
отклоняются с сообщением.

Распаковка никогда не пишет за пределы назначения: записи с `..` или
абсолютным путём в имени не показываются, символическая ссылка создаётся
только если её цель остаётся внутри распаковываемого дерева — с учётом
других ссылок архива, так, как её разрешит система, — и только после
записи всех файлов. Через символическую ссылку, которая уже есть в
назначении, ничего не пишется: ссылка на месте файла заменяется файлом,
а ссылка на месте каталога останавливает распаковку с ошибкой. Запись,
которая распаковывается в больший объём, чем заявлено, завершается
ошибкой, а не заполняет диск.

URL места внутри архива имеет вид
`archive://<файл архива>!<путь внутри>`, например
`archive:///home/nvn/src.tar.gz!/docs`; он работает в `Go to path` и
в сохранённых проектах, как любой другой VFS URL.

### Упаковка

`P` (или `Alt+F5`) упаковывает выбранные файлы и каталоги (или запись под курсором) в
новый архив. Окно предлагает `<имя>.zip` рядом с выбранным; формат
задаётся расширением имени — `.zip`, `.tar`, `.tar.gz`, `.tar.bz2`,
`.tar.xz` или `.tar.zst`, — а строка **Формат** под именем меняет его на
другое поддерживаемое. Относительный путь берётся от каталога выбранного, а для
каталога архив создаётся внутри него с именем по выбранному.

Строка **Сжатие** под ней (переход — `↓`, выбор — `←`/`→`, `Пробел`
или щелчок, как и у **Формата**) задаёт **Без сжатия**, **Быстрое**, **Обычное** (по
умолчанию) или **Максимальное**. Для zip, `.tar.gz`, `.tar.bz2` и
`.tar.xz` это уровни 0, 1, 6 и 9; у bzip2 и xz нет режима без сжатия,
поэтому **Без сжатия** даёт их самый слабый уровень. `.tar.zst`
различает только **Без сжатия** и остальные, а простой `.tar` не
сжимается никогда.

Упаковка идёт в [панели операций](operations.md) с прогрессом, паузой
и отменой. Символические ссылки сохраняются как ссылки, а не
разворачиваются; права и время изменения сохраняются. Архив пишется во
временный файл и появляется под своим именем только целиком, так что
отменённая или упавшая упаковка ничего не оставляет, а существующий
файл никогда не перезаписывается. Упаковывать можно только локальные
файлы.

### Распаковка

`Alt+F9` распаковывает архивы из выделения или архив под курсором; остальные
выделенные элементы пропускаются. Окно предлагает каталог с именем архива в
каталоге ближайшего другого файлового менеджера, а каталоги остальных
панелей — в [дереве каталогов](file-manager.md#путь-назначения). Один архив распаковывается в указанный каталог
(он создаётся при необходимости); несколько архивов — каждый в свой каталог
с именем архива внутри указанного. Относительный путь берётся от каталога
архива.

Распаковка идёт в [панели операций](operations.md) с прогрессом, паузой и
отменой. Если в целевом каталоге уже есть файлы, Termide сначала спросит:
файлы с совпадающими именами будут заменены. Распаковывать можно только
локальные архивы. Для зашифрованного zip-архива Termide спросит пароль до
начала распаковки и переспросит, если пароль неверный.

## Ограничения / известные пробелы

- Поиск и замена по файлам работают только в локальных папках: в
  удалённой панели и внутри архива они отклоняются с сообщением.
- NFS версии 4 и Kerberos не поддерживаются, а экспорт, ограниченный
  привилегированными портами, в Linux требует root; см.
  [SMB и NFS](#smb-и-nfs).
- Нет резюма прерванной передачи с offset'a: отменённые upload'ы при
  повторе начинаются сначала.
- Парольная фраза зашифрованного SSH-ключа в удалённых панелях не
  спрашивается; загрузите ключ в SSH agent.
- Сертификаты хостов (`@cert-authority`) не принимаются, а сертификаты
  пользователя (`CertificateFile`) не предъявляются.
- Блоки `Match` в настройках SSH пропускаются, `ProxyCommand` не
  запускается, а подстановки `%C`, `%i`, `%j`, `%L` и `%l` не
  раскрываются.
- Промежуточные хосты не принимают вход по паролю; загрузите их ключ в
  SSH agent или укажите его в `IdentityFile`.
