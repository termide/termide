# Удалённые файловые системы (VFS)

TermIDE содержит чистый Rust-слой VFS, позволяющий [файловому
менеджеру](file-manager.md) просматривать удалённые серверы как
обычные локальные каталоги. Файлы можно открывать в редакторе,
копировать между локальной и удалённой панелями, переименовывать и
т.д. — тот же интерфейс, с прогрессом в [панели
операций](operations.md).

Системные библиотеки не требуются: SFTP работает на `russh` +
`russh-sftp`, FTPS — на `rustls`. Статические сборки под Alpine / musl
работают «из коробки».

## Поддерживаемые протоколы

| Схема     | Протокол                                            |
|-----------|-----------------------------------------------------|
| `sftp://` | SSH File Transfer Protocol поверх SSH               |
| `ftp://`  | Обычный FTP                                         |
| `ftps://` | FTP поверх TLS (rustls)                             |

`smb://` и `nfs://` распознаются парсером URL, но соответствующих
провайдеров пока нет в поставке — используйте нативное монтирование
ОС.

## Синтаксис URL

VFS URL имеет вид:

```
scheme://[user[:password]@]host[:port][/path]
```

Примеры:

```
sftp://nvn@example.com/home/nvn/projects
sftp://example.com:2222/srv/builds
ftp://files.example.com/pub
ftps://secure.example.com/uploads
```

Замечания:
- Не-ASCII символы в `path` поддерживаются; парсер percent-decode'ит
  их обратно в UTF-8 перед отправкой на сервер.
- Если пользователь опущен, провайдер SFTP подставляет значение из
  SSH config (см. Аутентификацию).
- Если порт опущен, используется значение по умолчанию (22 / 21 / 990).
- Пароль в URL не используется. Когда сервер требует пароль, TermIDE
  спрашивает его и может сохранить в [хранилище паролей](passwords.md);
  для SFTP по-прежнему лучше аутентификация по ключу.

## Открытие удалённой локации

Два пути к удалённой панели:

1. **Go to path** — открыть в файловом менеджере поле ввода
   `Go to path` и вставить / ввести VFS URL.
2. **Bookmarks** — сохранить часто используемые удалённые точки и
   возвращаться к ним через меню `Bookmarks`. Записи закладок
   принимают тот же URL-синтаксис; хранятся в
   `~/.config/termide/bookmarks.toml` (или в `.termide/bookmarks.toml`
   проекта, если нужны проектные shortcut'ы).

В обоих случаях открывается обычная панель файлового менеджера в
удалённом каталоге; всё остальное (раскрытие дерева, копирование,
переименование, свойства по `Space`) полностью совпадает с поведением
локальных панелей.

## Аутентификация (SFTP)

SFTP поддерживает четыре режима аутентификации:

- **`Auto`** *(по умолчанию)* — пробует сначала SSH agent, затем ключи
  из `~/.ssh/config` для этого хоста (включая `IdentityFile`, `User`,
  `Port`, `Hostname`-алиасы), затем дефолтные ключи (`id_ed25519`,
  `id_rsa`, `id_ecdsa`, `id_dsa`), затем пароль.
- **SSH agent** — использует SSH agent, если `SSH_AUTH_SOCK` указывает
  на работающий.
- **SSH key** — явный приватный ключ, опционально с парольной фразой.
- **Password** — если способы выше отклонены, TermIDE берёт пароль из
  [хранилища паролей](passwords.md) или спрашивает его.

FTP и FTPS входят под пользователем из URL; при отказе пароль
спрашивается так же. Без пользователя в URL вход анонимный.

Поскольку `Auto` читает `~/.ssh/config`, в bookmark можно держать
короткий URL (`sftp://my-build-host/path`) и позволить SSH config
подставить настоящие host, user, ключ. Та же конфигурация, что
использует CLI `ssh`.

## Поведение удалённых панелей

Все удалённые операции асинхронны:

- Первое чтение каталога показывает короткий спиннер; записи
  появляются как только сервер ответит.
- Раскрытие подкаталога вставляет маленький `…`-плейсхолдер; когда
  листинг придёт, он заменяется реальными детьми.
- Состояние дерева, курсор и выделение сохраняются между перезагрузками.

Размеры каталогов в wide view **не** считаются для удалённых панелей —
обход удалённого дерева ради одного столбца дороже, чем выгода.
Колонка размера для remote всегда пустая.

## Передача файлов

Выберите файлы в одной панели, нажмите `C` / `F5` (копирование) или
`M` / `F6` (перемещение), укажите назначение — локальный путь или
другую удалённую панель. Передача регистрируется как операция в
[панели операций](operations.md) со следующим:

- Реальный progress bar (байты + файлы), обновляемый воркером на
  каждый chunk.
- Pause / Resume действительно останавливает поток байт (paused
  uploads / downloads висят на worker'е; актор SFTP остаётся свободен
  для metadata-запросов других панелей).
- Cancel останавливает чисто между chunk'ами. Если осталась
  частичная копия на сервере, панель предложит её удалить — см.
  раздел очистки после отмены в [панели операций](operations.md).

Переименование внутри одного SFTP / FTP-соединения остаётся на
сервере: move в пределах одного хоста выполняется как remote-rename,
а не download-then-upload.

## Проекты

Раскладка проекта с удалённой панелью сохраняет URL точно так же, как
для локального пути. При следующем запуске TermIDE переподключается в
фоне и показывает панель с загрузочным placeholder'ом до прихода
листинга — остальной UI отзывается сразу.

### Обрыв соединения

Если удалённая сессия потеряна (таймаут простоя, обрыв сети),
следующая операция завершается ошибкой, и панель показывает диалог
восстановления с тремя вариантами: **Переподключиться** (свежая сессия
к тому же пути), **Открыть домашний (локально)** (сбросить соединение и
переключить панель на локальный домашний каталог) или **Закрыть
панель**. `Esc` закрывает диалог, оставляя панель на последнем листинге.
Бесконечного цикла ошибки больше нет.

## Архивы

Файлы архивов открываются в файловом менеджере как каталоги: `Enter` на
архиве показывает его содержимое, а `..` (или `Backspace`) в корне
архива возвращает в каталог, где он лежит, с курсором на архиве. `F3`,
`F4` и `O` по-прежнему работают с архивом как с файлом.

| Формат | Имена |
|--------|-------|
| ZIP    | `.zip`, `.jar`, `.war`, `.apk`, `.whl` |
| tar    | `.tar`, `.tar.gz` / `.tgz`, `.tar.bz2` / `.tbz2`, `.tar.xz` / `.txz`, `.tar.zst` / `.tzst` |
| ISO 9660 | `.iso` |

Формат определяется по содержимому файла; имя решает только то, какие
файлы `Enter` открывает таким образом. При открытии один раз читается
оглавление архива — для большого сжатого tar это проход по всему файлу,
его можно прервать `Esc`. Если архив изменился на диске, пока он открыт,
при следующем обращении оглавление читается заново.

Архив в удалённой панели или внутри другого архива открывается так же:
сначала он целиком копируется во временный каталог (в строке статуса в
это время `Opening …`), а копия удаляется при выходе из архива.
Изменения удалённого файла, пока архив открыт, не отслеживаются.

Зашифрованный ZIP (ZipCrypto или AES) при открытии запрашивает пароль,
а после неверного — ещё раз. Пароль проверяется расшифровкой самой
маленькой зашифрованной записи и хранится только пока архив открыт.

Имена в ZIP читаются как UTF-8, если они корректны в UTF-8 (так их пишет
macOS, не отмечая этого). Старые архивы из Windows хранят имена в
системной кодировке: архив, имена в котором похожи на кириллицу в CP866,
читается как CP866, всё остальное — как CP437, кодировка, которую
называет формат ZIP.

Образ ISO показывает дерево Rock Ridge (POSIX-имена, права и
символические ссылки), если оно есть, иначе дерево Joliet (длинные
имена в Unicode), иначе голые имена ISO 9660 вида `README.TXT`. UDF не
читается: образ, который хранит файлы только в UDF (установочные образы
Windows, DVD-Video, Blu-ray), показывает лишь небольшую часть ISO 9660
рядом с ним — обычно одинокий `README.TXT`.

Архивы доступны **только для чтения**. Файл из архива открывается так же,
как удалённый (через временную копию), а копирование `C` / `F5` в
локальную панель распаковывает выбранные файлы и каталоги — с обычным
прогрессом, паузой и отменой в [панели операций](operations.md).
Создание, удаление, перемещение и переименование внутри архива
отклоняются с сообщением.

Распаковка никогда не пишет за пределы назначения: записи с `..` или
абсолютным путём в имени не показываются, символическая ссылка создаётся
только если её цель остаётся внутри распаковываемого дерева (и только
после записи всех файлов), а запись, которая распаковывается в больший
объём, чем заявлено, завершается ошибкой, а не заполняет диск.

URL места внутри архива имеет вид
`archive://<файл архива>!<путь внутри>`, например
`archive:///home/nvn/src.tar.gz!/docs`; он работает в `Go to path` и
в сохранённых проектах, как любой другой VFS URL.

### Упаковка

`P` упаковывает выбранные файлы и каталоги (или запись под курсором) в
новый архив. Окно предлагает `<имя>.zip` рядом с выбранным, а
остальные форматы — в выпадающем списке; формат задаётся расширением
имени — `.zip`, `.tar`, `.tar.gz`, `.tar.bz2`, `.tar.xz` или
`.tar.zst`. Относительный путь берётся от каталога выбранного, а для
каталога архив создаётся внутри него с именем по выбранному.

Упаковка идёт в [панели операций](operations.md) с прогрессом, паузой
и отменой. Символические ссылки сохраняются как ссылки, а не
разворачиваются; права и время изменения сохраняются. Архив пишется во
временный файл и появляется под своим именем только целиком, так что
отменённая или упавшая упаковка ничего не оставляет, а существующий
файл никогда не перезаписывается. Упаковывать можно только локальные
файлы.

## Ограничения / известные пробелы

- Провайдеры `smb://` / `nfs://` пока не реализованы — только разбор
  URL.
- Нет резюма прерванной передачи с offset'a: отменённые upload'ы при
  повторе начинаются сначала.
- Парольная фраза зашифрованного SSH-ключа в удалённых панелях не
  спрашивается; загрузите ключ в SSH agent.
