# Агент-программист

В TermIDE встроен агент-программист: панель, где вы описываете задачу
обычными словами, а языковая модель выполняет её, читая файлы, изменяя их и
запуская команды в вашем проекте. Всё, что может что-то изменить, сначала
спрашивает у вас разрешение.

Открывается по `Alt+A`, через **Окна → Агент** или из палитры команд
(**Open Agent**).

## Настройка модели

Агент обращается к модели через **подключение**: сервер, совместимый с API
OpenAI, Anthropic Messages API или CLI-агент. Протокол OpenAI покрывает
локальные серверы (llama.cpp, Ollama, vLLM, omlx) и большинство облачных
шлюзов, включая OpenAI и OpenRouter. По умолчанию подключений нет; пока нет ни одного,
панель не открывается и сообщает об этом.

```toml
[ai]
connection = "local"               # подключение для новых сессий; иначе первое по имени
max_tokens_per_turn = 0            # по умолчанию: без ограничения, решает модель
reasoning = "high"                 # по умолчанию; off | minimal | low | medium | high | xhigh | max
fold_blocks = "immediately"        # immediately (по умолчанию) | on-finish | never
bell_on_attention = true           # по умолчанию; звонок, когда панель вне поля зрения ждёт вас

[ai.connections.local]
provider = "openai_compatible"     # openai_compatible (по умолчанию), anthropic_compatible, claude_code, codex, gemini_cli
base_url = "http://127.0.0.1:10000/v1"
model = "Qwen3.8-Flash-Next-oQ4e-mtp"  # не задано: первая модель провайдера
# api_key_env = "OPENAI_API_KEY"   # имя переменной, а не сам ключ
# context_window_fallback = 32000  # только если сервер не сообщает окно
# prefill_progress = true          # просить у сервера llama.cpp прогресс обработки промпта
# reasoning_param = "enable_thinking"  # auto (по умолчанию) | reasoning_effort | enable_thinking | none

[ai.connections.cloud]
provider = "anthropic_compatible"
model = "claude-sonnet-5"
api_key_env = "ANTHROPIC_API_KEY"

[ai.connections.codex]
provider = "codex"                 # CLI-агенту больше ничего не нужно
```

Подключение задаёт `provider`, `base_url`, `model`, `api_key_env`,
`context_window_fallback` и, для `openai_compatible`, `prefill_progress` и
`reasoning_param`; не указанное в нём берёт значение этого поля по умолчанию. `prefill_progress`
добавляет в каждый запрос `return_progress`, на который llama.cpp отвечает
прогрессом обработки промпта; по умолчанию он выключен, потому что сервер, не
знающий этого поля (в том числе API самой OpenAI), может отклонить запрос. Всё остальное в `[ai]` — предел вывода, рассуждения, разрешения,
сжатие и прочее — действует, на каком бы подключении ни шла сессия.

`reasoning` — уровень рассуждений, с которым стартуют новые сессии: `off`,
`minimal`, `low`, `medium`, `high` (по умолчанию), `xhigh` или `max`. Каждая
модель предлагает уровни, которые принимает её API, а недостающий уровень
сводится к ближайшему из имеющихся: Claude Opus 5.5 и Fable не умеют не
думать, поэтому `off` получает их наименьшее усилие, а `max` у модели, где
потолок `high`, становится `high`. В Messages API форму задаёт модель:
адаптивное мышление с усилием у Claude 4.6 и новее (с запросом краткого
изложения рассуждений, которое новые модели иначе не возвращают), бюджет
мышления у Claude 4.5 и старше и у собственных моделей шлюза.
OpenAI-совместимое подключение передаёт уровень в поле, которое называет его
`reasoning_param`: `reasoning_effort` (модели OpenAI предлагают свой набор
значений, остальные — `low`, `medium` и `high`), `enable_thinking` —
`chat_template_kwargs.enable_thinking`, переключатель вкл/выкл в шаблонах чата
Qwen3, GLM и DeepSeek на vLLM или llama.cpp, — или `none`. Значение по
умолчанию, `auto`, передаёт `reasoning_effort` в OpenAI, OpenRouter и Gemini
API, `enable_thinking` — серверу на этой машине или в локальной сети
(`localhost`, имя `.local`, loopback- или частный адрес), — так чип
**Reasoning** появляется и у локальной модели, — и ничего — другим серверам,
которые могут отклонить незнакомое поле;
модель, которой ничего не передаётся, рассуждает так, как настроен её сервер,
и чипа **Reasoning** у неё нет. Прежний `prefer_reasoning = true | false` по-прежнему
читается — как `high` или `off`.

В модале настроек (шестерёнка или палитра команд) всё это есть в разделе
**AI**. Первым идёт список **Connections**: в каждой строке имя подключения,
его провайдер и модель, а подключение для новых сессий отмечено `●`. `Enter`
или клик открывают подключение на отдельной странице — имя, провайдер,
base URL, переменная с ключом API, модель, контекстное окно, **Прогресс
prefill (llama.cpp)** и **Параметр рассуждений** (у OpenAI-совместимого) и **Использовать
по умолчанию** (на нём стартуют новые сессии), — а **[ К списку ]**, `Esc` или
`Backspace` возвращают к списку; **+ Добавить подключение** добавляет
OpenAI-совместимое, а **[ Удалить подключение ]** на странице или `Del` на
строке удаляют его. Подключение по умолчанию всегда ровно одно: им становится
первое добавленное, следующее — только если отметить его галочку, а снятая
галочка (или удаление подключения по умолчанию) передаёт роль первому другому
подключению по имени.
Новое подключение называется по провайдеру, пока вы не дадите ему имя. Модель
— это дропдаун: первым идёт **Авто — на выбор провайдера**, затем модели
подключения (подгружаются в фоне при открытии его страницы), а последний пункт
«Enter a model id…» позволяет ввести id вручную, если эндпоинт не отдаёт
список. Авто — модель подключения не задана — берёт первую модель из списка
провайдера (CLI-агент — свою по умолчанию); запрос, отправленный до прихода
списка, остаётся в поле ввода с уведомлением. Текстовые поля редактируются как
любой ввод в termide: курсор ходит по символам и словам, `Shift` или
протягивание мышью выделяют, работают `Ctrl+C`/`Ctrl+X`/`Ctrl+V`, `Ctrl+A` и
отмена.

Ключ API читается из переменной окружения, названной в `api_key_env`, поэтому
файл настроек никогда не содержит секрета. Локальным серверам ключ обычно не
нужен, оставьте переменную незаданной. `fold_blocks` решает, когда
размышления и вызовы инструментов сворачиваются в однострочный заголовок:
`immediately` — сразу, ещё во время работы (идущее размышление показывает свою
последнюю строку), `on-finish` — показывает их целиком до завершения, `never` —
все блоки остаются развёрнутыми; выбранный блок разворачивается `Enter` или
повторным кликом в любом режиме. В модале настроек это **Сворачивать блоки**. Старое
`autofold = false` читается как `never`, `true` — как `on-finish`. Если
`max_tokens_per_turn` равен нулю
или меньше, предел вывода не передаётся и длину ответа решает модель; API
Anthropic требует его обязательно, поэтому там подставляется щедрое значение
32000.

Настройки, записанные до появления подключений, — с `provider`, `base_url`,
`model`, `api_key_env` или `context_window_fallback` прямо в `[ai]`, —
читаются как одно подключение `default`, на котором и стартуют новые сессии;
следующее сохранение из модала настроек записывает их в новом виде.

Строка подключения в баннере и чип **Connection** в статусной строке
переключают сессию на другое подключение: его эндпоинт и модель заменяют
текущие, агент перезапускается на том же логе и продолжает разговор, а
делегированные задачи идут следом. CLI-агент (`claude_code`, `codex`, `gemini_cli`)
не подхватывает разговор, поэтому переключиться на него или с него можно только до
первого запроса. Лог сессии запоминает подключение, так что переоткрытая сессия
подключается к нему снова, пока оно есть в настройках, а иначе — к подключению
для новых сессий.

Для облачного OpenAI-совместимого сервера оставьте `provider = "openai_compatible"` и
укажите у подключения `base_url` и `api_key_env`, например сам OpenAI
(`https://api.openai.com/v1`, `OPENAI_API_KEY`) или OpenRouter
(`https://openrouter.ai/api/v1`, `OPENROUTER_API_KEY`) или Gemini API
(`https://generativelanguage.googleapis.com/v1beta/openai`, `GEMINI_API_KEY`).
Подпись, которую модель ставит на вызов инструмента (thought signature Gemini
в `extra_content` вызова), сохраняется в логе сессии и отправляется обратно
вместе с вызовом, как того требует сервер. Для подписки Anthropic
задайте `provider = "anthropic_compatible"`, уберите `base_url` (корень API встроен;
задавайте его только для шлюза) и укажите `api_key_env` с вашим
`ANTHROPIC_API_KEY`; тогда уровень рассуждений просит модель думать.
Чип **Model** перечисляет модели каждого сервера.

`provider = "claude_code"`, `provider = "codex"` и `provider = "gemini_cli"` —
иного рода: вместо того чтобы встроенный цикл обращался к модельному
эндпоинту, панель запускает CLI самого инструмента как
[внешнего агента](#внешние-агенты) по ACP
(`@agentclientprotocol/claude-agent-acp` / `@agentclientprotocol/codex-acp`
/ `@google/gemini-cli --acp`, последний выпуск, через `npx`).
Эндпоинт и вход (своя подписка или ключ) — целиком за CLI, поэтому `base_url`,
`api_key_env` и контекстное окно подключения неактуальны: модал настроек
прячет их для этих провайдеров и вычищает из файла. `model` сохраняется: это модель, **предвыбираемая**
на агенте — применяется по ACP при старте сессии, — а в рантайме чип **Model**
перечисляет и переключает собственные модели агента. Инструмент должен быть
заранее установлен и залогинен (`npx` в `PATH`); сам termide вход не
выполняет, поэтому один раз запустите Gemini CLI отдельно
(`npx @google/gemini-cli`) и выберите способ входа.

termide берёт управление этими агентами настолько, насколько они позволяют,
чтобы сессия шла одинаково на любом подключении:

- **Claude Code** получает системный промпт termide вместо своего и вызывает
  инструменты termide, которые ему отдаёт локальный MCP-сервер, вместо своих —
  в том числе инструменты MCP-серверов termide, по мере того как они
  подключаются и отключаются. Его встроенные инструменты и собственные настройки — их правила, хуки,
  `CLAUDE.md` и MCP-серверы — не используются. Каждый вызов выполняется в
  termide и проходит те же проверки, что во встроенном цикле: режим
  разрешений, правила, ответы на сессию, режим плана и контрольные точки
  `/undo`. Вызовы, которые Claude Code делает вместе, выполняются
  одновременно; по очереди только решается, разрешить ли их. Вызов может идти сколько нужно — субагент, долгая сборка, карточка,
  до которой вы ещё не дошли, — Claude Code его не бросит; а если всё же
  бросит, вызов остановится и его карточка разрешения исчезнет, так что
  следующие вызовы пойдут дальше.
- **Codex** оставляет свои системный промпт и инструменты; termide переводит
  его в режимы, соответствующие режиму панели (`ask`, `configured` и `auto` — Ask for
  approval, `plan` — то же плюс его режим совместной работы plan, `edit` —
  Approve for me, `all` — Full access), и решает то, о чём он спрашивает.
- **Gemini CLI** тоже оставляет свои системный промпт и инструменты; termide
  ставит ему режим подтверждений, соответствующий режиму панели (`ask`,
  `configured` и `auto` — `default`, где он спрашивает перед правками и командами,
  `plan` — `plan` или `default`, если режим плана в Gemini выключен, `edit` —
  `autoEdit`, `all` — `yolo`), и решает то, о чём он спрашивает.

Codex и Gemini CLI вдобавок получают инструменты MCP-серверов termide: их
отдаёт тот же локальный MCP-сервер рядом с их собственными инструментами, и
вызовы проверяются так же, как у Claude Code; их собственная настройка MCP
продолжает действовать. Список инструментов MCP-сервера они читают только
один раз, при старте сессии, поэтому сессия до десяти секунд ждёт, пока
MCP-серверы termide ответят. Сервер, подключившийся позже или перезагруженный,
дойдёт до них в следующей сессии.

Цикл разговора у всех троих свой: контекст они сжимают сами, остановить выполнение
между шагами нельзя, замеров префила и генерации нет (суммы токенов видны,
если агент их сообщает, как Claude Code). Чип **Разрешения** работает для всех троих.
То же сказано в модале настроек под страницей подключения.

## Работа с панелью

Сессия занимает панель, поле ввода находится внизу — под заголовочной рамкой с
именем агента (`─ default ─`), чтобы параллельные панели агентов было легко
различать. Длинная строка переносится по ширине панели, и поле растёт под неё —
до половины высоты панели, — прежде чем начать прокручиваться. Как и новый терминал,
агент работает в каталоге панели, которая была в фокусе при открытии (каталог
файлового менеджера, файл редактора), иначе в корне проекта. Заголовок
панели — ваш первый запрос, поэтому несколько панелей агента различимы с
одного взгляда; до первого запроса в заголовке стоит рабочий каталог.
Длинный заголовок обрезается с конца по ширине панели, так что широкая панель
показывает больше. Своё
название сессии можно дать через меню панели `[≡]` → **Переименовать
сессию**, и дальше в заголовке будет оно.

Свежая сессия встречает баннером: слева небольшой логотип, справа — с чем
настроен агент. Заголовок баннера — имя агента, под ним описание агента, если
оно задано в определении (агент по умолчанию, если определение не говорит
иного, описан как «Агент» — та же подпись, что в заголовке панели); ниже — рабочий каталог, подключение, модель и
доступные инструменты, каждое под своей подписью, на выбранном в настройках
языке. Имя агента, подключение, модель и инструменты показаны жирным акцентным
цветом: клик по любому открывает тот же выбор, что и чип в статусной строке, —
можно настроить сессию до начала работы. Так же, пока панель ничем не занята,
показан и рабочий каталог: клик открывает выбор каталога (`.` в нём показывает
скрытые каталоги), и панель на месте переходит в выбранный. Лог сессии
переносится вместе с ней, так что выбранные подключение, модель и агент
сохраняются, а агенты и скиллы проекта, хуки и список сессий ниже берутся уже
из нового каталога. Ещё ниже, под заголовком «Сессии», —
остальные сессии этого каталога, самые свежие сверху, у каждой — локальные дата
и время последнего изменения: список начинается с колонки логотипа, так что
названиям достаётся вся ширина панели, занимает свободное место
панели, остальное прокручивается колесом. Сессии, открытые в других панелях,
в список не попадают и возвращаются в него, когда панель их отпускает. Клик
открывает сессию вместо пустой; с клавиатуры `Tab` переводит в список,
стрелки, `PgUp`/`PgDn` и `Home`/`End` двигают курсор, `Enter` открывает сессию
под ним, `F2` переименовывает её, `F8` или `Delete` удаляют её после подтверждения, а `Tab` или `Esc`
возвращают в промпт. То, что панель сообщает до этого, — подключился
MCP-сервер, `/имя` определено дважды, — выводится под баннером, за пунктирной
чертой, последние строки на виду; список сессий первым уступает им место.
У каждого MCP-сервера там одна строка, которая переписывается по мере
изменений: его инструменты и сколько из них включено, подключение, нужен вход.
Баннер уступает место разговору, как только вы отправите первое сообщение, а
эти строки остаются в его начале; дальше каждое изменение — отдельная строка:
сервер переподключился или сменил инструменты, применён набор инструментов
(`mcp github: включено 3 из 12 инструментов`, `Инструменты выключены: bash;
включены: —`), — ведь с этого места у модели другой набор.

Чип **Tools** (и строка инструментов в баннере) открывает список того, чем сессии
можно пользоваться: встроенные инструменты, скиллы и инструменты каждого
MCP-сервера, как только он подключится. Каждая группа сначала свёрнута до
заголовка, который показывает, сколько её пунктов включено
(`▶ [-] MCP github  3/12`): `→` или клик по стрелке раскрывает её, `←`
сворачивает (а с пункта переходит на заголовок его группы). Чекбокс на
заголовке группы включает или выключает всю группу разом, раскрыта она или нет,
и показывает `[-]`, пока она включена частично. Список применяется, как бы его
ни закрыли, — `Enter`, `Esc` или кликом мимо окна. У каждого настроенного
MCP-сервера есть заголовок, в том числе у неподключившегося, — с состоянием
рядом с именем («нужен вход», «ошибка: …») — и кнопки у правого края,
выстроенные в одну колонку: `[↻]` подключает его заново (`r` на заголовке), а
у сервера со входом по OAuth `[⇥]` выполняет вход или `[⇤]` — выход (`l`)
слева от него. Кнопка применяет отметки, как `Enter`, закрывает список и
делает то, что обещает. Сервер, подключившийся, пока список открыт, появляется
в нём тут же — у его заголовка исчезает состояние, а под ним встают его
инструменты — так что список не нужно закрывать и открывать заново, чтобы
увидеть, где сервер стоит; снятое вами остаётся снятым.
Снятый до первого запроса пункт вообще
не попадает в контекст модели — его описание и схема не отправляются, это
экономит токены и убирает саму возможность. Позже в сессии снятый пункт остаётся
в контексте, чтобы не сбрасывать кеш промпта у провайдера, но каждый его вызов
отклоняется; из контекста он уходит в ближайший момент, когда кеш теряется и
так, — при сжатии, смене агента или модели — и вернуть его в этой сессии
уже нельзя. Набор хранится в логе сессии, так что переоткрытая сессия
возвращается с ним. У Claude Code этот список тоже есть: инструменты
termide он получает при старте своей сессии, поэтому снятый пункт с первого же
запроса отклоняется, а не убирается из его контекста. У Codex и Gemini CLI он появляется, когда подключится
MCP-сервер termide, и содержит только инструменты таких серверов. Другие агенты
по ACP приносят свои инструменты, поэтому у них такого списка нет.

Меню панели `[≡]` оставлено только под действия без другого места — **Сведения
о сессии** (также `F3` и `/usage`), **Переименовать сессию**, **Сохранить чат
в Markdown…** (также `Ctrl+S`), **Ответвить сессию** (также `F5` и `/fork`)
и **Удалить сессию**. Собранный системный промпт
открывается командой `/prompt`. Сохранение чата записывает разговор через диалог
«Сохранить как» с именем сессии: каждый день под своим заголовком, а под ним
каждое ваше сообщение и каждый ответ агента под заголовком с 🧑 или 🤖,
именем автора (у своего агента — его имя) и временем. Размышления, вызовы
инструментов с их выводом и служебные строки панели не попадают; сообщение,
отправленное как `/имя аргументы`, сохраняется так, как вы его набрали.
Сохраняется вся ветка, включая сжатую часть. Управление
сессиями теперь на F-клавишах и в меню AI: `F7` начинает новую сессию, `F6` открывает список
сессий каталога (новые сверху, текущая помечена `●`), `F5` ответвляет текущую,
`F8` удаляет её с подтверждением, `F2` переименовывает. Переключение ждёт текущую
задачу: если агент работает, сначала остановите её по `Esc`. Ответвление ничего
не требует от выполняемой работы, поэтому доступно и во время неё.

Ответвление копирует лог сессии и открывает копию в новой панели агента, которая
подхватывает разговор с того же места — те же сообщения, тот же агент и модель, —
а панель, из которой сделали ответвление, продолжает работу со своим логом. Они
расходятся в этот самый момент: каждая пишет свой файл, так что один разговор
теперь ведётся в двух местах, и агент может параллельно пробить два подхода.
Копия получает собственное имя — имя исходника со счётчиком, `Refactor`
становится `Refactor (2)`, затем `Refactor (3)`, — чтобы две строки различались
в списке и в заголовке панели; переименовать любую можно в любой момент. Копия —
обычная сессия: она появится в списке сессий и на баннере свежей панели, как
только её панель её отпустит, и в неё можно вернуться.

Из поля ввода `/new` начинает свежую сессию (текущая остаётся), `/fork`
копирует эту в новую панель, а `/clear` — тоже свежую, но сначала удаляет
текущую; `/rename` (или `/name`) переименовывает.
Выбор модели, агента и режима разрешений — это чипы статусбара.

Сессия, в которую вы ничего не отправили, удаляется при переключении на другую
или закрытии панели — так что открыть панель и закрыть её (или попробовать
пару новых сессий) не оставляет пустых логов, засоряющих список и диск. Сессия,
которой вы дали имя или отправили хотя бы одно сообщение, сохраняется всегда.

Разговор — это стопка блоков, каждый открывается меткой акцентного цвета: `› `
для вашего сообщения и для ответа агента, `@ ` для его размышления, `$ ` для
вызова оболочки, `< ` для чтения файла, `> ` для записи, `± ` для правки,
`/ ` для скилла, `& ` для субагента, `* ` для инструмента MCP, `¿ ` для
вопроса вам, `# ` для системного промпта. Ответ показан целиком;
сообщение пользователя или системный промпт длиннее пяти строк
сворачивается в превью, в котором остаются первая строка и несколько последних,
а между ними — пометка `… N more lines`. Блок в пять строк и меньше прятать
незачем, поэтому он показан целиком и без символа сворачивания; так же
показан любой завершённый блок, который в развёрнутом виде занимает одну строку. Завершённый
вызов инструмента сворачивается в одну строку: заголовок (у вызова оболочки —
первая строка команды), и только он; сколько вызов длился (`🕒`), видно в
развёрнутом виде. Метка и действие вызова инструмента, пока он выполняется,
акцентного цвета, после успешного завершения — цвета успеха, после неудачи —
цвета ошибки; предмет вызова сохраняет свой цвет. Галочки `✓` в одной строке
нет, чем вызов закончился, видно по цвету его метки; развёрнутый вид
неудавшегося вызова заканчивается `✗`. Длительность растёт от секунд к минутам,
часам и дням (`2с`, `1м13с`, `2ч5м`, `3д4ч`). Так же сворачивается
завершённое размышление: до одной первой строки; в развёрнутом виде видны
строки `⏫`/`✍️`. Блок, который
ещё в работе, — размышление, пока оно идёт, или выполняющийся инструмент с его
живым выводом, — всегда показан развёрнутым и сворачивается только после
завершения. Ваше сообщение —
это обычный текст на приглушённом фоне; размышление, системный промпт и вывод
инструмента — тусклый текст, кроме диффа правки: он раскрашен так же, как в
панели Git diff. Каждый шаг открывается своим символом и
локализованным действием того же акцентного цвета, затем идёт его предмет:
размышление — `@ Думаю` и его текст, вызов оболочки — `$ Выполняю` и команда
(тускло, с переносом по ширине), файловый инструмент — с путём
(`< Читаю src/main.rs`, `> Записываю`, `± Редактирую`), веб-инструмент — с
адресом или запросом (`↓ Загружаю https://docs.rs`, `? Ищу ratatui scrollbar`),
скилл — с именем и аргументами (`/ Использую скилл review src/x.rs`), субагент —
с именем и первой строкой задачи (`& Поручаю reviewer: проверь дифф`),
инструмент MCP — с сервером, именем и аргументами в виде `ключ=значение`
(`* Использую MCP github: create_issue title=Crash`); любой другой — как имя и
краткая сводка. Размышление —
это отдельный блок над ответом, его текст переносится по ширине. Только системный промпт
начинается тусклой штриховой линией-разделителем; у пометок её нет, их
отмечает символ. После вашего
сообщения идёт пустая строка, ещё одна — перед ответом и ещё одна — после
ответа, за которым идут следующие шаги; размышления и вызовы инструментов между
ними идут подряд, без промежутков. Свёрнутый блок помечен
`▸`, развёрнутый — `▾`, сразу после действия шага
(`@ Думаю ▸`, `$ Выполняю ▸`, `< Читаю ▸ src/main.rs`) или после `#` системного
промпта (`# ▸`).

Пока прогон идёт, под его последним блоком справа стоят часы прогона:
анимированный `✽` и время с момента отправки запроса. У них свой символ, а не
`🕒`: показатели под каждым блоком относятся только к нему, а эти часы — итог
прогона. Когда прогон заканчивается, часы застывают на месте и становятся блеклыми,
так что застывший `✻` не спутать с работающим. Прогон,
завершившийся ответом, оставляет их в мете ответа (`✻ 3m41s`), под временем и
`✓`/`✗` самого ответа — в том числе ответа с ошибкой вызова. Прогон, исход
которого ответ не показывает (закончившийся вызовом инструмента или прерванный
после удачного ответа), оставляет их итоговой строкой после последнего блока,
со временем окончания и тем, чем он закончился: `✻ 3m41s · 21:03:41 ✗`.

`/pause` срабатывает, как только завершится текущий вызов инструмента или ответ
модели, — а не в конце всего шага, так что шаг, загружающий несколько страниц,
останавливается после текущей. Оставшиеся вызовы ждут `/continue`, которая
выполняет их первыми; новый запрос вместо этого закрывает их как невыполненные.
Прогон, остановленный через `/pause`, получает вместо этого строку паузы
`‖ 1m12s`: она отсчитывает, сколько длится пауза, с выделенным `‖`, пока
пауза идёт, и сохраняет эту длительность, уже блеклой, когда прогон
продолжится. Часы
продолженного прогона идут дальше от исходного запроса, так что его итог
включает паузу. Кнопки управления прогоном стоят у правого края
верхней границы поля ввода и видны при любой прокрутке ленты: пока агент
работает, `[‖]` ставит прогон на паузу, как `/pause`, а `[■]` останавливает
его, как `Esc`; когда пауза запрошена, на месте `[‖]` появляется `[▶]`,
который её отменяет (как и клик по её предупреждению в полосе состояния или
`/continue`); на паузе `[▶]` продолжает прогон — как и клик по строке паузы или
`/continue`, — а `[■]` отказывается от приостановленного прогона (оставшиеся
вызовы закроет следующий запрос). Claude Code, Codex и Gemini CLI ведут свой
цикл, который нельзя остановить между шагами: у них есть только `[■]`, а `/pause` сообщает,
что пауза недоступна. В покое кнопки акцентного цвета, как рамка панели; `[▶]` зелёная. Нажатие `[■]` (или
`Esc`) отменить нельзя: до фактической остановки прогона остаётся только
красная `[■]`, и повторное нажатие ничего не делает.

Итоговая строка — один из видов пометок: строк, которые отмечают момент в
разговоре, а не несут содержимое. Остальные пометки — уведомления панели: `·`
для информации (смена модели, завершённое сжатие), `!` для предупреждения
(остановленная цель, занятый агент), `✗` для ошибки вне блока (неудачное
сжатие, ошибка MCP). Ошибка внутри хода остаётся в блоке ответа. Пометки не
сворачиваются. Текст уведомления переносится по ширине под его символом; курсор чата может встать на
уведомление, так что ошибку можно выбрать и скопировать, как блок, а итоговую
строку прогона он пропускает.

То, что верно сейчас, а не то, что произошло, показано в полосе состояния —
нескольких строках между разговором и полем ввода, которые появляются, только
когда есть что показать: ожидаемая пауза (`‖ приостановлю после текущего
шага`), — когда пауза срабатывает, её место занимает строка `‖` в ленте, — и
каждое сообщение,
поставленное в очередь, пока агент работает (`› …`, его первая строка; после
трёх — число остальных). Всё, что стоит в очереди, уходит агенту разом, одним
сообщением, где части разделены пустой строкой, — сообщения, набранные пока агент
работает, обычно дописывают одну мысль, — и тогда уходит из полосы, появляясь в
разговоре как ваше сообщение. Пока агент их не забрал, `↑` на первой строке
ввода возвращает очередь в поле ввода, перед уже набранным, чтобы её можно было
поправить.

Действующий системный промпт показан свёрнутым блоком `# ` в начале сессии и
снова всякий раз, когда он меняется перед вашим следующим сообщением (например,
при смене агента или режима), — так видно, что было сказано модели.

Ваше сообщение и ответ агента заканчиваются тусклым, прижатым вправо временем и
статусом `✓`/`✗` (`18:34:01 ✓`) — в конце последней строки текста, если там
хватает места; блоки размышления и инструментов несут только
свои рабочие показатели, без часов, и только в развёрнутом виде. Вызов
инструмента показывает, сколько он занял (`🕒 6s`), и статус. Вызов, который ждал ответа на
запрос разрешения, показывает это ожидание отдельно и первым, как паузу, которой
оно и было: `‖ 12s 🕒 2s`, с выделенным и тикающим `‖`, пока вопрос открыт;
`🕒` считает только работу самого вызова. Если ход рассуждал, блок размышления несёт стоимость
хода — фазу prefill (`⏫ 6s (↑42k, 7k tok/s)`) и фазу генерации
(`✍️ 12s (↓5k, 420 tok/s)`), у каждой длительность (в целых секундах), число
токенов и средняя скорость; большие значения сокращаются (`40k`, `1.2M`). У хода
без размышления это показано на ответе. Пока
ход ещё идёт, та же прижатая вправо мета-зона показывает живые цифры: до первого
токена — строку prefill `⏫` с тем, сколько модель уже читает промпт, и оценкой
его размера (`⏫ 14s (↑~48k)`), а от сервера, сообщающего прогресс
(`prefill_progress`), — полоску с числом уже прочитанных токенов и скоростью по
тем, что не взяты из его кэша (`⏫ 14s ▰▰▰▰▱▱▱▱ (↑24k/48k, 1k tok/s)`); когда токены пошли — строку генерации `✍️` с
текущей длительностью, оценкой токенов и скоростью; под любой из них — часы
прогона. Точное число входных токенов и скорость prefill появляются в готовом
блоке. Компакция, в том числе `/compact` между прогонами, показывает те же строки
`⏫`/`✍️` для своего запроса на сводку, а цифра контекста в строке состояния
сразу после её завершения падает до размера сводки и сохранённого хвоста. У
внешнего агента живой строки prefill нет: его сообщение начинается сразу
с первого текста. При повторном открытии разговора из лога
восстанавливаются время каждого блока, его размышления, строки
prefill/генерации хода и длительность каждого вызова инструмента.

Разверните блок, чтобы увидеть его целиком: щёлкните по нему или нажмите
`Tab`, чтобы перейти в чат, и `Space`/`Enter` или `→` на блоке под курсором
`↑`/`↓` (`←` сворачивает его обратно);
`Ctrl+O` разворачивает всё сразу, и блоки, пришедшие после этого, тоже
приходят развёрнутыми; повторное нажатие сворачивает всё обратно, а новые блоки
снова сворачиваются по `fold_blocks` (по завершении, если там `never`). `o` открывает выбранный блок в отдельной
панели только для чтения, для большого обзора (команда с сохранённым полным
логом открывает этот файл). Повторный `Tab` — или клик обратно во ввод —
возвращает фокус во ввод. Панель следит за новыми строками, пока вы не
прокрутите вверх, и возобновляет слежение, когда вы вернётесь вниз.

Чтобы скопировать блок целиком, выберите его (кликом или переходом) и нажмите
`Ctrl+C`. Во вводе `Ctrl+C` копирует выделенный там текст — выделение показано
инверсией, поэтому видно, что именно попадёт в буфер.

Мышью можно выделять текст прямо в поле запроса: нажмите, чтобы поставить
курсор, тяните, чтобы выделить (в том числе через перенесённые строки),
отпустите и копируйте или вырезайте. В транскрипте протяжка выделяет текст,
как в терминале, — от ячейки, где она началась, до ячейки под указателем, с
прокруткой, если тянуть за край; `Ctrl+C` копирует его, отбрасывая пробелы в
конце строк. Клик без протяжки (срабатывает при отпускании) выбирает блок под
ним и снимает выделение текста.

То, что запускает агент, захватывается для модели в чистом виде: цветовые и
курсорные escape-коды, перерисовки прогресс-баров, кадры спиннеров и длинные
череды почти одинаковых строк сборки убираются или сворачиваются до того, как
вывод попадёт в контекст, поэтому шумная команда стоит куда меньше токенов.
Прогон тестов — Rust (`cargo test`, `cargo nextest`), Python (`pytest`), Go
(`go test`) или JS/TS (`jest`, `vitest`) — выбрасывает строки пройденных и
пропущенных тестов, оставляя падения и итоговую сводку. Полный нетронутый лог
всё равно пишется в файл, путь к которому инструмент сообщает, а живой сырой
поток вы по-прежнему видите в панели.

Статусные чипы идут слева направо: агент, режим разрешений, уровень
**Reasoning** (его нет у модели, которую нельзя об этом попросить), подключение с его протоколом
(`local · OpenAI Compatible`) и модель. Суммарные
токены за сессию и контекстное окно прижаты к правому краю; на узком терминале
урезаются чипы слева, а не они. Суммы — это `↑` токены промпта, оплачиваемые
по полной цене (некэшированный вход и запись в кэш промпта), `↻` токены,
отданные кэшем, когда они есть, и `↓` выход: `↑2.1k ↻48k ↓900`. Окно — занятые
токены из его размера с полоской-заполнением, `66k/262k ▰▰▱▱▱▱▱▱`; для Claude
Code, Codex и Gemini CLI и то и другое берётся из того, что сообщает агент, а окно
появляется, как только он его сообщил. Агент, режим,
reasoning, подключение и модель — кнопки. Клик по
**Reasoning** показывает уровни, которые предлагает модель (у модели с
переключателем вкл/выкл он просто переключается), и выбранный действует со
следующего запроса; выбор запоминается в сессии, так что резюме возвращается с
ним, и сохраняется при смене модели, сводясь к ближайшему уровню новой. Что агент делает прямо сейчас, статусбар не дублирует: это несёт подпись
каждого блока чата.

Ввод `/` открывает над полем список подходящих шаблонов запросов; `↑`/`↓`
двигаются по нему, `Tab` или `Enter` дополняют подсвеченный, а `Enter` на
полностью набранном имени отправляет.

Ввод `@` открывает тот же список, но с файлами и каталогами внутри каталога
панели, так что путь набирается парой нажатий: `@ma` находит `src/main.rs`, причём
буквы не обязаны идти подряд (`@srmain`). То, что игнорирует git, не
предлагается, а скрытые файлы — только если набрать `.`.
`Tab` или `Enter` вставляет подсвеченный; каталог оканчивается на `/` и
переоткрывает список для своего содержимого, чтобы можно было углубиться.
Агент прочитает названный файл; `@` — это только быстрый ввод пути, ничего не
прикрепляется втихую.

Большая вставка (больше пяти строк или 2000 символов) не заполняет поле ввода, а
держится вне него в виде короткого плейсхолдера `[#1 pasted 40 lines]`; при
отправке полный текст подставляется на место плейсхолдера, так что модель
получает его целиком. Повторная вставка того же блока раскрывает его:
плейсхолдер сменяется полным текстом, чтобы его можно было прочитать или
поправить. Вставка поменьше вставляется как есть.

**Модель** запрашивает у сервера список обслуживаемых моделей и показывает
его с пометкой `●` у текущей; последний пункт позволяет ввести идентификатор
вручную — он же остаётся единственным, когда сервер список не отдаёт. Смена
действует со следующего запроса и остаётся за сессией: она записывается в
журнал сессии — вместе с провайдером, на котором работает, — поэтому открытая
заново сессия возвращается к своей модели и провайдеру, а новая сессия
начинается на той модели, на которой сейчас панель. Смена ждёт текущую задачу,
как и переключение сессий.

**Контекстное окно.** Если сервер сообщает окно модели (vLLM и omlx отдают
`max_model_len`), панель всегда берёт его — при старте и при каждой смене
модели, — так что `Context:` совпадает с тем, что реально разрешает сервер.
`context_window_fallback` в конфиге — лишь **запасное** значение на случай, когда сервер
окно не сообщает; если он не задан (`(auto)` в модале настроек), до момента,
пока провайдер не известен, используется встроенный запасной вариант.

Чип **Разрешения** предлагает шесть режимов, описанных ниже. `Shift+Tab`
переключает их по кругу без списка. Изменение применяется на следующем вызове
инструмента, так что режим можно ослабить прямо во время долгой задачи, не
отвечая на один и тот же вопрос снова и снова. Ни одна из смен не трогает
файл настроек: в следующий раз панель снова начнёт с `[ai]`.

### Запускаете команду сами

`$`, набранный в пустой строке ввода, переключает её на команду оболочки:
`$` встаёт на место маркера `›`, а `Enter` сразу выполняет набранное, ничего не
спрашивая у модели. Режим включается заново для каждой команды: её запуск,
`Esc` или `Backspace` в пустой строке возвращают к сообщениям. В режиме
оболочки `↑` и `↓` листают ранее запущенные команды, а не сообщения. Текст,
который просто начинается с `$` — вставленный или набранный после пробела, —
остаётся сообщением.

Команда выполняется в каталоге сессии тем же `bash`, что и агент, поэтому у
длинного вывода сохраняются начало и конец, а полный лог пишется в файл. В
транскрипте она выглядит как блок вызова оболочки, такой же, как у агента, —
`$ git status --short`, свёрнутый, со временем выполнения и `✗`, если команда
завершилась с ошибкой; в развёрнутом блоке сказано, что запустили её вы, — и
агент видит и команду, и вывод, когда вы обратитесь к нему снова: можно сразу
спросить «что это значит для правки». `Esc` останавливает ещё работающую
команду; запуск не расходует вызов модели и доступен, пока агент занят.

Что вы набрали, то и выполняется — без карточки разрешения, потому что это
набрали вы. В этом и весь смысл различия: команды самого агента по-прежнему
судят режим и правила ниже, а предложенная агентом команда (см.
**suggest_command**) выполняется только после вашего подтверждения.

### Откат запроса

`/undo` откатывает
последний запрос, изменивший файлы: карточка в панели перечисляет файлы, и
после подтверждения каждый возвращается к состоянию до этого запроса (файл,
который запрос создал, удаляется), а разговор отматывается к моменту перед
ним, так что агент тоже больше не помнит, что делал. Открытые редакторы
перезагружают восстановленные файлы. Повторный `/undo` отступает к более
ранним запросам; запрос, который ничего не менял, пропускается. Это шаг назад
без повтора: откаченные сообщения остаются в журнале сессии на мёртвой ветке,
а новое содержимое файлов теряется.

Перед запуском `edit` или `write` панель сохраняет копию файла в каталоге
сессии (`ai/sessions/<путь>/checkpoints/<id сессии>/`), по папке на запрос;
после отката папка удаляется. Команды оболочки не покрыты: то, что меняет
`bash`, должны хранить git или ваши собственные копии.

### Откат к сообщению

`Esc` в пустом поле ввода, когда ничего не выполняется, показывает
отправленные вами в этой сессии сообщения прямо над полем ввода, как
подсказки `/команд` (`F4` открывает тот же список в любой момент).
Последнее сообщение стоит рядом с полем и выбрано, `↑`/`↓` переходят к
остальным, `Enter` (или щелчок) выбирает, а `Esc` или набор текста
закрывают список. Рядом с сообщением, после которого агент менял файлы,
перечислены эти файлы. Выбор сообщения отматывает разговор к моменту
перед ним и возвращает сообщение в поле ввода, чтобы его можно было
поправить и отправить снова, — если вы ещё не начали набирать другое. Если
с тех пор менялись файлы, карточка перечисляет их и спрашивает, что
вернуть: файлы и разговор, только разговор (файлы сохраняют текущее
содержимое) или только файлы (разговор продолжается с того же места). Файлы
восстанавливаются из тех же контрольных точек, что и в `/undo`, и в любом
случае контрольные точки откаченных запросов расходуются. Как и при `/undo`,
откаченные сообщения остаются в журнале сессии на мёртвой ветке.

## Инструменты

Встроенные инструменты агента перечислены ниже, плюс те, что дают его
MCP-серверы (см. [MCP-серверы](#mcp-серверы)). У собственного агента панели
есть ещё **question** и **suggest_command**, описанные после списка.

- **read** возвращает файл с номерами строк, длинные файлы читаются по частям.
- **edit** заменяет уникальный фрагмент текста в файле и показывает diff.
- **write** создаёт файл или полностью заменяет его содержимое.
- **bash** выполняет команду в каталоге проекта, передавая вывод по мере
  появления. У длинного вывода сохраняются начало и конец, а полный лог
  пишется в файл, который агент может прочитать.
- **web_search** задаёт вопрос поисковику и возвращает заголовки, ссылки и
  сниппеты.
- **fetch** загружает веб-страницу и возвращает её текст в markdown; длинные
  страницы читаются по частям, как в `read`.
- **recall** ищет в прежних сессиях агента, истории git и коде проекта
  сделанную работу, решения и их причины; см. [Recall](#recall).

Поиск файлов проекта по шаблону выполняется через `bash` привычными средствами
(`rg`, `find`), а не отдельным инструментом.

Ещё один инструмент, **skill**, появляется, когда определены скиллы; см.
[Скиллы](#скиллы).

**question** позволяет агенту спросить вас, когда решение за вами: какой
подход выбрать, что значит неоднозначное требование. Он задаёт до четырёх
вопросов, по одному, карточкой в панели над полем ввода. В заголовке —
что спрашивает агент, тема вопроса и, если вопросов несколько, его номер
(`Агент спрашивает: Подход (1/2)`); под ним тускло сам вопрос, затем варианты,
у каждого — тусклая пометка о том, что он значит. Вопрос предлагает выбрать
один вариант или несколько: тогда у каждого варианта есть флажок, который
переключают `Space`, `Enter` или его цифра, а **Готово** отправляет выбор.
После вариантов всегда идёт **Ввести свой ответ** — строка, которую вы
вводите вместо них или, где можно выбрать несколько, вместе с ними. `↑`/`↓`,
цифры и щелчки работают как на карточке разрешения; **Отказаться и
остановить**, или `Esc`, сообщает агенту, что вы отказались отвечать, и
останавливает прогон, чтобы вы сказали, чего хотите, своим сообщением.
Когда вопросов несколько, `←` возвращает к предыдущему, а `→` ведёт дальше
мимо уже отвеченного, как показывают стрелки в заголовке
(`Агент спрашивает (← 2/3 →)`): данный прежде ответ показан выбранным, а
новый ответ переводит к следующему вопросу. Ответы уходят агенту, когда
отвечен последний вопрос. Ожидание ответа считается паузой вызова (`‖`), как и вопрос о разрешении.
Спросить можно всегда без разрешения, и в режиме plan тоже. Этот инструмент
есть только у собственного агента панели: субагенту и запуску
`termide --prompt` спросить некого, и они решают сами. Агент, чей список `tools` не включает
`question`, тоже не спрашивает.

**suggest_command** отдаёт команду вам, вместо того чтобы выполнить её сам.
Агент выводит её на карточке — целиком и ровно так, как она бы выполнилась, с
пояснением, зачем она, и с каталогом выполнения, — и помечает её как
предложение агента. **Выполнить** запускает её тем же путём, что и набранное
вами [команда через `$`](#запускаете-команду-сами), и вывод возвращается агенту;
**Сначала отредактировать** кладёт её в поле ввода в режиме оболочки, чтобы вы
поправили и запустили сами; **Скопировать** забирает только текст;
**Не выполнять**, или `Esc`, отклоняет, и агент получает, что ничего не выполнилось и предлагать снова
нельзя. Именно так заканчивается заблокированный вызов: отказ говорит агенту
сообщить, что нужно выполнить, а это превращает сообщение в карточку, а не в
строку, которую вам набирать заново. Так же агент передаёт то, чего делать не
должен сам: публикацию, всё, что требует ваших учётных данных или вашего
решения.

Карточка ничего не запускает сама и не может провести вас мимо ваших же
правил: когда включён режим плана или команду накрывает правило `deny`,
**Выполнить** и **Сначала отредактировать** снимаются и остаются только
**Скопировать** и **Не выполнять**. Само предложение разрешения не стоит — оно ничего не меняет, —
так что агент всегда может достучаться до вас так; до оболочки доходит только
ваше подтверждение. Как и `question`, этот инструмент принадлежит агенту
панели.

### Веб

`web_search` и `fetch` работают через браузер семейства Chrome на вашей машине
(Chrome, Chromium, Edge или Brave): поисковики отказывают скриптовым запросам,
а многие страницы строит JavaScript. Браузер запускается с собственным
профилем в `ai/web/browser/` каталога настроек, а не с вашим повседневным,
поэтому ваших входов на сайты у агента нет. Он работает без окна и
представляется так же, как тот же браузер с окном; один браузер обслуживает
все панели агента и закрывается после пяти минут простоя.

Когда поисковик просит подтвердить, что ищет человек, перед вами открывается
окно с этой страницей, а вызов инструмента в панели показывает ожидание:
пройдите проверку, и поиск продолжится. Профиль агента запоминает пройденную
проверку, так что она не повторяется при каждом поиске, а после простоя
браузер снова работает без окна.

Без такого браузера `fetch` всё равно читает страницы по обычному HTTP
(страницы, которые строит JavaScript, тогда приходят почти пустыми), а
`web_search` агенту не предлагается.

```toml
[ai.web]
backend = "auto"         # auto: браузер, если найден, иначе HTTP; chrome; http
engine = "duckduckgo"    # duckduckgo, bing, google, yandex или свой
chrome_path = ""         # исполняемый файл браузера; пусто — искать в обычных местах
display = "headless"     # headless (без окна); minimized; visible
```

`minimized` даёт браузеру настоящее окно, свёрнутое сразу после открытия, — для
поисковика, который всё же отличает браузер без окна. `visible` оставляет окно
на экране, чтобы наблюдать за работой агента: все страницы открываются в одной
вкладке, и она остаётся на последней прочитанной странице, так что её можно
рассмотреть или открыть на ней инструменты разработчика. Вкладку можно
закрыть: следующая страница откроется в новой. Чтобы понаблюдать какое-то
время, не меняя настройку, выберите **Показать окно браузера** в меню **AI**:
браузер сразу перезапускается в видимом окне и остаётся в нём, даже без
работы, до **Скрыть окно браузера** — для всех панелей агента, ведь браузер у
них общий. Профиль и его cookies сохраняются. В Linux без графического сервера
браузер работает без окна при любой настройке.

Каждый поисковик описан небольшим файлом в `ai/web/engines/`: адрес, куда
отправить запрос, и CSS-селекторы, которые выбирают результаты со страницы.
termide поставляет `duckduckgo`, `bing`, `google` и `yandex` и держит их
актуальными, как остальные поставляемые файлы. Если поисковик изменил
страницу и поиск перестал что-либо находить, селекторы в его файле нужно
обновить; собственный файл с новым именем добавляет поисковик. Ключи описаны
в поставляемых файлах.

В `plan` и `edit` оба инструмента работают без вопросов, в `ask` и, без
правила, в `configured` спрашивают; в `auto` поиск выполняется, а загрузка
страницы, чей адрес может вынести данные наружу, уходит ревьюеру. Разрешение дольше одного раза для `fetch`
покрывает весь сайт (`https://docs.rs/*`), для `web_search` — любые запросы.

Файл, который агент правит, пока тот открыт в редакторе, сразу перечитывается
там с сохранением курсора и прокрутки, если только в редакторе нет
несохранённых правок; тогда редактор их сохраняет и помечает конфликт, как при
любом изменении на диске (см. [Изменения на диске](editor.md#изменения-на-диске)).

### Recall

`recall` ищет то, что проект уже знает, — журналы его прежних сессий агента,
историю git и файлы — и ранжирует результаты вместе. Так агент находит, что
решали, пробовали или обсуждали раньше («почему отказались от tokio», «на чём
остановилась работа над компакцией»), без отдельной памяти, которую надо
поддерживать: журналы, коммиты и файлы и есть запись, а сам инструмент ничего
не пишет. Он одинаково подходит проекту из заметок и документов и проекту с
кодом.

- **Сессии**: журналы проекта в `ai/sessions/` (корень проекта и каталоги под
  ним), по живой ветке каждого журнала — то, что отменили `/undo` или откат, не
  ищется, а то, что свернула компакция, по-прежнему находится. Больше всего
  весят ваши сообщения, ответы агента, сводки компакции и handoff-брифы, меньше —
  вызовы инструментов, меньше всего — рассуждения и вывод инструментов (у вывода
  ищется только первые 4 КБ). Сессия на Claude Code, Codex или Gemini CLI
  тоже записывает в лог свои вызовы инструментов и их вывод, как сессия
  встроенного агента. Из сессии, в которой работает панель, ищется
  только то, что компакция убрала из контекста: остальное и так там. `git commit`, выполненный в сессии, связывается
  со своим коммитом.
- **Git**: коммиты, в сообщении которых есть слово запроса, и коммиты, которые
  добавили или удалили названный в запросе идентификатор (`git log -S`), во
  всех репозиториях проекта — том, в котором он лежит, его подмодулях или
  репозиториях папки, которая только их содержит, как их находят git-панели.
  Проект, который — лишь каталог большего репозитория, видит историю этого
  каталога.
- **Файлы**: заметки, документы и код проекта, где есть слово запроса.
  Текстовые файлы (Markdown, обычный текст, reStructuredText, Org, AsciiDoc) —
  проза: Markdown ищется по разделам между заголовками, так что каждый раздел
  длинного файла — каждая запись журнала решений — отдельный результат с
  заголовками в подписи; совпадение показывается целым абзацем, а недавно
  изменённый файл стоит выше давно не менявшегося. Любой другой файл — код:
  один результат на файл, показанный совпавшими строками. Как в ripgrep,
  скрытые, игнорируемые и бинарные файлы пропускаются, а обход не выходит за
  пределы одной файловой системы (смонтированный диск или файлы виртуальной
  машины внутри проекта не читаются); файлы любого размера читаются построчно.
  Каждый вложенный в проект репозиторий обходится со своим `.gitignore`, так
  что и тот, который внешний репозиторий игнорирует, тоже ищется; журналы
  сессий как файлы не читаются.

Панель, переведённая в каталог вне проекта, ищет и в нём — в его журналах
сессий, репозиториях и файлах — и называет найденное там по пути.

Слова сравниваются по основе, на английском и русском, а идентификаторы — по
частям, так что `split_command_line`, `splitCommandLine` и «split the command
line» сходятся, а «сессия» находит «сессии»; русское слово сравнивается ещё и
по основе без падежного окончания, так что имя, которого стеммер не знает
(«сомбала», «сомбалу»), находится в любом падеже. Двухбуквенная аббревиатура,
набранная заглавными («CI», «UI»), ищется целым словом, а не внутри более
длинного. Агент передаёт несколько
формулировок того, что ищет, и каждая ранжируется отдельно: результату нужна
большая часть веса одной формулировки, а редкое слово весит куда больше
частых. У каждого результата есть
ссылка — `session:<id>#<entry>`, `commit:<repo>@<sha>` или `file:<path>:<line>`, —
и агент вызывает `recall` ещё раз с `open`, равным ссылке, чтобы увидеть записи
вокруг результата из сессии или сам коммит, а файл читает с указанной строки.
Поиск можно сузить параметрами
`sources` (`sessions`, `git`, `files`), `paths` (пути или glob-шаблоны
относительно каталога панели, как любой путь, который даёт агент) и `since`
(дата, для сессий и коммитов). Результаты-файлы называют путь так же, поэтому
агент читает их как есть.

`recall` только читает, поэтому никогда не спрашивает разрешения, в режиме плана
тоже; он есть и у подагентов, и у запусков `termide --prompt`, а список `tools`
агента может его исключить, как любой другой инструмент.

С включённым решателем ещё один вызов модели читает результаты и отвечает на
вопрос по ним, ссылаясь на них, а результаты идут после ответа, чтобы агент мог
его проверить. По умолчанию он выключен.

Три источника ищут параллельно, у каждого свой лимит времени, по умолчанию
минута: найденное источником к его лимиту ранжируется вместе с остальным, а в
результате сказано, какой источник остановился — и git тоже, когда в лимит
упёрлась одна медленная команда, например `git log -S` по длинной истории. Так проект, где медленен один
источник — например файлы проекта с корнем в домашнем каталоге, — не отнимает
время у остальных, а поиск длится столько, сколько самый медленный источник.

```toml
[ai.recall]
sessions_timeout_secs = 60   # сколько секунд может искать каждый источник; 0 — без лимита
git_timeout_secs = 60
files_timeout_secs = 60
solver = false               # отвечать по результатам одним вызовом модели
connection = ""              # подключение, чья модель отвечает; пусто — модель сессии
```

Инструкции решателя — `system/recall.md` (см.
[Служебные промпты](#служебные-промпты)).

## Разрешения

Ничего, что меняет проект, не происходит без вашего согласия. Когда агент
хочет сделать что-то ещё не разрешённое, в панели над полем ввода появляется
карточка. В заголовке — намерение («Agent wants to run bash:»), а под ним
блеклым — что именно это (команда или путь); длинное сворачивается до пяти
строк, которые разворачивает щелчок. Ниже строки ответов: разрешить один раз,
разрешить на эту сессию, в режимах `configured` и `auto` ещё разрешать всегда в этом
проекте и разрешать всегда везде, затем отклонить, отклонять в этой сессии,
**отклонить и объяснить агенту** (вы печатаете фразу, и она уходит модели как
причина, чтобы та пошла другим путём) и **остановить**. Строки, действующие
дольше одного вызова, называют шаблон, который запоминают (`cargo build *`,
сайт, путь). Отвечают `↑`/`↓` и `Enter` или цифра строки; щелчок выбирает
строку, а второй щелчок (или `Enter`) подтверждает её, так что случайный клик
не ответит; `Esc` останавливает выполнение. Статусная строка тоже объявляет
вопрос, чтобы панель не в фокусе не спрашивала незамеченной; в заголовке такой
панели вместо иконки стоит 🔔, пока на неё не переведут фокус, —
так же и по завершении прохода. Если панель не та, что перед вами в окне
терминала с фокусом, вопрос ещё и подаёт звонок терминала, как и конец прохода
длиной от десяти секунд (кроме остановленного вами); звонок звучит один раз,
пока вы не взглянете на панель, а `bell_on_attention = false` в `[ai]`
отключает его. «В этом проекте»
дописывает правило в `.termide/config.toml` проекта, «везде» — в глобальные
настройки; ответы на сессию живут, пока открыта панель.

Каждый вызов хранит, кто его решил, — в журнале сессии, а значит, и после
возобновления: правила, режим плана, хук, ревьюер режима auto с причиной,
никто (подагент или запуск без интерфейса, которым некого было спросить) или
вы — с вашим ответом и сроком его действия. Развёрнутый вызов показывает это
отдельной строкой (`✓ вы разрешили на эту сессию`, `✗ ревьюер режима auto
заблокировал: …`); вызов, который правила разрешили без вопроса, — обычный
случай — ничего не пишет. Отказ по правилу сообщает модели, что правила ваши,
чтобы она не искала другой путь к тому же. Что модель читает при каждом виде
отказа — по правилу, в режиме плана, от ревьюера, по вашему ответу, в
запуске, где спросить некого, — лежит в `system/permissions.md` каталога
агента на уровне настроек, по строке на случай; правьте его, чтобы
сформулировать по-своему.

Правила задаются по инструментам. Среди совпавших побеждает самое строгое,
поэтому `deny` всегда сильнее `allow`:

```toml
[ai.permissions]
mode = "auto"       # ask | plan | edit | configured | auto (по умолчанию) | all — с чего начинают новые сессии

[ai.permissions.bash]
"cargo *"     = "allow"
"git status*" = "allow"
"git push*"   = "ask"
"rm -rf *"    = "deny"

[ai.permissions.edit]
"src/**" = "allow"
".env"   = "deny"

[ai.permissions.read]
"**/.env*" = "deny"
```

В шаблоне `*` означает любой текст, а начальное `**/` необязательно, поэтому
`**/.env*` совпадает и с `.env` в корне проекта. Команды оболочки проверяются
по частям: для `cargo build && rm -rf target` нужны разрешения на обе половины,
а запрет любой половины останавливает всю команду. Служебные слова оболочки
частями не считаются: в `if [ -f x ]; then make; fi` части — это `[ -f x ]` и
`make`, а заголовок `for … in` или закрывающие `fi` и `done` частями не
являются вовсе. Подстановка команд
(`$(…)`, обратные кавычки) не разрешается автоматически никогда, и спрашивает
только о той части, которая её несёт, а не о соседних: в
`cd x && ls && echo $(date)` вопрос будет об `echo`; операторы внутри
подстановки принадлежат ей и строку больше не разделяют. Встроенный
скрипт — одна команда, а не команды из его строк: скрипт в кавычках (включая
экранированные кавычки внутри) и тело here-document (`python3 - <<'EOF'`) —
это данные команды.

Части команды проверяются в том каталоге, где они выполняются: termide
отслеживает `cd`, `pushd` и `popd` по строке, а программа, заданная путём,
сравнивается с правилами и по приведённому пути — относительно корня внутри
проекта, абсолютному вне его, — и как написано, так что
`cd /tmp && ./venv/bin/pip install x` подходит под `/tmp/venv/bin/pip *`.
Карточка спрашивает только о частях, которые не решены правилом или списком
«только посмотреть», перечисляет их под командой, а ответ на сессию или
навсегда записывает правило для каждой. Часть, чей каталог не определить
(после `cd $DIR`, `cd -` или подоболочки) или с подстановкой, помечена
«только на этот раз»: правило для неё не записывается, а если такой нет ни у
одной части, карточка предлагает только разрешить один раз и отклонить.

Ответ, который переживает этот вызов, — решение, принятое без единого взгляда
на вызовы, которые оно накроет, поэтому карточка предлагает его только там,
где правила говорят достаточно. **Разрешить навсегда** появляется для одной
команды, чей шаблон задаёт её охват: не для команды из нескольких частей, на
которую ты ответил разом; не для той, что уничтожает то, к чему прикасается
(`rm`, `git clean`, `git push`, `git stash drop`, установка или публикация
пакета); не для той, что запускает *другую* программу, чьё имя шаблон не
показывает (`env rm`, `xargs rm`, `./deploy.sh`, `sh -c …`, `python3 -c …`,
`make`, `nix run`). **Разрешить на сессию** снимается только у команды,
которая уничтожает: сессию пережить такое недолго, и кончается вместе с
панелью. Значит команда, которая уничтожает, разрешается по одному разу за
раз — `all` есть режим, пропускающий прогон без вопроса. **Отклонить на сессию** предлагается всегда: он ничему не доверяет.
Снятые строки исчезают, а не гаснут, так что ответ, который ты даёшь, и есть
ответ, который записывается.

Режим решает, какие правила действуют и что делать с тем, что они не
покрывают. `mode` в настройках — это начальное значение, с которым стартует
каждая новая сессия (`auto`, если не менять), его же можно выбрать в
разделе **AI** модала настроек, в группе Permissions; чип **Разрешения** и
`Shift+Tab` меняют его только для текущей панели.

- **ask** спрашивает обо всём; разрешения `allow` из настроек не действуют,
  действуют только ваши ответы в этой сессии.
- **plan** читает и ходит в веб, а всё, что может что-то изменить,
  отклоняет; агент отвечает планом. См. ниже.
- **edit** дополнительно правит и создаёт файлы внутри проекта без вопросов;
  команды, инструменты MCP и файлы вне проекта спрашивают. Разрешения `allow`
  из настроек не действуют.
- **configured** следует правилам из настроек и вашим ответам в этой сессии,
  об остальном спрашивает и предлагает «разрешать всегда».
- **auto** (по умолчанию) следует правилам из настроек, кроме широких
  `allow`, правит файлы внутри проекта без вопросов, а то, о чём иначе
  спросил бы, отдаёт модели-ревьюеру, которая разрешает или блокирует вызов
  вместо вас. См. ниже.
- **all** разрешает всё.

| | ask | plan | edit | configured | auto | all |
|---|---|---|---|---|---|---|
| чтение в проекте | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| чтение вне проекта | ? | ? | ? | правила / ? | правила / Р | ✓ |
| веб-поиск | ? | ✓ | ✓ | правила / ? | ✓ | ✓ |
| загрузка страницы | ? | ✓ | ✓ | правила / ? | правила / Р | ✓ |
| правка в проекте | ? | ✗ | ✓ | правила / ? | ✓ | ✓ |
| правка вне проекта | ? | ✗ | ? | правила / ? | правила / Р | ✓ |
| команда «только посмотреть» | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| прочая команда, MCP | ? | ✗ | ? | правила / ? | правила / Р | ✓ |

✓ — выполняется, ? — спрашивает, ✗ — отклоняется, Р — решает ревьюер,
«правила / ?» — по совпавшему правилу, а без него спрашивает. В любом режиме `deny` из правил
отклоняет, а `ask` спрашивает: режимы отключают только разрешения `allow` из
настроек, но не запреты. Ваши ответы на сессию действуют во всех режимах,
кроме `all`.

Команды «только посмотреть» — короткий список тех, что лишь смотрят (`ls`,
`cat`, `rg`, `git status`, `git log`, `find`, `cd` и подобные);
перенаправление в файл лишает команду этой поблажки, а направление потока в
другой (`2>&1`) или в `/dev/null` — нет. Так же действуют аргументы, с
которыми такая команда пишет файл или запускает другую программу: `env`
считается, только если ему не передана команда, `git branch`, `git tag`,
`git remote`, `git stash`, `git worktree`, `git reflog` и `git config` —
только пока они выводят список или значение (и никогда с `-c`
или `-C`: настройка или конфиг чужого репозитория могут запустить программу),
`git grep` — только без `-O`, CLI форджей `gh`, `glab` и `tea` — только
чтобы вывести список, посмотреть и поискать задачи, pull/merge request'ы,
прогоны CI, релизы, репозитории и метки (без `--web` и без `api`; `glab ci
view` и `glab ci status` спрашивают, потому что умеют перезапускать задания,
как и `tea comments` без подкоманды, который публикует комментарий), `sed` — только пока печатает
(без `-i` и `-f`, а скрипт состоит из адресов с `p`, `l`, `=`, `q` или `d`,
например `sed -n '40,80p'`; замена спрашивает), `find` — только без `-delete`, `-exec`, `-ok`,
`-fprint` и `-fls`, а `sort -o`, `uniq` с выходным файлом, `tree -o`/`-R`,
`rg --pre` и `git diff --output` спрашивают. Загрузка скилла никогда
не спрашивает.

### Режим плана

Когда задачу хочется сначала увидеть продуманной, а не сразу в правках,
включите **plan** (чипом, `Shift+Tab` или агентом, у которого в `AGENT.md`
стоит `mode: plan`). Пока режим включён, к системному промпту добавляются
инструкции из `system/plan.md`, а любой вызов инструмента, способный что-то
изменить, отклоняется с сообщением, которое модель читает, что бы ни говорили
правила, ответы на сессию или одобрение хука: `edit`, `write`, инструменты
MCP и любая команда оболочки не из списка «только посмотреть»; для команды
сообщение называет часть, которая в список не входит, чтобы агент сразу
выбрал другой путь. Чтение внутри проекта, веб и `skill` работают без вопросов, чтение снаружи спрашивает.
`task` тоже работает: подагент удерживается в режиме плана, что бы ни говорил
его `AGENT.md`, поэтому только читает.

Инструкции по умолчанию заставляют агента проработать задачу вместе с вами,
прежде чем писать план. Сначала он исследует и сам выясняет факты, отдавая
широкие поиски подагенту. Затем выносит открытые решения на вас раундами
карточек `question`, до четырёх вопросов за раунд, у каждого первым идёт
рекомендуемый ответ. Каждый раунд опирается на ответы предыдущего, и раундов
столько, сколько нужно задаче: десятки на большой, ни одного на маленькой и
ясной. Рутинные решения он принимает сам и называет в плане. План затем
содержит цель и признак готовности, решения и их причины, что вне рамок,
шаги по порядку с файлами, которые каждый меняет, риски и проверки.

Когда агент отвечает, карточка спрашивает, что делать с планом:

```
┌ Plan mode: carry the plan out? ──────────────┐
│ 1. Yes, accepting edits, from a clean context│
│ 2. Yes, accepting edits                      │
│ 3. Yes, under the configured rules           │
│ 4. Keep planning                             │
└──────────────────────────────────────────────┘
```

Первые три пункта выводят из режима плана в edit или configured и отправляют
запрос из шапки `system/plan.md`, так что та же сессия продолжает выполнять
план; последний (или `Esc`) оставляет режим плана, и следующий ввод уточняет
план. План — это ответ агента в сессии, в файл ничего не пишется; изменения,
которые последуют, покрыты контрольными точками `/undo`.

Второй и третий пункты оставляют в контексте всё, что прочитано при
планировании, и отправляют `request:`. Первый перед отправкой
`clean_request:` убирает из контекста исследование: остаются ваши сообщения,
вопросы, на которые вы ответили, с ответами, загруженные навыки и каждый
ответ, которым агент закончил прогон, план в том числе; прочитанные файлы,
выполненные команды, веб-страницы и отчёты подагентов уходят. Ничего не
пересказывается, поэтому решения остаются дословно, а агент перечитывает то,
что затрагивает каждый шаг. Это подходит для долгого планирования, чьё
исследование мешало бы работе. Журнал сессии хранит всё: открытая заново
сессия показывает очищенный разговор, как после сжатия, `recall` по-прежнему
находит убранное, а отмена запроса на выполнение возвращает его.

На Claude Code, Codex и Gemini CLI карточка тоже появляется, но без строки
с чистым контекстом: такой агент сам хранит свою историю, и termide нечего
в ней очищать. У внешнего агента, который подчиняется собственной
конфигурации, нет ни режима плана, ни карточки.

### Режим auto

**auto** — для работы, направлению которой вы доверяете, но отвечать на
карточку за карточкой не хотите. То, что решают правило или безопасное
умолчание, решается как в `configured`; всё, ради чего появилась бы
карточка, уходит ревьюеру — отдельному вызову модели, которая решает,
разумный ли это шаг к тому, о чём вы просили, или он выходит за рамки.
Разрешённый вызов выполняется; заблокированный — нет, и модель читает
причину вместе с советом пойти более безопасным путём или сказать вам, что ей
нужно. Так же устроены auto mode в Claude Code и auto-review в Codex.

Ревьюер видит то, что вы написали в сессии, и вызовы, которые сделал агент,
но никогда — результаты этих вызовов и собственный текст агента. Через
результаты в контекст попадает враждебное содержимое файлов и веб-страниц, а
агент не должен иметь возможности уговаривать ревьюера, поэтому ни то, ни
другое до него не доходит. Поставленное вами ограничение («не пушь», «дождись
моего ревью») действует, пока вы его не снимете, и переживает сжатие
контекста: запись ваших слов для ревьюера хранится отдельно от контекста
модели.

Кое-что ревьюеру никогда не доверяется и спрашивается, как в `configured`:

- вызов, который покрывает правило `ask`;
- удаление корня файловой системы, домашнего каталога, рабочего каталога или
  каталога выше него (`rm -rf ~`, `rm -rf .`, `rm -rf *`);
- всё подряд, когда ревьюер заблокировал три вызова подряд или двадцать за
  сессию: вопросы возвращаются к вам, а разрешение одного из них снова
  передаёт решения ревьюеру;
- вызов, по которому ревьюер не смог решить: запрос упал, не уложился во
  время или ответ не содержал вердикта.

`deny` из правил отклоняет, как в любом режиме. Широкие правила `allow` —
на весь инструмент (`"*" = "allow"`), с маской после интерпретатора, запуска
скриптов или обёртки (`python3*`, `npm run *`, `make*`, `env *`), `allow`
для `task` — откладываются, потому что пропускали бы мимо ревьюера любую
программу; узкие вроде `"cargo test*"` по-прежнему проходят без него.

Что говорится ревьюеру, лежит в `system/classify.md` каталога агента на
уровне настроек: что разрешать, что блокировать и в каком виде давать
вердикт. Правьте его, чтобы рассказать ревьюеру о своей инфраструктуре и
привычках. По умолчанию вызовы оценивает модель самой сессии; `auto_reviewer`
в `[ai]` (в окне настроек — **Ревьюер режима auto** в разделе «Разрешения»)
называет другое подключение для этого, обычно маленькую и быструю модель.
Проверка — это ещё один вызов модели перед каждым действием, которое она
решает; чтение, правки внутри проекта и команды «только посмотреть» до неё не
доходят и ничего не стоят.

```toml
[ai]
auto_reviewer = "haiku"   # имя подключения; пусто — оценивает модель сессии
```

Ревьюер оценивает и делегированную работу: вызовы подагента проверяются
против ваших слов и выданной ему задачи, помеченной как слова другого
агента. Запуск без интерфейса пользуется им так же, только там, где панель
спросила бы, выходит отказ. Внешний (с `command`) агент держит разговор у себя,
поэтому в `auto` о его запросах спрашивается, как в `configured`.

## Меню AI

Меню **AI** в верхней строке (после **Проекты**) управляет ресурсами агента
без открытия панели. В нём четыре раздела — **Агенты**, **Сессии**, **Скиллы**,
**Промпты**, — каждый открывает список для просмотра стрелками `↑`/`↓`; стрелки,
`Enter` и мышь работают как в меню **Команды**. Элементы из проекта (жирным) и
глобальной конфигурации показаны вместе (см. [Каталог агента](#каталог-агента)).

- `Enter` (или `F4`) редактирует: открывает `SKILL.md` скилла или `.md` промпта
  в редакторе, для агента так же открывает его `AGENT.md`; сессия возобновляется — с фокусом на уже открытой
  её панели, либо в новой панели агента, если такой нет.
- `Delete` удаляет элемент (с подтверждением); `F2` переименовывает (для сессии
  задаёт отображаемое имя). Подтверждение удаления сессии называет её
  (отображаемое имя, первый запрос или «без названия») и её id.
- Первые две строки в Агентах, Скиллах и Промптах создают новый элемент —
  **Создать (в проекте)** в `.termide/ai/` или **Создать (глобально)** в каталоге
  конфигурации — спрашивают имя и открывают новый файл. Сессии создаются
  запуском агента, поэтому строк создания у них нет.
- В каждой строке сессии справа тускло показано, когда с ней работали в
  последний раз (например, «2h ago»).
- Агент, скилл или промпт с описанием показан как `имя · описание` (front
  matter `description` в `AGENT.md`, `SKILL.md` или промпте); слишком длинная для меню строка обрезается на `…`.

Под разделами, как только открыта панель агента, пункт **Показать окно
браузера** выводит веб-браузер агентов на экран, чтобы наблюдать за его работой
(см. [Веб](#веб)), а **Скрыть окно браузера** убирает его.

## Каталог агента

Собственные файлы агента лежат в каталоге `ai`, который существует на трёх
уровнях, от старшего приоритета к младшему:

1. `.termide/ai/` в каталоге, где работает панель;
2. `.termide/ai/` в корне проекта TermIDE, если это другой каталог;
3. `ai/` в каталоге настроек TermIDE
   (`~/.config/termide/ai/` на Linux,
   `~/Library/Application Support/termide/ai/` на macOS).

Одиночный файл берётся с первого уровня, где он есть. Каталог именованных
записей (агенты, скиллы, шаблоны запросов) объединяется по всем уровням, и имя,
заданное выше, скрывает такое же имя ниже.

```
ai/
  agents/default/AGENT.md  агент по умолчанию (только уровень настроек)
  agents/<name>/AGENT.md   любой другой агент: настройки и шаблон промпта
  skills/<name>/SKILL.md   скиллы, см. ниже
  prompts/<name>.md        шаблоны запросов, вызываются как /name
  commands/<name>          командные скрипты, вызываются как /name, см. ниже
  shims/<команда>          прослойки команд (только уровень настроек), см. ниже
  mcp.toml                 MCP-серверы, см. ниже
  mcp-auth.json            входы на MCP-серверы (только уровень конфигурации), см. MCP-серверы
  hooks.toml               командные хуки, см. ниже
  system/compact.md        как агент сжимает длинную сессию
  system/compacted.md      как сводка звучит в контексте
  system/plan.md           что режим плана говорит агенту и что отправляет принятие плана
  system/goal.md           как судья решает, достигнута ли цель /goal
  system/handoff.md        как /handoff описывает недоделанную работу
  system/recall.md         как решатель recall отвечает по результатам
  system/classify.md       что ревьюер режима auto разрешает и блокирует
  system/permissions.md    что модель читает, когда вызов отклонён
  tools/<name>.md          что модели говорится о встроенном инструменте
  web/engines/<name>.toml  поисковики для web_search, см. «Веб»
  web/browser/             профиль браузера веб-инструментов (только уровень настроек)
```

При первом открытии панели уровень настроек размечается: в `AGENT.md` агента
по умолчанию, файлы `system/` и `tools/` и описания поисковиков записываются
поставляемые тексты, `skills/`, `prompts/`, `commands/` и `shims/` создаются
пустыми. Шаблон агента по умолчанию, оставшийся от прежней версии в
`ai/AGENTS.md`, при этом переносится в `agents/default/AGENT.md`. termide запоминает, что
отгрузил (в `.seeds.toml`), и на последующих стартах держит эти файлы
актуальными: тот, что вы не правили, обновляется при смене поставляемой версии
(обновления доходят до вас); тот, что вы правили, не трогается — новый дефолт
кладётся рядом как `<file>.new`, чтобы сравнить и смёрджить когда удобно.
Удалите файл, чтобы вернуть поставляемую версию.

### Агенты

Агент — это каталог внутри `agents/`. `default` — тот, с которого панель
начинает; его задаёт только уровень настроек, поэтому проект не может
подменить агента, с которого начинается каждая панель. Любой каталог с
`AGENT.md` задаёт агента, на которого можно переключиться чипом **Agent** в
статусной строке (хватит и пустого файла; каталог без него агента не задаёт);
список показывает описание каждого. Агент — это его `AGENT.md`: front matter
задаёт, чем агент отличается (все поля необязательны), а тело — его
собственный шаблон промпта. `AGENT.md` без тела
говорит шаблоном агента по умолчанию, но не берёт его настроек; сам агент по
умолчанию без тела — поставляемым шаблоном. `prompt: none` означает, что
системного промпта нет вовсе: инструменты модель получает, но без инструкций.
Остальное в каталоге — собственное агента: скрипты или чеклисты, на которые
ссылается его промпт.

```markdown
---
description: Проверяет диффы и указывает на риски
model: Qwen3.8-27B-MTPLX-Optimized-Quality
mode: edit
tools: read, bash
---
Ты проверяешь переданные тебе изменения. …

{{tools}}
```

Front matter — строки `ключ: значение`; строка, начинающаяся с `#`, —
комментарий, значение можно взять в кавычки. `model` — id модели на
настроенном сервере; `mode` — режим разрешений, с которого агент начинает
(`ask`, `plan`, `edit`, `configured`, `auto` или `all`); `tools` перечисляет
через запятую встроенные инструменты, которые остаются у агента (список можно
взять в квадратные скобки или записать списком YAML — строками `- имя` под
`tools:`), включая `task`; без поля у агента есть все, а
`tools: []` не оставляет ни одного. Skills и инструменты
MCP-серверов этот список не касается: они приходят с тем, что вы настроили.
Ключ, который termide не читает, — опечатка вроде `descripton:` — при открытии
панели показывается под баннером.

Смена агента посреди сессии меняет промпт и инструменты для следующего
запроса; модель и режим меняются, только если определение их называет, а
журнал сессии записывает смену, как и для чипа **Model**. Открытая заново
сессия возвращается тем агентом, которым работала последним; сохранённая
раскладка тоже его помнит.

### Подагенты

Когда агентов больше одного, у каждого агента на встроенном цикле появляется
инструмент `task`, передающий самостоятельную задачу другому агенту.
Делегат проходит свой цикл до конца — свой промпт, свои инструменты, своя
модель — и его итоговый ответ возвращается как результат инструмента; шаги и
файлы, которые он читал по пути, остаются вне основного разговора. Так
лаконичный ревьюер или сосредоточенный поисковик делает работу, не заполняя
сессию, как инструмент `Task` в Claude Code и подсессии в OpenCode.

Делегат не видит разговора, поэтому вызывающий агент должен вложить всё в
промпт. Он работает в текущем режиме сессии, если его `AGENT.md` не задаёт
свой (режим плана сильнее: делегат планирующего агента только читает), и
спросить ему некого, поэтому он может только то, что уже разрешают
правила и этот режим: всё, что иначе спросило бы, отклоняется с причиной,
которую он читает. В `auto` эти вызовы вместо этого решает ревьюер. Внешние
агенты (с `command`) делегатами быть не могут, а у подагента своего инструмента `task` нет, так что делегирование не
вкладывается. Агент, в чьём списке `tools` нет `task`, делегировать не
может. Прогон, который не останавливается, обрывается после
пятидесяти вызовов модели.

### Внешние агенты

Агентом может быть совсем другая программа: укажите `command` в front matter
её `AGENT.md`, и панель будет управлять ею по
[Agent Client Protocol](https://agentclientprotocol.com) вместо встроенного
цикла. У Claude Code, Codex и Gemini CLI есть ACP-адаптеры или родная
поддержка:

```markdown
---
description: Claude Code через его ACP-адаптер
command: npx -y @agentclientprotocol/claude-agent-acp
---
```

`command` — программа и её аргументы; строка делится на слова, как это делает
shell (кавычки сохраняют пробелы внутри аргумента), но через shell не
запускается, поэтому ничего в ней не раскрывается. Программа наследует
окружение TermIDE; строка `env.<ИМЯ>: значение` на каждую переменную добавляет
её или переопределяет, а `$NAME` и `${NAME}` в значении берутся из окружения
TermIDE (`env.ANTHROPIC_BASE_URL: http://localhost:8080`). `timeout` — сколько
секунд ждать запуска, по умолчанию 120.

Программа запускается в фоне при переключении на агента; первый запрос её
дождётся. Её ответы, размышления и вызовы инструментов появляются в сессии,
как у встроенного агента, а файлы она читает и пишет через TermIDE, так что
открытый редактор следует за её правками. Её запросы разрешений судятся теми
же правилами, что и у встроенного агента: команда только для чтения или запрос,
уже покрытый правилом `[ai.permissions]` или разрешением сессии, проходит без
карточки, а до вас доходит лишь остальное — поэтому разрешённую команду или
команду только для чтения не спросят дважды. Чип **Разрешения** при внешнем агенте
пропадает: у него свой, и режим TermIDE для него не переключается. Чип
**Модель** остаётся, если агент объявляет свои модели по ACP — тогда он их
перечисляет и переключает через `session/set_model`, так что модель внешнего
агента выбирается прямо в TermIDE; если моделей агент не объявил, чипа нет.
Скиллы, шаблоны запросов и MCP-серверы тоже дело самого агента; `model`,
`mode`, `tools` и тело его `AGENT.md` не действуют. Смена агента пересобирает
разговор на том же журнале сессии: прежние сообщения остаются на экране, но
внешний агент их не знает, и панель об этом сообщает.

### Системный промпт

Промпт, который получает модель, собирается из файлов: тело
`ai/agents/default/AGENT.md` агента по умолчанию — шаблон с подстановками,
которые агент заполняет. В TermIDE нет вшитого текста промпта: шаблон ниже
поставляется файлом данных (`crates/agent-core/assets/agents/default/AGENT.md`),
при первом использовании записывается на уровень настроек, и дальше действует
именно файл. Это запасной шаблон любого агента, поэтому
`.termide/ai/agents/default/` проекта игнорируется, а шаблон меняется, только
когда вы выбираете агента, у которого в `AGENT.md` есть тело. Соглашения проекта пишутся в его
`AGENTS.md`, который шаблон подключает как инструкции проекта (см. ниже):

```markdown
You are a coding agent working inside termide, an all-in-one terminal workspace (editor, file manager, terminal, git). You help with software tasks in the current project: you read code, make targeted edits, run commands and report what you did and what you found.

# Guidelines
- Read a file before you change it, and keep edits small and targeted.
- Name file paths clearly when you talk about files.
- Be concise.
- Check the facts of the moment with a tool rather than guess them: run `date` for today's date, read a file for its contents, `git log` for history. State plainly when you did not check.
{{guidelines}}

{{if skills}}
# Skills
When a task matches one of these, load it with the `skill` tool before starting.
{{skills}}
{{/if}}

# Environment
{{environment}}

{{project_instructions}}
```

`{{tools}}` — список инструментов по строке на каждый (в сиде его нет: модель
и так получает каждый инструмент с описанием и схемой рядом с промптом, но
шаблону для слабой модели такой обзор может пригодиться), `{{guidelines}}` —
правила, которые добавляют сами инструменты, `{{skills}}` — скиллы с именем и
описанием, `{{environment}}` — рабочий каталог, платформа и признак
git-репозитория, `{{project_instructions}}` — файлы инструкций, описанные
ниже. Дату промпт намеренно не несёт: сессия живёт часами, и дата в промпте
тихо протухает, поэтому сид вместо этого велит проверять ситуативный факт
инструментом — `date` для сегодняшней даты, — а не помнить его наизусть.

`{{if skills}} … {{else}} … {{/if}}` убирает раздел из промпта, когда показать
нечего: ветка `{{if}}` остаётся, если у имени есть что показать, иначе —
`{{else}}`, а без `{{else}}` блок исчезает целиком. Поэтому сессия без
скиллов не рассказывает модели про скиллы и не зовёт её вызывать `skill`,
которого нет. Условие — тег на отдельной строке: тег в середине строки или
внутри подставляемого значения остаётся текстом; вложенности нет.
Одиночное `{{name}}` вне блока — по-прежнему просто значение, `(none)` для
пустого списка, так что шаблон, написанный до появления блоков, продолжает
работать.

Перепишите файл, уберите раздел или добавьте свой; подстановка, которую
вы не указали, просто не отправляется. Команда `/prompt` открывает собранный
результат в просмотрщике, так что видно ровно то, что получает модель.

### Служебные промпты

Собственные промпты TermIDE тоже файлы, в `system/`, и засеваются при первом
запуске, как `AGENT.md` агента по умолчанию. Читается только `system/` уровня настроек: такой же
каталог в проекте игнорируется, чтобы склонированный репозиторий не мог
переписать, как termide сжимает сессию, планирует и выносит оценки. Сжатие, то есть сводка,
которая заменяет старую часть длинной сессии, использует два: `compact.md` —
системный промпт суммирующего вызова, в шапке которого `request:` задаёт
закрывающую реплику пользователя, а `{{focus}}` принимает слова, переданные
`/compact`; `compacted.md` — сообщение, которым сводка становится в контексте,
с `{{summary}}` на месте текста модели. Правьте их, чтобы изменить, что сводка
сохраняет и как представляется.

```
/compact              сжать сейчас
/compact the API      сжать сейчас, сосредоточившись на API
```

`/compact` встроена и стоит в списке `/` рядом с вашими шаблонами; она ждёт
текущую задачу, как любое переключение. Автоматическое сжатие при
приближении к контекстному окну использует те же файлы. Когда оно начинается и
сколько сохраняет, задаётся в `config.toml`; пропущенный ключ сохраняет значение
по умолчанию:

```toml
[ai.compaction]
enabled = true              # сжимать автоматически у края окна
reserve_tokens = 16384      # начинать, когда контекст превышает окно минус это число
keep_recent_tokens = 4096   # недавние сообщения дословно (не больше четверти окна)
```

[Режим плана](#режим-плана) использует `plan.md`: его тело добавляется к
системному промпту, пока режим включён, а `request:` в шапке — сообщение,
которое отправляется при принятии плана; `clean_request:` — то, что
отправляется при принятии с чистого контекста (без него служит `request:`).
Перепишите тело, чтобы изменить,
что должен содержать план, или запрос, чтобы иначе сказать агенту «вперёд».
Claude Code получает системный промпт один раз, при старте своей сессии,
поэтому о последующем переключении режима плана он узнаёт из заметки перед
вашим следующим сообщением; в журнал сессии она не попадает. При включении
режима это тело файла, при выключении — `leave:`.

`/goal <что достичь>` использует `goal.md`: агент работает к цели, и после
каждого хода судья — отдельный вызов модели только для чтения — решает,
достигнута ли она. `goal.md` — это системный промпт судьи, с `{{goal}}` вместо
текста цели и вопросом-вердиктом в шапке (`request:`). Судья отвечает `DONE`
или `CONTINUE` с одной строкой обоснования; на `CONTINUE` агента отправляют
доделывать с тем, чего не хватает, — пока судья не скажет «готово», ход не
завершится ошибкой или не будет достигнут предел в пятьдесят ходов. `/goal
stop`, `Esc` или остановка выполнения завершают цикл. Перепишите `goal.md`,
чтобы изменить строгость судьи.

```
/goal довести тесты до зелёного   работать, пока судья не согласится
/goal stop                        завершить активную цель
```

`/handoff` использует `handoff.md`: read-only модельный вызов сгущает транскрипт
в направленный вперёд бриф — цель, что сделано, что осталось, ключевые решения,
файлы и как проверить — чтобы свежая сессия или другой агент подхватили работу
с нуля; в отличие от `/compact`, который сжимает весь разговор ради продолжения
на месте. `handoff.md` — системный промпт этого вызова, запрос в его шапке.
Когда бриф готов, карточка предлагает **сохранить его в `HANDOFF.md`** в каталоге
панели (откуда его прочтёт другой агент, даже внешний, читающий файлы; добавьте
в `.gitignore`) или **начать из него новую сессию**, засеяв её брифом.
Перепишите `handoff.md`, чтобы изменить содержимое брифа.

Решатель [recall](#recall) использует `recall.md`: системный промпт вызова,
который отвечает по результатам поиска, со строкой вопроса в шапке
(`request:`, `{{question}}` — запросы); результаты идут после неё. Перепишите
его, чтобы изменить, как ответ выводится и на что ссылается.

### Тексты инструментов

То, что модели говорится о каждом встроенном инструменте, — тоже файл:
`tools/<name>.md` для `read`, `edit`, `write`, `bash`, `question`,
`suggest_command`, `task`, `skill`, `fetch`, `web_search` и `recall`; он
засевается и обновляется, как файлы `system/`, и читается только с уровня
настроек. Тело — описание, которое модель видит вместе с инструментом;
`snippet:` в шапке — его строка в списке инструментов системного промпта (без
неё инструмент в список не попадает, но вызывать его можно), а `guideline.1:`,
`guideline.2:`, … — правила, которые добавляются к правилам промпта в этом
порядке. В `task.md` на место `{{agents}}` подставляется список агентов, которым
можно поручить работу. Перепишите файл, чтобы изменить, как агент пользуется
инструментом; сам инструмент, его аргументы и то, что он возвращает, не
меняются. Правка доходит до панели, когда она в следующий раз берёт своего
агента (новая панель, смена агента или набора инструментов), и до каждой
задачи, которую она с этого момента поручает подагенту. Файл с пустым телом
пропускается целиком, вместе с шапкой; об этом, о другом ключе и о файле,
названном не по встроенному инструменту, при открытии панели сообщается под
баннером.

```markdown
---
snippet: read a file as numbered lines, paged with offset/limit
guideline.1: Use `read` instead of `cat`, `head` or `sed -n` to look at files.
---
Read a text file. Returns lines prefixed with their 1-based line number. …
```

### Скиллы

Скилл — это каталог с `SKILL.md` в формате [agentskills.io](https://agentskills.io):
YAML-шапка с `name` и `description`, затем инструкции, плюс файлы, на
которые инструкции ссылаются (скрипты, чек-листы, примеры):

```markdown
---
name: release
description: Выпустить релиз: версия, changelog, тег, пакеты
---
# Release

1. Запустить `scripts/check.sh` …
```

Скиллы читаются из `skills/` на трёх уровнях каталога `ai`, а также из
`.agents/skills/` в каталоге панели и в корне проекта — каталога, общего для
других агентов, так что скилл, написанный для Claude Code, Codex или pi,
работает без изменений. Одинаковое имя на старшем уровне скрывает младшее.

В промпт попадают только имена и описания, по строке на скилл под
`{{skills}}`; сами инструкции входят в разговор, когда модель загружает
скилл инструментом `skill`, который возвращает текст `SKILL.md` и перечисляет
лежащие рядом файлы, чтобы модель прочитала нужные через `read`. Загрузка
скилла никогда не спрашивает разрешения. Инструмент существует, только когда
есть хотя бы один скилл, и на него не действует список `tools` агента.

Скилл принимает аргументы так же, как [шаблон запроса](#шаблоны-запросов):
`argument-hint` в шапке говорит, что передавать, и выводится после имени
(`- review <путь>: Проверить файл`), модель передаёт аргументы вместе с
именем, а `$ARGUMENTS` и `$1`…`$9` в теле подставляются; тело без подстановок
получает аргументы отдельной строкой в конце.

Скилл можно отправить и самому — как `/имя аргументы` или `/skill:имя
аргументы`: его текст с подставленными аргументами и списком файлов уходит
вашим запросом, как у шаблона. Скилл, выключенный в наборе инструментов, так
тоже работает: выключение убирает его из контекста модели, а не от вас.

### Шаблоны запросов

Шаблон запроса — это Markdown-файл `prompts/<имя>.md` на любом из трёх
уровней, который отправляется как `/имя` с аргументами. Шапка необязательна:
`description` для списка и `argument-hint` — что печатать после имени. В теле
`$ARGUMENTS` означает всё после имени, а `$1`…`$9` — его слова; тело без
подстановок получает аргументы отдельной строкой в конце.

```markdown
---
description: Проверить файл на ошибки и риски
argument-hint: <путь>
---
Review $1. Point at bugs first, style last, and quote the lines you mean.
```

`/review src/parser.rs` отправит развёрнутый текст. В сессии сообщение
озаглавлено тем, что вы набрали, — `/review src/parser.rs`, — а текст, который
получила модель, свёрнут под ним; `↑` вспоминает команду, а не текст. Если
набрать `/`, появится список шаблонов, а выбор подставляет `/имя ` в поле ввода. Сообщение, начинающееся с `/` без такого шаблона, не
отправляется; путь вроде `/usr/bin/ls` — обычный текст.

### Командные скрипты

Если шаблон — это неизменный текст, то командный скрипт собирает запрос сам:
исполняемый файл `commands/<имя>`, запускаемый как `/имя аргументы` с
аргументами в argv и каталогом панели как рабочим, чей стандартный вывод
отправляется модели. `/review`, собирающий `git diff --staged`, `/failing`,
запускающий тесты и вставляющий упавшие, `/issue 123`, забирающий задачу из
трекера. Язык любой; комментарии в начале файла описывают его:

```sh
#!/bin/sh
# description: Проверить подготовленные изменения
# argument-hint: [фокус]
# timeout: 30
printf 'Review this diff%s:\n\n' "${1:+ with attention to $1}"
git diff --staged
```

Вывод появляется в сессии как ваш запрос, свёрнутый под командой, как текст
шаблона, так что полученное моделью — в одном щелчке. Скрипт, завершившийся с
ошибкой, ничего не напечатавший или превысивший таймаут (по умолчанию 60 с),
ничего не отправляет и сообщает причину. Скрипты уровня настроек — ваши
собственные и запускаются сразу; пришедший с проектом или каталогом сначала
спрашивает карточкой, как разрешение: запустить один раз, на сессию, всегда
(пишется правило `[ai.permissions.command]`) или не запускать.

Встроенные команды, шаблоны, скрипты и скиллы делят имена `/`. Если одно имя
определено несколькими, побеждает встроенная команда, затем шаблон, затем
скрипт, затем скилл: проект не может перехватить `/clear`, а написанное для
ввода после `/` важнее написанного для модели. `/skill:имя` всегда доходит до
скилла, и список `/` предлагает скилл с занятым именем в таком написании.
О дважды определённых именах панель сообщает при открытии: строкой
**shadowed** на приветственном экране, которая по щелчку объясняет их, или
предупреждениями под возобновлённой сессией. Одно имя на разных уровнях
одного вида не считается конфликтом — старший уровень скрывает младший, так
устроены уровни.

### MCP-серверы

К встроенным инструментам добавляются инструменты серверов
[MCP](https://modelcontextprotocol.io). Сервер — это таблица в `mcp.toml` на
любом из трёх уровней; такое же имя выше заменяет таблицу ниже, а
`enabled = false` там выключает сервер для проекта или каталога.

```toml
[github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { GITHUB_PERSONAL_ACCESS_TOKEN = "$GITHUB_TOKEN" }   # $NAME берётся из вашего окружения
tools = ["search_issues", "get_issue", "create_issue"]      # необязательно: подмножество
timeout_secs = 60                                            # запуск и один вызов
```

Сервер — это либо программа, которую TermIDE запускает и слушает по stdio,
либо URL, до которого TermIDE говорит по Streamable HTTP: один запрос на POST,
ключи в `headers` (`$NAME` в значении заголовка берётся из вашего окружения,
как и в `env`). Не-`https` URL отклоняются, кроме loopback, — такие серверы
носят токены. В обоих случаях панель подключается в фоне при открытии и
сообщает в сессии, когда подключилась или почему нет. Его
инструменты видны как `<сервер>__<инструмент>` (например
`github__search_issues`) — форма, которую принимают OpenAI-совместимые
серверы; в системный промпт они не попадают, модель видит их схемы напрямую.
Каждая схема уходит с каждым запросом, поэтому сервер с десятками
инструментов стоит сузить через `tools`; лог предупреждает, когда у сервера
больше двадцати и списка нет.

Сервер может сменить инструменты на ходу. Программа сообщает об этом в свой
канал; URL-сервер — в поток, который TermIDE держит открытым после
рукопожатия и открывает заново, когда тот обрывается. В обоих случаях
инструменты перечитываются, и сессия получает новый набор, о чём пишет строкой.
Как и любая смена инструментов, это стоит следующему запросу кеша промпта.

Конфигурация читается при открытии панели. `/mcp reload` перечитывает её — на
всех уровнях и из всех `.mcp.json`: сервер, которого больше нет в
конфигурации, уходит вместе со своими инструментами, новый или изменённый
подключается, упавший пробует снова, а подключённый и не изменившийся
остаётся как есть. `/mcp reload <сервер>` делает это для одного сервера и
подключает его заново, даже если ничего не изменилось, — как кнопка `[↻]` на
его заголовке в списке инструментов. `/mcp` без аргументов показывает серверы
и состояние каждого.

URL-сервер без `Authorization` в `headers`, отвечающий `401`, хочет вход по
OAuth, и сессия об этом сообщает. `/mcp login <сервер>` открывает браузер на
странице авторизации сервера; после подтверждения браузер возвращается на
одноразовый слушатель на `127.0.0.1`, и сервер подключается. Адреса берутся из
метаданных самого сервера, TermIDE регистрирует себя клиентом, где сервер это
позволяет, обмен идёт с PKCE. Вход хранится в `mcp-auth.json` в каталоге `ai/`
конфигурации, доступном на чтение только вам, по URL сервера — поэтому его
разделяют все панели и все проекты, где настроен тот же URL, — и обновляется,
когда истекает. `/mcp logout <сервер>` его забывает. Если браузер не открылся
(например, по SSH), сессия показывает адрес, чтобы открыть его вручную;
браузер должен достучаться до слушателя, так что пробросьте его порт и
зафиксируйте его через `callback_port`. Серверу, который сам не регистрирует
клиентов, нужен клиент, зарегистрированный вручную:

```toml
[jira]
url = "https://mcp.example.com/mcp"
oauth = { client_id = "termide", client_secret = "$JIRA_SECRET", scopes = ["read"], callback_port = 8765 }
```

`.mcp.json` в каталоге панели, в любом каталоге выше него или в корне
проекта читается рядом с ними,
чтобы репозиторий, настроенный для Claude Code, Cursor или VS Code, приносил
свои серверы без правок — то же гостеприимство, что и `CLAUDE.md` с
`.agents/skills/`. Стандарта на этот файл нет: спецификация MCP оставляет
конфигурацию на совести каждого клиента. Поэтому он принимается ровно
настолько, насколько совпадает с termide: `command`, `args`, `env`, `cwd` и
`tools` — либо `url` с `headers` и `oauth` (`clientId`, `clientSecret`,
`scopes`, `callbackPort`); под любым из корневых ключей (`mcpServers`
или `servers` у VS Code); `disabled` и `enabled = false` читаются как
выключено; `${workspaceFolder}`, `${userHome}` и `${env:NAME}` подставляются.
Сервер `sse` пропускается — это прежний транспорт, где запросы идут на адрес,
который сначала называет поток, и TermIDE говорит не на нём, —
как и сервер со ссылкой `${input:…}`: в другом инструменте она спрашивает у
вас секрет, а termide запустил бы его с пустым. Каждый пропуск попадает в
лог. Внутри одного
каталога такое же имя выигрывает `mcp.toml`; каталог ближе к панели
выигрывает оба. Поэтому один `.mcp.json` над группой репозиториев обслуживает
каждую панель, открытую внутри них, — так же его читает Claude Code.

MCP-инструмент спрашивает разрешение, как команда: в `all` работает, в `plan`
отклоняется, в `auto` уходит ревьюеру, в остальных спрашивает, если в
`configured` его не покрывает правило. «Разрешить всегда» пишет правило по имени инструмента:

```toml
[ai.permissions.github__search_issues]
"*" = "allow"
```

### Хуки

Хук — это программа, которую TermIDE запускает вокруг вызова инструмента; он
объявляется в `hooks.toml` на любом из трёх уровней (слияние как у
MCP-серверов). Событие приходит программе JSON-ом на стандартный ввод, ответ
она печатает JSON-ом на стандартный вывод — та же форма, что у Claude Code,
Gemini CLI и Cursor:

```toml
[no-force-push]
event = "before_tool_call"      # или after_tool_call
tools = ["bash"]                # шаблоны; без поля — все инструменты
command = "scripts/guard.sh"    # запускается в каталоге панели
timeout_secs = 30
```

Перед вызовом на входе `{"event","hook","cwd","tool","arguments"}`. Программа
может напечатать `{"decision": "block", "reason": "…"}`, чтобы пропустить
вызов (причина уходит модели), `{"decision": "allow"}`, чтобы выполнить его
без запроса разрешения, или `{"arguments": {…}}`, чтобы выполнить с другими
аргументами; без решения или с `"ask"` решают правила разрешений. Код
возврата 2 тоже блокирует, причиной становится стандартный вывод ошибок.
После вызова на входе есть ещё `"result": {"text", "is_error"}`, а
`{"text": "…"}` переписывает то, что увидит модель; код 2 превращает
результат в ошибку с текстом из stderr. Хуки идут в порядке имён перед
правилами разрешений; хук, упавший иначе или не уложившийся в таймаут,
записывается в лог и пропускается, так что сломанный хук агента не
останавливает.

### Прослойки команд

Прослойка (shim) — это исполняемый файл в `shims/`, названный как команда.
Когда встроенный агент запускает команду оболочки, каталог `shims/`
добавляется в начало `PATH` инструмента `bash`, поэтому прослойка перекрывает
реальную команду — в том числе внутри пайплайна (`… | grep …`). Это слой
экономии токенов, который вы расширяете руками: `shims/grep` с более компактным
поиском, `shims/cat`, срезающий шум, — каждый печатает сжатый результат для
модели. (Инструмент `bash` и сам чистит вывод; прослойка — та часть, что под
вашим контролем.)

```sh
# ~/.config/termide/ai/shims/rg  (chmod +x)
#!/bin/sh
# Ограничить ripgrep несколькими совпадениями на файл, дальше — реальный.
exec /usr/bin/rg --max-count 5 "$@"
```

Поскольку прослойка выполняется молча на каждой подходящей команде, учитывается
только `shims/` уровня настроек — никогда проектный или рабочего каталога, чтобы
репозиторий не мог подложить свой. Прослойка — обычный исполняемый файл на любом
языке; зовите реальную команду по абсолютному пути (или `PATH= command <tool>`),
чтобы не вызвать саму себя. Внешние (ACP) агенты запускают команды сами и не
проксируются.

### Инструкции проекта

Агент читает `AGENTS.md` (или `CLAUDE.md` в том же каталоге) из каждого
каталога от корня файловой системы до рабочего каталога панели, самый
конкретный последним, поэтому файл каталога панели старше файла проекта. Файл
корня проекта попадает в промпт и тогда, когда панель работает вне его.
Опишите там свои соглашения, и агент будет им следовать; глобальные правила
пишутся прямо в шаблон — `AGENT.md` агента по умолчанию. Файлы больше 32 КиБ пропускаются.

## История сессий

Каждая сессия пишется в журнал в формате JSON Lines, по файлу на сессию, в
`ai/sessions/<путь каталога панели>/` в каталоге настроек TermIDE, рядом с
агентами. В журнале записаны модель и агент, с которыми сессия началась, и
каждая их смена, поэтому открытая заново сессия продолжается на той модели и
тем агентом, что использовала последними. Когда сессия приближается к пределу
контекстного окна модели, агент заменяет старую часть сводкой, которую пишет
сам, и сохраняет недавние сообщения дословно; панель сообщает об этом, а
`/compact` делает это по запросу (см. [Служебные промпты](#служебные-промпты)).
`/undo` и откат к сообщению пишут запись `rewind`: журнал хранит все
сообщения, но ветка продолжается с момента перед откаченным запросом, в том числе после
повторного открытия.

При открытии сохранённой раскладки TermIDE панель агента возвращается вместе с
ней и продолжает ту сессию, в которой была, на модели этой сессии и тем же
агентом. Если журнал
удалён, панель начинает новую сессию; если модель больше не настроена, панели
в раскладке не будет.

## Из командной строки

`termide --prompt "<запрос>"` выполняет одну задачу агента, не открывая
интерфейс, печатает ответ в stdout и завершается. Это агент из панели — тот
же каталог `ai`, агенты, инструменты и правила разрешений — запущенный без
интерфейса, для скриптов, конвейеров и CI.

```
termide --prompt "опиши, что изменилось в src/main.rs"
git diff | termide --prompt -          # запрос читается из stdin
termide --prompt "прогони тесты и покажи падения" --agent runner
```

В stdout попадает только ответ, поэтому вывод удобно передавать по конвейеру;
работа инструментов и ошибки идут в stderr. `--agent` выбирает одного из
заданных агентов, иначе берётся агент по умолчанию. Код возврата `0` при
успехе, `1` при ошибке и `130` при прерывании.

Для машиночитаемого результата добавьте `--output json`: вместо потоковой
выдачи в конце печатается один JSON-объект с ответом, расходом токенов,
вызванными инструментами и статусом. `--output stream-json` печатает по
одному JSON-объекту на строку по ходу прогона — `tool_use` и `tool_result`
на каждый инструмент, `message` на каждый ответ и завершающий `result` с теми
же полями, что и `json` — для вызывающего, который следит за долгим прогоном
вживую.

```
termide --prompt "посчитай TODO в src" --output json
# {"ok":true,"answer":"7","stop_reason":"stop","model":"…","provider":"…",
#  "usage":{"input":…,"output":…,"cache_read":…,"cache_write":…},
#  "tools":[{"name":"bash","subject":"rg -c TODO src","error":false}],"error":null}
```

Ответить на карточку разрешения некому, поэтому запуск без интерфейса делает
только то, что уже разрешают правила и режим: всё, что иначе спросило бы,
отклоняется с причиной, которую модель читает. В режиме `auto` по умолчанию
то, что не решают правила, решает ревьюер, а вызов, по которому он не смог
решить, отклоняется; в `configured` добавьте правила `allow` для нужных команд
и путей или задайте `mode = "all"` для работы без присмотра. Режим плана без
панели смысла не имеет и трактуется как `auto`, а внешнего (с `command`) агента так
запустить нельзя.

`termide --recall "<запрос>"` выполняет поиск [recall](#recall) без интерфейса
и печатает результаты — тот текст, который прочитал бы агент, — или, с
`--output json`, один объект с результатами (и ответом решателя, если он
включён). Если ничего не найдено, код выхода — `1`. Другой агент может вызвать
его через свой shell, а вам он быстро покажет, что `recall` находит по вопросу.

```
termide --recall "почему отказались от tokio"
termide --recall "сводка компакции" --output json
```
