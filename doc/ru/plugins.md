# Плагины

Плагин — это программа, которую termide запускает в фоне, пока открыт проект,
и с которой общается по JSON-RPC через её stdin и stdout. Плагин узнаёт, что
происходит в редакторах и репозитории проекта, читает и правит открытые
буферы, добавляет команды со своими клавишами, помечает строки в редакторе,
показывает элементы в строке состояния, спрашивает в окнах termide, открывает
собственные панели и терминалы и даёт инструменты агенту.

Плагины глобальные: они устанавливаются в каталог конфигурации, а проект может
только выключить установленный вами плагин или включить тот, которому вы это
разрешили. Открытый репозиторий никогда не решает, какая программа запустится.

## Установка

Скопируйте каталог плагина в `plugins/` рядом с вашим `config.toml`:

| Платформа | Каталог |
|---|---|
| Linux | `~/.config/termide/plugins/<имя>/` |
| macOS | `~/Library/Application Support/termide/plugins/<имя>/` |
| Windows | `%APPDATA%\termide\plugins\<имя>\` |

Имя каталога — это имя плагина: латинские буквы, цифры, `-` и `_`. В каталоге
лежит `plugin.toml`:

```toml
description = "Форматирует при сохранении"
command = "./run.py"          # относительно этого каталога
args = ["--quiet"]
[env]
LOG_LEVEL = "info"
```

`command` — абсолютный путь, путь относительно каталога плагина (содержит `/`)
или просто имя, например `python3`. Просто имя ищется только в абсолютных
элементах `PATH`. Плагин запускается с рабочим каталогом, равным своему
каталогу, а корень проекта узнаёт из `initialize`.

Плагины читаются при запуске termide. После установки, удаления или изменения
плагина команда **Плагины: перечитать каталог плагинов** в палитре команд
(`Ctrl+P`) подхватывает его без перезапуска: все плагины запускаются заново, а
языковые функции нового плагина доступны редакторам, открытым после этого.
**Плагины: показать состояние**
перечисляет установленные плагины и их состояние в текущем проекте, а
**Плагины: перезапустить <имя>** запускает плагин заново.

## Включение и выключение

Глобальный `config.toml` задаёт режим каждого плагина:

```toml
[plugins.formatter]
mode = "on"       # по умолчанию: работает во всех проектах, проект может выключить
[plugins.deploy]
mode = "opt-in"   # работает только в проектах, которые его включили
[plugins.experiment]
mode = "off"      # не работает нигде

[plugins.formatter.settings]
line_width = 100  # передаётся плагину в `initialize`
```

Проектный `.termide/config.toml` может переключить плагин в пределах его
режима и дополнить его настройки:

```toml
[plugins.deploy]
enabled = true
[plugins.formatter]
enabled = false
```

| Глобальный `mode` | Проект молчит | `enabled = false` | `enabled = true` |
|---|---|---|---|
| `on` (или нет записи) | работает | выключен | работает |
| `opt-in` | выключен | выключен | работает |
| `off` | выключен | выключен | выключен |

Вкладка **Плагины** в настройках (`Alt+P`) перечисляет установленные плагины:
при глобальном хранении `Enter` на плагине переключает его режим, при
хранении в проекте — переключатель проекта.

`mode` в проектном файле и `enabled` в глобальном игнорируются с
предупреждением в журнале. Ставьте `opt-in` плагинам, которые работают с
содержимым проекта (например, запускают его скрипты), чтобы ни один
репозиторий не включил их без вашего согласия.

У каждого открытого проекта свой экземпляр каждого плагина, в том числе у
проектов, отложенных в фон. Упавший плагин перезапускается через 1, 2, 4…
секунды. После трёх падений за минуту он остаётся выключенным, пока не
изменятся его настройки, его не перезапустят, каталог плагинов не перечитают
или termide не перезапустится; строка состояния его проекта сообщает об этом.

## Как написать плагин

Каждое сообщение — одна строка JSON-RPC 2.0. Всё, что плагин пишет в stderr,
попадает в журнал termide. На Python протокол берёт на себя
`examples/plugins/sdk/termide_plugin.py` из репозитория, а в `examples/plugins/`
лежат плагины, написанные с ним.

**termide → плагин**

| Метод | Вид | Параметры | Результат |
|---|---|---|---|
| `initialize` | запрос | `protocolVersion` (1), `termide.version`, `plugin.name`, `plugin.dir`, `project.root`, `settings` | что плагин добавляет, см. ниже |
| `initialized` | уведомление | | |
| `command/execute` | запрос | `id` | любой |
| `tool/call` | запрос | `name`, `arguments`, `progress` | `text`, `isError` |
| `$/cancelRequest` | уведомление | `id` запроса, от которого termide отказался | |
| `shutdown` | запрос | | `null` |
| `exit` | уведомление | | |

События, на которые подписывается плагин, — уведомления о его собственном проекте:

| Событие | Параметры | Когда |
|---|---|---|
| `file/opened` | `path` | файл открыт в редакторе |
| `file/saved` | `path` | редактор записал свой файл |
| `file/closed` | `path` | закрыт редактор текущего проекта |
| `editor/focused` | `path` | активной панелью стал редактор другого файла |
| `editor/changed` | `path`, `version` | буфер изменился, когда набор текста затих на 300 мс |
| `git/changed` | `root` | сдвинулись индекс, HEAD или ссылки репозитория: коммит, переключение ветки, индексация |
| `agent/started`, `agent/finished` | `panel`, а по окончании и `ok` | ход агента в панели начался или закончился |

`file/will_save` — запрос, а не событие: подписанного на него плагина
спрашивают `{ "path", "version" }`, когда в редакторе его проекта нажат
`Ctrl+S`, до записи файла, и он может ответить `{ "edits": [...] }` (как в
`editor/edit`) или `null` — форматирование при сохранении. termide спрашивает
такие плагины по очереди, по три секунды на каждый, применяет правки к
буферу, если он за это время не изменился, и записывает файл. Сохранение при
закрытии и «Сохранить как» не спрашивают.

За событиями редакторов termide следит, только пока их запросил плагин
текущего проекта.

Результат `initialize` и параметры уведомления `contributions/changed`,
которым плагин позже заменяет его:

```json
{
  "subscriptions": ["file/saved"],
  "commands": [{ "id": "check", "title": "Проверить проект", "key": "Ctrl+Alt+K" }],
  "tools": [{
    "name": "lookup",
    "description": "Найти слово в глоссарии проекта",
    "inputSchema": { "type": "object", "properties": { "word": { "type": "string" } } },
    "readOnly": true
  }]
}
```

Команды появляются как `<плагин>: <название>` в палитре команд (категория
«Плагины») и в конце меню «Команды». `key` команды запускает её откуда
угодно, если termide нигде не назначает эту клавишу — включая собственные
команды пользователя — и это `Ctrl` или `Alt` с ещё одним модификатором
(`Ctrl+Alt+K`, `Ctrl+Shift+K`, `Alt+Shift+K`) или F-клавиша с модификатором
(`Shift+F7`): такие клавиши редко нужны программе в терминале. Неподходящая
клавиша остаётся не назначенной, а в журнал пишется строка об этом.

Инструменты предлагаются сессиям агента в проекте плагина под именем
`plugin-<плагин>__<инструмент>`. Правила разрешений агента относятся к ним как
к инструментам MCP: перед запуском спрашивают, если инструмент не `readOnly`.
Пока инструмент работает, плагин может присылать `tool/progress`
`{ "token", "text" }` с токеном `progress` из вызова: весь вывод на данный
момент, который показывается в транскрипте по мере поступления. За вызовом,
который остановил пользователь или который превысил десять минут, следует
`$/cancelRequest`, как и за командой, превысившей пять.

**плагин → termide**

| Метод | Вид | Параметры |
|---|---|---|
| `contributions/changed` | уведомление | как результат `initialize` |
| `window/notify` | запрос | `message`, `level` (`"info"` или `"error"`) |
| `status/set` | запрос | `id`, `text` (пустой текст убирает элемент) |

Плагин проекта, отложенного в фон, на экран не выводится: его уведомления
попадают в журнал. За одно обновление экрана termide принимает от всех
плагинов не больше 256 сообщений; остальные ждут следующего.

### Дополнение, подсказки и исправления

Плагин может отвечать в редакторе так же, как языковой сервер, — рядом с
серверами или для языка, у которого сервера нет. Языки, по LSP id (`rust`,
`python`, … — `*` для всех), он называет в `providers` среди своих добавлений:

```json
"providers": { "completion": ["python"], "hover": ["*"], "codeActions": ["python"],
               "definition": ["python"], "references": ["python"] }
```

| Запрос | Параметры | Ответ |
|---|---|---|
| `editor/completion` | `path`, `line`, `col` | `{ "items": [...] }`, `CompletionItem` из LSP (`label`, `insertText`, `detail`, `kind`, …) |
| `editor/hover` | `path`, `line`, `col` | `{ "markdown" }` |
| `editor/code_actions` | `path`, `line`, `col`, `end_line`, `end_col`, `diagnostics` (`line`, `col`, `end_line`, `end_col`, `message`, `source`) | `{ "actions": [{ "title", "edits" }] }`, правки как в `editor/edit` |
| `editor/definition`, `editor/references` | `path`, `line`, `col` | `{ "locations": [{ "path", "line", "col", "end_line"?, "end_col"? }] }`, пути абсолютные |

termide спрашивает плагины проекта файла вместе с сервером и показывает один
ответ: пункты дополнения вместе, подсказки одну под другой, исправления одним
списком, места для перехода (`F12`) и ссылки вместе. У плагина есть
1,5 секунды; ответивший позже в этот ответ не
попадает. Исправление меняет только файл, о котором спрашивали, в его
открытом буфере, а его название начинается с имени плагина, чтобы было видно,
кто его предлагает. От плагина берётся не больше 500 пунктов, 50 исправлений и
20 000 символов подсказки.

### Редактор

Плагин имеет доступ к редакторам своего проекта, и только к ним:

| Метод | Параметры | Результат |
|---|---|---|
| `editor/active` | | `path`, `line`, `col`, `selection` (`{ line, col, end_line, end_col }` или `null`), `modified`, `version` активного редактора; `null`, если его нет или проект плагина в фоне |
| `editor/read` | `path` | `text`, `version`, `modified` открытого буфера, включая несохранённые изменения |
| `editor/edit` | `path`, `edits`: `[{ "line", "col"?, "end_line"?, "end_col"?, "text" }]`, `version` (необязательно) | `{ "version" }` |
| `editor/open` | `path`, `line`, `col` (необязательно) | `null`; открывает файл в текущем проекте |

Позиции считаются как в LSP: строки с 0, колонки в единицах UTF-16; правка
без конца — вставка. `editor/edit` меняет только открытый буфер — termide не
пишет файлы за плагин, который может записать их сам, — и правки составляют
один шаг отмены, так что `Ctrl+Z` их откатывает. С `version` правка
отклоняется как `stale`, если буфер изменился после этой версии (какой её
сообщили `editor/read` или `editor/changed`), чтобы плагин, вычисливший правки
по тексту, не применил их к другому. Буфер редактора, который только
просматривает свой файл, тоже отклоняется. `editor/read` отдаёт не больше
16 МБ, `editor/edit` принимает не больше 10 000 правок за раз.

### Терминалы

`terminal/run` `{ "command", "cwd" }` открывает панель терминала в проекте
плагина, который должен быть текущим, и набирает в ней `command`, чтобы
пользователь видел, что запускается; `cwd` (абсолютный) по умолчанию — корень
проекта. Команда — одна строка без управляющих символов; если терминал не
открылся, возвращается ошибка.

### Пометки в редакторе

Плагин помечает строки файлов так же, как языковой сервер, запросом
`editor/diagnostics` `{ "path", "items" }`: пометки видны на полях редактора и
под текстом, их сообщения — строками ниже, а также в панели диагностик, рядом
с пометками языковых серверов и с именем плагина. Каждый вызов заменяет
пометки плагина на этом файле; пустой `items` их снимает. `path` — абсолютный.

```json
{ "path": "/home/me/proj/src/main.rs", "items": [
  { "line": 11, "message": "забытый TODO", "severity": "info" },
  { "line": 40, "col": 8, "end_col": 15, "severity": "error",
    "message": "небезопасный вызов", "code": "S101" }
] }
```

Строки считаются с 0, колонки — как в LSP (единицы UTF-16). Без `col`
помечается вся строка, с одним `col` — слово в этом месте. `severity` —
`error`, `warning` (по умолчанию), `info` или `hint`. Файл, открытый позже,
показывает уже поставленные пометки; пометки плагина снимаются, когда он
останавливается.

### Окна

Плагин может спросить пользователя в одном из окон самого termide. Ответ на
запрос приходит, когда пользователь закрывает окно: с ответом или `null`,
если окно закрыли (`Esc`).

| Метод | Параметры | Ответ |
|---|---|---|
| `window/confirm` | `title`, `message` | `true`, `false` или `null` |
| `window/choose` | `title`, `items` (строки) | индекс выбранного или `null` |
| `window/input` | `title`, `prompt`, `default` (необязательно) | текст или `null` |
| `window/form` | `title`, `fields`: `[{ "name", "label", "type", "options"?, "default"? }]`, `type` — `text`, `number`, `bool` или `select` | `{ name: value }` (переключатели — логические значения, числа — числами) или `null` |
| `window/message` | `title`, `message` | `null` |

Каждое окно termide озаглавливает `🧩 <плагин> · <title>`, чтобы его нельзя
было принять за вопрос самого termide; текст плагина очищается от
управляющих и невидимых символов. Скрытого ввода нет: окно с запросом пароля —
это то, что показал бы фишинговый плагин, поэтому секрету место в `settings`
плагина или в его окружении. Окно ждёт за любым другим окном на экране и
показывается, только пока проект плагина текущий; у плагина одно окно за раз,
а просьба о следующем в это время отклоняется как busy. Когда плагин
останавливается или его проект закрывается, его окна снимаются.

### Панели

Плагин может открывать собственные панели, нарисованные по присланному им
Markdown: заголовки, списки, таблицы, код и ссылки — как в просмотрщике
Markdown, с курсором, выделением, поиском и копированием. Ссылка на
`plugin:<действие>` — это кнопка: переход по ней (`Enter` на ссылке или щелчок)
отправляет действие обратно плагину, а тот отвечает обновлением панели.

| Метод | Вид | Направление | Параметры / результат |
|---|---|---|---|
| `panel/open` | запрос | плагин → termide | `title`, `markdown`, `menu` (необязательно); результат — `{ "panel" }`, её id |
| `panel/update` | запрос | плагин → termide | `panel`, `markdown`, `title` и `menu` (необязательно) |
| `panel/close` | запрос | плагин → termide | `panel` |
| `panel/action` | уведомление | termide → плагин | `panel`, `action` |
| `panel/closed` | уведомление | termide → плагин | `panel`: пользователь её закрыл |

`menu` — собственные пункты меню `[≡]` панели, `[{ "label", "action" }]` (не
больше 12): выбранный пункт отправляется как `panel/action`, так же как
ссылка `plugin:`. То, по чему видно, кто нарисовал панель, задаёт termide: её
значок всегда 🧩, а заголовок всегда начинается с имени плагина (`deploy:
Отчёт`); заголовок и подписи плагина очищаются от управляющих и невидимых
символов и обрезаются по длине.

Панель открывается в проекте плагина, и он должен быть текущим; в раскладке
она не сохраняется. Обновление оставляет читателя на месте, насколько хватает
нового содержимого. Когда плагин останавливается, его панели остаются и
сообщают об этом; запущенный заново плагин их не получает.

```python
# в цикле примера ниже
elif method == "command/execute":            # команда «Показать отчёт»
    send({"jsonrpc": "2.0", "id": id, "result": None})
    send({"jsonrpc": "2.0", "id": "open", "method": "panel/open",
          "params": {"title": "Отчёт", "markdown": "# Отчёт\n\n[Обновить](plugin:refresh)"}})
elif msg.get("id") == "open":                # ответ на panel/open
    panel = msg["result"]["panel"]
elif method == "panel/action" and msg["params"]["action"] == "refresh":
    send({"jsonrpc": "2.0", "id": "upd", "method": "panel/update",
          "params": {"panel": panel, "markdown": "# Отчёт\n\nОбновлено.\n\n[Обновить](plugin:refresh)"}})
```

### Пример

Плагин на Python, который считает сохранения в строке состояния:

```python
#!/usr/bin/env python3
import json, sys

def send(message):
    print(json.dumps(message), flush=True)

saves = 0
for line in sys.stdin:
    msg = json.loads(line)
    method, id = msg.get("method"), msg.get("id")
    if method == "initialize":
        send({"jsonrpc": "2.0", "id": id, "result": {
            "subscriptions": ["file/saved"],
            "commands": [{"id": "reset", "title": "Сбросить счётчик"}]}})
    elif method == "file/saved":
        saves += 1
        send({"jsonrpc": "2.0", "id": f"s{saves}", "method": "status/set",
              "params": {"id": "saves", "text": f"сохранено {saves}×"}})
    elif method == "command/execute":
        saves = 0
        send({"jsonrpc": "2.0", "id": id, "result": None})
        send({"jsonrpc": "2.0", "id": "r", "method": "status/set",
              "params": {"id": "saves", "text": ""}})
    elif method == "shutdown":
        send({"jsonrpc": "2.0", "id": id, "result": None})
    elif method == "exit":
        break
```

Сохраните его как `plugins/save-count/run.py`, сделайте исполняемым и добавьте
`plugins/save-count/plugin.toml` со строкой `command = "./run.py"`.
