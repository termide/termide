# Общее устройство окна приложения

**Приложение занимает всё доступное место и имеет вертикальное разделение на элементы:**
- Строка меню
- Область панелей инструментов
- Статусная строка

Также приложение использует всплывающие окна:
- Помощь
- Настройки
- Подтверждение закрытия приложения

## Модальные окна

Приложение использует интерактивные модальные окна для различных операций:
- **Встроенные строки поиска / замены** (`Ctrl+F` / `Ctrl+H`) - Докнутые поиск и замена прямо в редакторе, файловом менеджере и терминале: живой предпросмотр, счётчик совпадений, тумблеры `[Aa]` / `[.*]` и кнопки навигации
- **Модалы ввода** - Различные запросы для файловых операций (создание, переименование и т.д.)
- **Диалоги подтверждения** - Подтверждение удаления, несохранённых изменений и т.д.

**Возможности модалов:**
- Кнопка `[X]` для закрытия в заголовке модала (нажимается мышью)
- Навигация с клавиатуры через Tab/Shift+Tab (между полями / кнопками модала)
- Поддержка мыши для всех кнопок
- Клавиша Escape для закрытия модала; клик мимо списка выбора, чек-листа, поля ввода, подтверждения или информационного окна закрывает его так же
- Живой предпросмотр для операций поиска/замены
- Сохранение состояния (последний введённый текст сохраняется)

### Окно помощи

`F1` или `Alt+H` (меню **Options → Help**) открывает поверх панелей окно со всеми клавишами termide в том виде, как они заданы в конфиге. Оно открывается на разделе панели в фокусе — из панели git status на её клавишах, — а общие клавиши остаются выше.

- Набранный текст фильтрует список: остаются строки, в клавишах или описании которых он есть, и целые разделы, в названии которых он есть; `Backspace` и `Ctrl+U` стирают его.
- `Tab` / `Shift+Tab` переходят к следующему или предыдущему разделу; стрелки, `PgUp` / `PgDn`, `Home` / `End` и колесо мыши прокручивают.
- `F1`, `Alt+H`, `Esc` или щелчок вне окна закрывают его.

### Модал настроек (Settings)

Открывается клавишей `Alt+P` или через меню **Опции → Настройки**. В отличие от прежнего горизонтально-табового варианта, теперь используется **sidebar-layout**:

**Три зоны:**
- **Левый sidebar** (ширина 18 символов) — список секций с навигацией Up/Down
- **Область контента** — поля выбранной секции, сгруппированные подзаголовками `── Группа ──` и разделённые пустыми строками
- **Кнопки снизу** — `Хранить: глобально / в проекте`, `Сбросить`, `Закрыть`

**Сохранение.** Каждое изменение применяется и сохраняется сразу: переключатель и выпадающий список — при выборе, текстовое и числовое поле — по `Enter`. Кнопки «Применить» нет, отменять нечего. Числовое поле, оставленное пустым или с не-числом, сохраняет прежнее значение. Некоторые настройки агента доходят только до панелей агента, открытых после изменения (см. [Настройка модели](agent.md#настройка-модели)).

**Где хранятся настройки.** Первая кнопка переключает место хранения:
- **Глобально** — `~/.config/termide/config.toml`, общий для всех проектов.
- **В проекте** — `<проект>/.termide/config.toml`, только то, что отличается от глобальных настроек. При переключении файл создаётся, сами настройки не меняются.
- При переключении обратно на глобальное хранение файл проекта удаляется, а termide спрашивает, что сделать с его настройками: **Отбросить** (действуют глобальные) или **Перенести в глобальные** (они станут глобальными для всех проектов).

**Сбросить** сначала спрашивает и действует там, где хранятся настройки: проект возвращается к глобальным настройкам, глобальные — к умолчаниям.

Тема, язык и шелл, выбранные из меню, сохраняются в глобальных настройках;
собственные тема или язык проекта при этом убираются. Чтобы задать их
отдельно для проекта, выберите их здесь со `Stored: Project`.

**Что задаётся только глобально.** Файл проекта приходит с репозиторием,
поэтому в нём нельзя назвать программу, которую запускает termide, файл, в
который он пишет, или адрес, куда уходит ключ, и нельзя ослабить агента: шелл
терминала по умолчанию, файл журнала, браузер веб-инструментов, команду и
аргументы LSP-сервера и отладчика, базовый URL и переменную с ключом API
подключения и режим разрешений агента. При хранении в проекте эти поля
показывают значение с пометкой «задаётся в глобальных настройках» и не
меняются; в файле проекта они игнорируются, с записью в журнале.

**Секции в sidebar:**
- General, Editor, File Manager, Terminal, LSP, Debug, Logging, VFS, AI, Plugins — обычные листья
- **Keybindings** — раскрываемая группа (▶/▼), последняя в списке, с 9 подсекциями (Global, Editor, FileManager, GitStatus, GitDiff, GitLog, Terminal, Database, Viewer)

**Раскладка и иконки** (секция General, `[general]` в `config.toml`):
- **Режим иконок** (`icon_mode`) — иконки в заголовках панелей: `auto` (по умолчанию) показывает эмодзи, если терминал их рисует, `emoji` — всегда, `unicode` — никогда
- **Порог автостека** (`auto_stack_threshold`, по умолчанию `80`) — новая панель встаёт под активной, а не в новую колонку, если колонка вышла бы уже этого числа символов
- **Мин. ширина панели** (`min_panel_width`, по умолчанию `20`) — изменение размера панели останавливается на этой ширине

**Навигация:**

| Комбинация | Действие |
|-----------|----------|
| `Up` / `Down` | Перемещение внутри текущей зоны (секции / поля / кнопки) |
| `Tab` / `Shift+Tab` | Переключение между зонами (Sidebar ↔ Content ↔ Buttons) |
| `Left` / `Right` | **Не** меняют зону: используются для изменения значений (cycle enum, toggle bool) и для свёртки группы Keybindings в sidebar |
| `Enter` / `Space` | Активировать: в sidebar — войти в секцию, в content — переключить bool/enum или начать редактирование текста/числа, на header группы — toggle expand |
| `Escape` / `Ctrl+S` | Закрыть модал (всё уже сохранено); в ряду кнопок Escape сначала снимает открытый вопрос |
| Колесо мыши | Прокрутка sidebar / content |

**Поля и индикаторы:**
- **Bool** — `[✓]` (включено) или `[ ]` (выключено), переключаются `Enter`/`Space` или `Left`/`Right`
- **Enum** — `< значение >`, циклятся `Left`/`Right`
- **Number** / **OptionalText** — `Enter` входит в режим inline-редактирования
- **LSP → Servers** — список серверов помечен буллетом `•`; есть строка `+ Add Server`

**Keybindings — редактирование бинда:**  
Навигация по списку — `Up/Down`. В каждой строке перечислены все клавиши действия — `Alt+W, Alt+X, F10` — и курсор стоит на одной из них:

| Клавиша | Действие |
|----------|--------|
| `Left` / `Right` | Переместить курсор по клавишам строки; за последней клавишей он встаёт на кнопку `[+]` |
| `Enter` | Захватить нажатие для слота под курсором — заменить эту клавишу, а на `[+]` — добавить новую альтернативу |
| `Delete` | Убрать клавишу под курсором |
| `Shift+Delete` / `Backspace` | Очистить все клавиши действия |
| `Escape` | Выйти из списка, либо отменить начатый захват |

На фокусной строке в конце нарисована кнопка `[+]`: клик по ней или `Enter` на ней начинают захват, и клавиша дописывается в конец. Клик по клавише выбирает её, так что следующий `Enter` или `Delete` действует на то, по чему кликнули; двойной клик по клавише начинает захват. Комбинацию, которая у этого действия уже есть, панель не принимает и показывает почему; комбинацию, занятую другим действием, записывает с предупреждением, где именно она занята. Во время захвата строка продолжает показывать свои клавиши, а та, что будет заменена, помечена предупреждающим цветом.

Подсветка активной секции в sidebar убирается при потере фокуса — текущая секция видна по заголовку в области контента, поэтому двойная подсветка не вводит в заблуждение.

## Строка меню

Строка меню располагается вверху окна и включает: пункты меню расположенные слева, кнопки открытых проектов после них, индикаторы системных ресурсов (скорость сети, CPU, RAM и — если есть батарея — её заряд) и часы в формате ЧЧ:ММ расположенные справа.
Активация и деактивация меню, а также каждого пункта может производиться кликом мыши либо [клавиатурной комбинацией](#клавиатурная-навигация-и-управление-по-меню-и-панелям).
Выпадающий список открывается без выбранного пункта — у пункта меню, кнопки проекта, `[≡]` панели (`Alt+K`), операции и кнопки stash: `←`/`→` идут дальше по строке меню, `↓` выбирает первый пункт, `↑` последний, а `Enter` срабатывает, только когда пункт выбран. Подменю, открытое из пункта с `▶`, начинается с первого пункта.

**Пункты меню:**
- `Закладки` — закладки (директории, файлы, SSH, SFTP, веб-ссылки). Открытие маршрутизируется по типу: директории и удалённые пути — в файловом менеджере, файлы HTML/Markdown/Mermaid/CSV/изображения и `http(s)`-ссылки — во встроенном просмотрщике (см. [просмотр HTML](html.md); `O` там передаёт страницу браузеру), прочие текстовые файлы — в редакторе, SSH — в терминале, базы данных — в DB-просмотрщике. Клик по заголовку группы разворачивает и сворачивает её подменю, как в «Командах».
- `Команды` — пользовательские команды, сначала проектные (жирным), с группами подменю; `Добавить команду...` вверху создаёт новую. Клик по заголовку группы разворачивает подменю; повторный клик на том же заголовке — сворачивает (toggle). См. [Пользовательские команды](actions.md).
- `Окна` — создание панелей:
  - Открыть… — открыть файл, каталог или URL через строку ввода с подсказками (`Ctrl+G`)
  - Терминал — терминал (имеет подменю выбора оболочки: показывает все доступные в системе оболочки, текущая оболочка по умолчанию отмечена ●)
  - Файлы — файловый менеджер
  - Редактор — текстовый редактор
  - Git статус — панель статуса git
  - Git история — история коммитов
  - Журнал — журнал приложения; плашки `TRACE`…`ERROR` в его заголовке или клавиши `1`…`5` показывают и скрывают каждый уровень
  - Диагностика — диагностика LSP
  - [Операции](operations.md) — фоновые операции
  - Структура — структурная навигация по коду
  - [Агент](agent.md) — панель агента
- `Опции` — настройки:
  - Темы — выбор темы с предпросмотром
  - Язык — язык интерфейса с предпросмотром
  - Настройки — открыть окно настроек
  - Помощь — окно помощи
  - Отсоединить экземпляр — оставить экземпляр работать в фоне (показывается, только когда отсоединение возможно; см. [Отсоединяемые экземпляры](detached-instances.md))
  - Выход — закрыть приложение
- `AI` — агенты, сессии, скиллы и промпты агента, а также переключатель окна браузера агентов; см. [Меню AI](agent.md#меню-ai)
- `Проекты` — управление проектами:
  - Новый проект — начать проект в другой директории

    Директория выбирается в дереве, как и для `F6` на проекте, директории которого больше нет (см. ниже): `→`/`←` раскрывают и сворачивают ветку, `Enter` входит в директорию, `Backspace` поднимается к родительской, `.` показывает или скрывает скрытые директории, `Ctrl+Enter` подтверждает выбор из любого места

    Там же работают клавиши файлового менеджера для директорий: `create_dir` (`F7`/`D` или кнопка `Новая папка`) открывает строку для имени рядом с элементом под курсором — на его уровне, а не внутри, даже если он раскрыт; `rename` (`F2`/`R`) правит имя прямо в строке; `delete` (`F8`/`Delete`) удаляет только пустую директорию. `Enter` применяет имя, `Esc` отменяет; если имя не подходит, строка остаётся открытой, а причина показывается над деревом
  - Открыть проекты прошлого запуска (N) — появляется, если в прошлом запуске было открыто больше одного проекта, и пропадает, когда вы им воспользуетесь или сами откроете другой проект. Открывает эти проекты в фоне, оставляя вас в текущем; раскладка каждого загружается при первом переключении на него — а проект, где агент оставил незавершённую работу (оборванный или приостановленный прогон, `/goal` или `/loop`, запрос, ждущий повтора), загружается сразу, чтобы его карточка позвонила и отметила проект 🔔, — в терминалах запускаются новые оболочки. Список сохраняется при каждом изменении набора открытых проектов, поэтому переживает аварийное завершение; запуск, в котором так и не открыли второй проект, его не трогает. Если запущено несколько экземпляров, побеждает тот, что последним изменил свой набор. Проект, открытый в другом экземпляре, остаётся ему и заново не открывается. Каждый запуск делает это сам (`restore_projects`, включено по умолчанию; **Открывать проекты прошлого запуска** в Настройки → Общие): каталог, в котором вы запустились, становится текущим проектом — и добавляется в набор, если его там не было, — а проекты прошлого запуска открываются вокруг него в фоне; незаконченная работа агента в них ждёт, пока вы не войдёте в его проект. `--no-restore` пропускает это для одного запуска. `termide --restore` (`-r`) восстанавливает и при выключенной настройке, как пункт меню, и открывается в том проекте, в котором был прошлый запуск; запущенный из каталога этого набора, он остаётся в нём, поэтому запуск из другого каталога не добавляет его в набор. Без сохранённого набора оба варианта запускаются как обычно; запуск с путём (`termide <файл>` в роли `$EDITOR` или `termide <каталог>`) ничего не восстанавливает
  - Под разделителем — все проекты, с которыми вы работали. Сначала открытые в этом экземпляре, в том порядке, в каком вы их держите: новый встаёт в конец, а клавиши перемещения панели между группами двигают выбранный — `Alt+PgUp`/`Alt+PgDn` на одно место вверх или вниз, `Alt+Home`/`Alt+End` в начало или в конец; мышью проект перетаскивается через остальные, а `Esc` во время перетаскивания возвращает его на место; по этому порядку их нумеруют `goto_project_N`, и он восстанавливается вместе с ними. Затем, под ещё одним разделителем, остальные, недавно использованные выше; длинный список прокручивается. Строка выглядит так же, как в окне переключения: отметка, время последней работы с неоткрытым проектом (блёклым цветом), путь — если он не помещается, обрезается его начало — и 🔔. ● отмечает текущий проект, ○ — открытый в фоне, ✗ — проект, каталога которого больше нет (перемещён или удалён вне Termide), 🔔 — проект, панель которого ждёт вас (вопрос или законченная работа агента, звонок в терминале); пока такой есть, а его кнопки нет в строке меню, 🔔 стоит и перед заголовком `Проекты`. При переключении в проект с 🔔 фокус переходит на ждущую панель. Без emoji-иконок вместо 🔔 здесь и в заголовках панелей стоит `!`. `Enter` или щелчок переключает. `Delete`/`F8` закрывает проект, открытый в фоне, и останавливает запущенные в нём программы, а неоткрытый удаляет: всё, что Termide хранит о нём, — сохранённую раскладку, несохранённые буферы, логи и выданные ему разрешения, — и он пропадает из списка (файлы проекта не трогаются); если у проекта есть сессии агента, вопрос предлагает удалить и их или оставить. Оба действия спрашивают подтверждение; проект, открытый в другом экземпляре, не удаляется. На текущем проекте — переключает в проект, из которого вы ушли последним, и закрывает текущий, спрашивая подтверждение, только если в нём запущены программы или есть несохранённые изменения; если других открытых проектов нет, текущий не трогается
  - При переключении на другой проект тот, в котором вы были, остаётся открытым в фоне: программы в его терминалах продолжают работать, агенты — тоже, несохранённые правки остаются как были. Проект открыт, пока вы его не закроете или пока Termide не завершится. «Новый проект» в уже открытой директории переключает на неё. При выходе Termide называет фоновые проекты, в которых ещё что-то работает. `Alt+1`…`Alt+9` переключают на открытый проект с этим номером, в том порядке, в каком их перечисляет меню `Проекты`; `prev_project` и `next_project` перебирают их по очереди и по умолчанию не назначены, см. [Действия без привязки](keybindings.md#действия-без-привязки)
  - Проект открыт только в одном Termide одновременно, чтобы два экземпляра не перезаписывали друг другу его раскладку и не запускали дважды его языковые серверы и агентов. Переключиться на директорию, которую держит другой экземпляр, создать на ней проект или перенести туда проект нельзя, а строка состояния называет этот экземпляр: его pid или отсоединённый экземпляр, к которому можно подключиться. Запуск `termide` в такой директории завершается ещё до интерфейса с тем же сообщением — а если проект держит [отсоединённый экземпляр](detached-instances.md) и у запуска есть терминал, подключается к этому экземпляру. Проект, открытый заново из прошлого запуска, занимается только при первой загрузке, поэтому другой экземпляр может открыть его раньше; тогда он рисуется перечёркнутым в строке меню и списках проектов, вход в него отклоняется тем же сообщением, а сам он остаётся в списке. Проект освобождается, когда его закрывают или когда его Termide завершается, как бы он ни завершился. Запуски в роли `$EDITOR` (`termide <файл>`), `--prompt` и `--recall` проект не занимают и никогда не отклоняются
  - `Alt+\` открывает окно переключения проектов. В нём проекты перечислены так же, как в этом меню, по одной строке — отметка, когда в последний раз работали с неоткрытым проектом (блёклым цветом), путь и 🔔, — а строка под курсором инвертирована. Ввод фильтрует список по пути. Курсор сразу стоит на проекте, из которого вы ушли последним: `Alt+\`, затем `Enter` возвращает в него. `Delete`/`F8` работают так же, как в меню, как и клавиши перемещения открытого проекта, пока фильтр пуст
  - `F6` на строке проекта переносит проект, а `F5` копирует его — директорию со всеми файлами и вместе с ней то, что Termide хранит о проекте в других местах: сохранённую раскладку с несохранёнными буферами, сессии агентов с их контрольными точками, точки останова и, при переносе, выданные проекту разрешения. Запрос — тот же, что при копировании и перемещении в файловом менеджере, с путём проекта для правки; цели ещё не должно существовать. Файлы переносит фоновая [операция](operations.md) со своим прогрессом и кнопкой отмены. Открытый здесь проект на время переноса закрывается — с вопросом, если в нём работают программы или есть несохранённые изменения, — и снова открывается по новому пути на своём месте в списке; текущий остаётся текущим и, пока переносится, показывает только панель операций. После переноса восстанавливаются ссылки репозитория на его git worktree. Копия — отдельный проект: она открывается в фоне после оригинала, её сессии агентов получают новые идентификаторы, а разрешения оригинала на неё не переносятся. Перенос отклоняется, пока внутри директории лежит другой открытый проект или цель открыта в другом экземпляре. Если операция не удалась или отменена, проект снова открывается на старом месте, а то, что успело попасть в цель, там и остаётся
  - На проекте с отметкой ✗, директорию которого перенесли вне Termide, `F6` и `Enter` — здесь и в окне переключения проектов — вместо этого спрашивают, где он теперь, и директория выбирается в дереве. То, что Termide хранит о проекте, переходит туда так же, как при переносе: сохранённая раскладка со своими путями, несохранённые буферы, сессии агентов с контрольными точками, точки останова и разрешения, а ссылки репозитория на его git worktree восстанавливаются; сами файлы не перемещаются. Директория, у которой уже есть свой проект, отклоняется: сначала удалите его или выберите другую

**Кнопки проектов:** у каждого открытого проекта, даже единственного, есть кнопка `имя` между пунктами меню и индикаторами: имя каталога проекта, с родительским каталогом, если у двух открытых проектов имена совпадают, а у ждущего перед именем 🔔. Кнопка текущего проекта цвета пунктов меню, остальные блёклые. Они идут в порядке меню `Проекты`, разделённые блёклым `" | "` — ни перед первой, ни после последней разделителя нет, — и начинаются через два пробела после `Проекты`, последнего пункта меню, так что блок проектов читается отдельно. Если они не помещаются, имена теряют начало — короткое имя сохраняет свою ширину, а длинные поровну делят остаток; если не помещаются и обрезанные, кнопки пропадают — последней выбранная или перетаскиваемая, перед ней текущий и ждущие проекты, — а `+N` показывает число скрытых. Кнопка открывает меню своего проекта, как пункт меню — свой список: **Перейти в проект** у другого проекта, **Перенести проект…** (`F6`), **Копировать проект…** (`F5`) и **Закрыть** (`F8`, `Delete`), у текущего — только пока открыт другой проект; закрытие проекта закрывает и меню. Щелчок переключает в другой проект; щелчок по кнопке текущего проекта открывает его меню, а повторный закрывает; перетаскивание кнопки вдоль строки сдвигает её проект, а `Esc` во время перетаскивания возвращает его на место. В открытом меню `←`/`→` проходят кнопки после пунктов меню и перед индикаторами, открывая меню каждой, а статусная строка показывает полный путь проекта, который кнопка могла обрезать. `Alt+PgUp`/`Alt+PgDn` сдвигают выбранную кнопку на одно место влево или вправо, `Alt+Home`/`Alt+End` — в начало или в конец, как в меню `Проекты`.

**Индикаторы системных ресурсов** (кликабельные индикаторы открывают модальное окно с подробностями):

| Индикатор | Описание | Клик открывает |
|-----------|----------|----------------|
| `↓…/↑…` | Скорость сети (↓ загрузка, ↑ отдача) | Топ-10 процессов по сетевой активности |
| `CPU XX%` | Загрузка процессора | Топ-10 процессов по CPU |
| `RAM X/YГб` | Использование памяти | Топ-10 процессов по RAM |
| `⚡NN%` / `🔋NN%` | Заряд батареи (⚡ — от сети / заряжается / заряжена, 🔋 — от батареи). Скрыт на системах без батареи. | — (только информация) |
| `УСТРОЙСТВО занято/всегоГб` (в статусной строке) | Использование диска | Топ-10 процессов по диску + разделы ФС |

Повторный клик по тому же индикатору закрывает открытое им окно (toggle), то же поведение и у индикатора диска в статусной строке.

Цветовая кодировка (CPU / RAM): зелёный < 50%, жёлтый 50–75%, красный > 75%. Батарея использует ту же шкалу наоборот (зелёный при зарядке или выше 50%, красный ниже 25%). Показания батареи кэшируются на 5 секунд, чтобы покадровая отрисовка не обращалась к `/sys`.

Индикаторы и открытое окно подробностей обновляются раз в `resource_monitor_interval` миллисекунд из `[general]` (по умолчанию `2000`; в настройках **Общие → Интервал монитора ресурсов (мс)**).

**Модал сетевой активности** показывает:
- **Application** — имя процесса
- **Ports** — слушающие TCP-порты (например, `80, 443`)
- **Conn** — количество активных (ESTABLISHED) соединений

Процессы отсортированы по убыванию числа соединений.

## Область панелей инструментов

Область заполняет вертикальное пространство между строкой меню и статусной строкой от левого до правого края окна.
Раскладка адаптируется к ширине терминала, показывая больше групп панелей на широких экранах. Панели (терминал, редактор, git) могут быть открыты и будут размещены рядом.

Новая панель всегда открывается **после текущей активной** в аккордеоне группы (не в конце списка). При закрытии панели фокус переходит на предыдущую.

**Возможные варианты открываемых панелей:**
- [файловый менеджер](file-manager.md) — `Alt+F`
- [терминал](terminal.md) — `Alt+T`
- [текстовый редактор](editor.md) — `Alt+E`
- статус git — `Alt+G`; вне git-репозитория — панель статуса плагина системы контроля версий, если он её предлагает (открытые файлы Perforce)
- структура (outline) — `Alt+O`
- диагностика — `Alt+I`
- git лог — `Alt+C`
- git diff
- [агент-программист](agent.md) — `Alt+A`
- [операции](operations.md)
- просмотр изображений
- журнал — `Alt+L`

Панель **git статус** сверху показывает два селектора: репозиторий и ветку.
В списке веток — локальные ветки и удалённые без локального двойника; `●`
отмечает ветку, выгруженную в основную копию репозитория, `⧉` — выгруженную в
связанный worktree (каталоги worktree не попадают в список репозиториев
отдельными записями). Список репозиториев — это дерево проекта: каталоги
показываются тусклыми строками, называющими, где лежат репозитории под ними,
дерево рисуется линиями, как дерево файлов; каталог с тем же именем, что и
репозиторий в нём (`github.com/owner/owner`), своей строки не получает. Каталог
сворачивается, как папка в дереве файлов: перед именем `▼`/`▶`, `Enter` или клик
переключают его, `←`/`→` сворачивают и раскрывают; выбрать каталог нельзя, а
свёрнутые каталоги помнятся, пока живёт панель. При открытии списка раскрываются
каталоги над текущим репозиторием. Список прокручивается, только когда курсор
выходит за видимые строки. Проект —
папка выгрузок поэтому читается как `<host>/<group>/<repo>`, а не чередование
повторяющихся имён; закрытый селектор показывает тот же путь. Фильтр сравнивает
именно этот путь, поэтому хост или группа находят репозитории внутри неё.
Панель, восстановленная из раскладки, открывается на том репозитории, с которым
была сохранена, но список её по-прежнему держит остальной проект: путь сохранён
один, а плоскость вокруг него находится заново.
Выбор ветки никогда её не выгружает — он лишь меняет то, что показывает панель:

- ветка, выгруженная в основную копию или в worktree, показывает изменения
  этой рабочей копии, и индексация, коммит, diff, push и pull выполняются в ней;
- ветка, не выгруженная никуда, показывает, на сколько коммитов она впереди и
  позади ветки основной копии, и кнопку `[Переключиться]`, которая выгружает её в
  основную копию. Если git отказывает (например, мешают незакоммиченные
  изменения), его сообщение показывается как ошибка.

`[Лог]` открывает git лог на том же репозитории и ветке. Селектор веток в логе
помечает ветки так же и лишь выбирает, чью историю показать; после checkout лог,
следящий за HEAD, переходит на новую ветку.

На изменённом файле `S` индексирует его (и каталог тоже), `U` убирает из
индекса, `F3` открывает его для просмотра, `F4` — в редакторе, `Пробел` или
`F12` показывает его свойства, а `Backspace` или `Delete` отменяет его
изменения, спросив. `Ctrl+R` обновляет статус и забирает изменения с удалённого
репозитория. Это `stage`, `unstage`, `view`, `edit`, `info`, `revert` и
`refresh` в `[git_status.keybindings]`.

Панель **git лог** рисует граф коммитов псевдографикой (`● │ ├ ╮ ╯`),
раскладывая его по родителям каждого коммита; каждая дорожка раскрашена своим
цветом, чтобы ветку можно было вести глазом по цвету. Чтобы вернуться к нативному
ASCII-выводу git `--graph`, снимите *Псевдографический граф в журнале git* на
странице «Общие» окна настроек или задайте в `config.toml`; открытый лог
перечитывается в выбранном виде:

```toml
[git_log]
unicode_graph = false
```

Лог читает историю по мере прокрутки: первые коммиты видны сразу, а следующие
дочитываются, пока до конца прочитанного остаётся меньше двух экранов; под
последним в это время стоит строка *Загружаю коммиты…*. `End` дочитывает
историю до конца, какой бы длинной она ни была, и держит выделение на последнем
коммите. Полоса прокрутки с самого начала охватывает всю историю. Когда лог
перечитывается — после коммита, checkout, rebase, — выделенный коммит остаётся
выделенным и на том же месте экрана.

На коммите `Enter` или `D` открывает его diff, а `Space` — сведения о нём;
`Ctrl+R` перечитывает лог. Всё, кроме `Enter`, настраивается как `info`,
`view_diff` и `refresh` в `[git_log.keybindings]`. Переключение на ветку
делается из панели git status.

Панель **git diff** (`[Diff]` в git status) показывает изменения рабочей копии:
сначала неиндексированные, затем индексированные с пометкой `[staged]`, — и
добавляет их в индекс или отбрасывает по фрагменту или по строке. Курсор ходит
по строкам так, как они нарисованы: на заголовке файла он означает весь файл, на
заголовке фрагмента `@@` — фрагмент, на строке — эту строку. `[` и `]`
перескакивают между фрагментами; `V` начинает выделение строк, `Shift+↑↓`
расширяет его в пределах фрагмента, `Esc` снимает.

- `Space` добавляет в индекс то, на чём стоит курсор; на индексированной стороне
  убирает из индекса. Выделенная строка контекста ничего не меняет, и панель
  так и пишет.
- `D` отбрасывает это из рабочей копии, сначала спросив; на индексированной
  стороне вместо этого убирает из индекса. `U` возвращает то, что забрало
  последнее отбрасывание, пока панель открыта: файл перед этим сохраняется в
  хранилище объектов git.
- Неотслеживаемые, переименованные и бинарные файлы берутся целиком.
  Отбрасывание неотслеживаемого файла удаляет его, поэтому спрашивается всегда.

Каждый патч панель вырезает из диффа, который git пишет в этот момент, поэтому
переводы строк CR и отсутствие перевода строки в конце файла сохраняются; если
файл изменился с тех пор, как его нарисовали, действие отклоняется и панель
перечитывается. `Enter` сворачивает файл, `E`/`F4` открывает его. Дифф коммита
или stash только показывает изменения, и `Space` там сворачивает, как `Enter`.
Клавиши — в `[git_diff.keybindings]`: `toggle_stage`, `discard`,
`undo_discard`, `select_lines`, `prev_hunk`, `next_hunk`, `toggle_collapse`,
`edit`, `refresh`, `scroll_half_up` и `scroll_half_down`.

Та же панель служит для ревью изменений агента: `/changes` в панели агента
или **Ревью изменений** в её меню открывает её на том, что агент изменил с
тех пор, как вы последний раз приняли изменения, — и только на этом: ваши
собственные правки между запросами в ревью не попадают. Каждый запрос
снимает состояние рабочей копии в git (деревья под `refs/termide/review/`,
которых не видно ни в одном логе), поэтому учитывается и то, что меняют
shell-команды и внешние агенты. Агент тем временем продолжает работать;
ревью идёт после факта.

- `Space` принимает то, на чём стоит курсор: оно уходит из ревью и остаётся
  в файле. Добавление изменения в индекс или его коммит тоже принимает его.
- `D` отклоняет: изменение откатывается в рабочей копии, а агент узнаёт об
  этом в следующем запросе из короткой заметки, добавленной к вашему
  сообщению. `U` возвращает последнее отклонение, и агенту о нём не
  сообщается.
- `A` принимает всё; `X` отклоняет всё, сначала спросив.
- Файл, который между запросами правили и вы, помечен `правили и вы`:
  отклонение в нём сначала спрашивает, ведь во фрагмент могли попасть ваши
  правки, а `X` оставляет такие файлы как есть.

То, что вы меняете, пока запрос выполняется, считается изменениями агента.
Клавиши — `keep_all` и `reject_all` в `[git_diff.keybindings]`, а также
`toggle_stage`, `discard`, `undo_discard` и `select_lines`.

Открытие **бинарного файла** (по `Enter` или `F3` в файловом менеджере)
показывает read-only **hex-вьюер** — `смещение │ hex │ ASCII`, ширина строки
подстраивается под панель секциями по 16 байт — вместо передачи системному
просмотрщику. Курсор байта виден сразу в hex- и ASCII-зонах (`Tab` переключает
активную); стрелки/`hjkl` двигают его, `Shift`+движение выделяет, `Ctrl+C`
копирует выделение (как hex из hex-зоны, как текст из ASCII-зоны). `Ctrl+F`
открывает поиск по ASCII-подстроке или — с тумблером `[hex]` — по
последовательности байт вида `ff fe`; совпадения подсвечиваются в обеих зонах.

Открытие бинарного файла по `F4` (редактирование) делает его **редактируемым**:
ввод перезаписывает байт под курсором — два hex-нибла в hex-зоне, символ в
ASCII-зоне — без изменения длины файла. Несохранённые правки помечаются `*` в
заголовке; `Ctrl+S` сохраняет после подтверждения, предварительно делая бэкап
оригинала в `<файл>.bak`, а если он уже есть — в первый свободный
`<файл>.bak.N`, так что прежний бэкап никогда не перезаписывается. `Ctrl+E`
(или поле `Edit:`) переключает правку и просмотр; при несохранённых правках
сначала спрашивает, сохранить их (с бэкапом), отбросить или продолжить
правку.

`Ctrl+L` (или чип `[Hex]`/`[Text]` в статус-баре) переключает hex и текст. Для
настоящего текстового файла это подменяет панель на месте read-only редактором
(а `Ctrl+L` в редакторе возвращает в hex); бинарный файл — который редактор не
может открыть как текст — переключается в lossy-текстовый режим внутри панели.
Клавиша настраивается:

```toml
[viewer.keybindings]
toggle_hex = "Ctrl+L"
```

**Особенности закрываемых панелей:**
- Имеют кнопку `[≡]` в заголовке панели (клик открывает контекстное меню с пунктами Закрыть / Отделить / Объединить / Переместить)
- Могут быть закрыты клавишами Alt+W, Alt+X или F10, а Escape — когда панели нечего им отменить у себя (строка поиска, выделение, режим вставки vim); работающий терминал отдаёт Escape своей программе, а панель агента от него не закрывается никогда; на месте последней закрытой открывается файловый менеджер в корне проекта
- Ширина колонки регулируется клавишами `Alt+=` / `Alt+-`
- Высота панели внутри колонки регулируется `Alt+Shift+=` / `Alt+Shift+-` (шаг 1 строка), перетаскиванием нижнего бордюра панели мышью или перетаскиванием заголовка панели вверх/вниз внутри колонки
- `Alt+F11` переключает «полноэкранный пресет» для активной панели (одна панель занимает всю колонку, остальные сжимаются до строки заголовка); повторное нажатие восстанавливает прежние высоты
- Некоторые панели подстраивают высоту под содержимое, а не берут долю колонки — так ведёт себя панель операций — и сохраняют её при полноэкранном пресете (фокус на такой панели не сворачивает развёрнутую панель); ручное изменение высоты такой панели даёт ей обычную фиксированную высоту до закрытия
- Могут перетаскиваться за верхний бордюр (см. раздел «Взаимодействие мышью» ниже)

**Контекстное меню действий панели:**

Клик по кнопке `[≡]` в заголовке панели (или нажатие `Alt+K` / `Shift+F10` на активной панели) открывает выпадающее меню:
- **Переместить вверх / Переместить вниз** — переупорядочить внутри текущей группы (если в группе больше одной панели)
- **Переместить влево / Переместить вправо** — в соседнюю группу (если групп больше одной)
- **Отделить / Объединить** — отделить панель из группы в новую (если в группе больше одной панели) или объединить одиночную панель с соседней группой
- **Закрыть** — закрыть панель (с подтверждением при необходимости)

Пункты фильтруются по контексту: например, *Отделить/Объединить* скрывается, если всего одна панель в одной группе; *Переместить вверх/вниз* — для одиночной панели в группе.

**Взаимодействие мышью:**
- Клик по заголовку активирует панель; двойной клик по заголовку
  файлового менеджера открывает выбор каталога.
- **Перетаскивание бегунка скроллбара** (блок `▌` на правом бордюре
  панели или `━` на нижнем, где нарисован горизонтальный скроллбар) —
  прокрутка панели в эту позицию. Захватывается только бегунок:
  дорожка скроллбара и бордюр без скроллбара по-прежнему меняют
  раскладку, как описано ниже. Перетаскивание бегунка неактивной
  панели прокручивает её на месте, не перемещая фокус, — так же, как
  колесо мыши.
- **Перетаскивание нижнего бордюра панели** в колонке — изменение
  высоты этой панели (живая ghost-линия `━` показывает положение
  нового разделителя, ресайз применяется на отпускании).
- **Перетаскивание панели за верхний бордюр (title)** — режим
  resize или reorder:
  - Отпускание в теле исходной панели или в теле верхнего соседа
    → вертикальный resize: разделитель над панелью прыгает к
    курсору (у верхней панели колонки разделителя выше нет —
    жест переходит в режим переноса).
  - Отпускание на строке-заголовке другой панели в той же группе
    → переупорядочивание: вставить перед / после в зависимости
    от направления.
  - Отпускание над телом панели другой колонки → перенос в эту
    группу с разрезанием целевой панели на строке drop'а.
  - Отпускание в 2-клеточном зазоре между группами → новая группа
    в этом месте.
  - Отпускание правее последней группы → добавление как новой
    последней группы.
  - Во время drag жирная линия `━` отмечает горизонтальные
    drop-зоны (resize / split в колонке), жирная `┃` —
    вертикальные (новая колонка между группами).
  - Нажатие `Escape` отменяет drag.

## Статусная строка

Статусная строка предназначена для отображения дополнительных сведений о работе в активной панели.
В зависимости от типа активной панели в ней отображаются соответствующие данные.
Прогресс фоновых файловых операций и индикатор дискового пространства прижаты
к правому краю; на узком терминале урезается собственный текст панели (с `…` в
конце), а они остаются видны.

### Индикатор дискового пространства

Справа в статусной строке отображается информация о дисковом пространстве в формате: `УСТРОЙСТВО занято/всегоГб (процент%)` с цветовой кодировкой в зависимости от уровня заполненности:

**Цветовая кодировка:**
- **Зелёный** при заполненности диска < 50%
- **Жёлтый** при заполненности диска 50-75%
- **Красный** при заполненности диска > 75%

**Формат:** `УСТРОЙСТВО занято/всего (процент%)`

Пример: `NVME0N1P2 386/467Гб (83%)`

Название устройства определяется автоматически из файловой системы:
- В Linux: показывает имена разделов как `NVME0N1P2`, `SDA1` и т.д.
- В macOS: показывает идентификатор контейнера диска (например, `DISK3`)
- Отображаемое устройство соответствует пулу хранилища, на котором находится текущая директория

В окне дисков каждая строка соответствует одному пулу хранилища, вторым столбцом указывается тип файловой системы. В macOS все тома APFS одного контейнера (`/`, `/System/Volumes/Data`, `Recovery` и т.д.) разделяют одно и то же свободное место, поэтому показываются одной строкой, а не повторяют одинаковые цифры.

### Командная палитра

`Ctrl+P` показывает все команды. Ввод фильтрует их нечётким поиском по
названию команды, её категории и сочетанию клавиш: лучшие совпадения идут
первыми, совпавшие буквы подсвечены. Например, `gitlog` находит *Open Git Log*.
Фильтр понимает синтаксис fzf: слова через пробел должны совпасть все, `'слово`
ищется буквально, `^слово` — в начале, `слово$` — в конце, `!слово` исключает.
Строчные буквы совпадают с буквами любого регистра, заглавная — только с собой.

### Окно открытия

`Ctrl+G` (или **Окна ▸ Открыть…**) запрашивает путь к файлу, каталог, URL базы
данных или адрес `http(s)://` и открывает его в подходящей панели. Клавиша
работает из любой панели, кроме двух: файловый менеджер оставляет `Ctrl+G` за
своим *переходом по пути* (с теми же подсказками), а терминал передаёт её
запущенной в нём программе. Относительный путь берётся от каталога активной
панели.

Под полем ввода список следует за набранным:

- имя (`hpprov`) нечётко сопоставляется с файлами проекта — без того, что
  игнорирует git, и без самого `.git`; лучшие совпадения первыми, синтаксис тот
  же, что у [командной палитры](#командная-палитра);
- путь (`/`, `~/`, `./`, `../`) дополняется из своего каталога, каталоги
  первыми;
- для URL списка нет.

`↑` / `↓` выбирают подсказку, `Tab` подставляет её в поле (для каталога список
затем показывает его содержимое), `Enter` открывает её — или набранный текст,
если список пуст. Щелчок по подсказке открывает её.

### Caps Lock

Termide включает [Kitty keyboard protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/) через `KeyboardEnhancementFlags::DISAMBIGUATE_ESCAPE_CODES | REPORT_ALTERNATE_KEYS | REPORT_EVENT_TYPES`. `REPORT_EVENT_TYPES` пробрасывает `KeyEventState::CAPS_LOCK`, и матчер хоткеев использует этот бит, чтобы игнорировать «фантомный» `Shift`, который X11/Linux-терминалы навешивают на каждый буквенный event при включённом Caps Lock.

Что это даёт на практике:

- Бинты вроде `Alt+T` продолжают работать при включённом Caps Lock (без фикса event пришёл бы как `{Char('T'), Alt|Shift}` и не совпал бы с `{Char('t'), Alt}`).
- Намеренные `Shift+буква`-бинты (например, `Ctrl+Shift+F` для content-поиска) остаются отличимыми от безшифтовых версий — Shift игнорируется только если реально сообщён Caps Lock.
- Терминалы без поддержки Kitty protocol (бит Caps Lock не приходит) падают на строгое сравнение модификаторов, поведение там прежнее — лучше использовать такие терминалы с выключенным Caps Lock.

Про кодировку модифицированных стрелок и Home/End для встроенного эмулятора терминала см. [terminal.md](terminal.md#взаимодействие).
