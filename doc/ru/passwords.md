# Хранилище паролей

TermIDE хранит пароли удалённых подключений в зашифрованном хранилище под
мастер-паролем, поэтому в закладках и сохранённых раскладках паролей быть
не должно.

Хранилище обслуживает:

- **Удалённые файловые системы** — SFTP, FTP, FTPS (см. [VFS](vfs.md)).
- **Базы данных** — PostgreSQL и MySQL (см. [Просмотр баз данных](database.md)).
- **Git по HTTPS** — имя пользователя и пароль или токен для push, pull и
  fetch.
- **Git по SSH** — парольную фразу вашего SSH-ключа.

## Как это работает

1. Подключение отклонено: SFTP — после SSH-агента и ключей, FTP — после
   анонимного входа, база данных — без пароля, git — без учётных данных.
2. Если в хранилище есть пароль для этого сервера и пользователя, TermIDE
   берёт его. Если хранилище заблокировано, сначала спрашивается
   мастер-пароль.
3. Иначе TermIDE спрашивает пароль. Отметьте **Сохранить в хранилище
   паролей**, чтобы его запомнить.
4. Пароль, который вы попросили сохранить, записывается только после того,
   как сервер его принял, — опечатка в хранилище не попадёт.
5. Первое сохранение создаёт хранилище. Вы задаёте мастер-пароль и вводите
   его дважды.

Если сохранённый пароль не подошёл (например, его сменили на сервере),
TermIDE спросит снова. Флажок уже отмечен, и новый пароль заменит старый.

Отмена запроса мастер-пароля не отменяет подключение: TermIDE просто
спрашивает пароль для входа.

Пароли хранятся по серверу: схема, хост и порт (порт по умолчанию не
пишется) плюс имя пользователя. Пароль базы данных относится к учётной
записи на сервере, а не к одной базе, поэтому при переключении базы в
панели он находится. Парольная фраза SSH-ключа, которым пользуется git,
хранится одной записью.

## Закладки с паролем в URL

Если добавить или изменить закладку, в URL которой есть пароль
(`postgres://user:secret@host/db`), TermIDE предложит перенести пароль в
хранилище. Ответьте **Да**:

- пароль сохраняется в хранилище;
- после сохранения закладка перезаписывается без него.

После этого проектные закладки (`.termide/bookmarks.toml`) можно спокойно
коммитить.

## Блокировка

Разблокированное хранилище само блокируется после 15 минут без
использования. Задержка меняется в **Настройки → VFS → Блокировать
хранилище паролей через** или в `config.toml`:

```toml
[vault]
lock_after_mins = 15   # 0 — не блокировать до выхода из termide
```

Команда **Заблокировать хранилище паролей** в палитре команд блокирует его
сразу.

[Отсоединяемый экземпляр](detached-instances.md) держит разблокированное
хранилище в серверном процессе; клиенты его не получают.

## Файл хранилища

Хранилище — это `~/.config/termide/vault.toml` (доступ только для
владельца). Хранилище одно на пользователя, проектных хранилищ не бывает.

- **Секреты зашифрованы.** Они запечатаны на пару ключей X25519: эфемерный
  X25519, HKDF-SHA256 и XChaCha20-Poly1305. Закрытый ключ зашифрован
  ключом, полученным из мастер-пароля через Argon2id (64 МиБ, 3 прохода).
- **Для сохранения разблокировка не нужна.** Нужен только открытый ключ,
  поэтому мастер-пароль TermIDE спрашивает лишь тогда, когда сохранённый
  пароль действительно нужен.
- **Метаданные читаемы.** Тип, сервер и имя пользователя хранятся открыто,
  чтобы TermIDE мог понять, есть ли пароль, не разблокируя хранилище. Они
  привязаны к зашифрованному секрету: изменённая запись не расшифруется, а
  не отправит пароль на другой хост.
- **Параллельная запись безопасна.** Хранилищем могут пользоваться
  несколько процессов TermIDE. Запись атомарна и упорядочена файлом
  блокировки.

**Забытый мастер-пароль восстановить нельзя.** Чтобы начать заново,
удалите `vault.toml`; сохранённые пароли пропадут вместе с ним.

## От чего защищает

Хранилище защищает пароли от того, кто прочитает ваши конфиги, резервные
копии, синхронизированные dotfiles или репозиторий, в который попал файл
закладок.

Оно не защищает от программы, запущенной под вашим пользователем, пока
хранилище разблокировано: такая программа может прочитать память TermIDE
или перехватить ввод с клавиатуры.

## Ограничения

- FTP-адрес без имени пользователя входит анонимно, и его запрос спрашивает
  только пароль. Укажите пользователя в URL (`ftp://user@host`).
- Списка и редактора сохранённых записей пока нет. Чтобы удалить запись,
  удалите файл хранилища.
- Пароли зашифрованных архивов не сохраняются.
