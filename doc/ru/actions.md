# Пользовательские команды

> **Примечание:** этот документ описывает **пользовательские команды** в меню `Команды`. Клавиатурные сочетания и действия интерфейса — в [ui.md](ui.md#клавиатурная-навигация-и-управление-по-меню-и-панелям).

Команда — это именованная строка оболочки, которую TermIDE запускает из меню `Команды` или по собственной горячей клавише: в новой панели терминала, незаметно в фоне или в фоне с показом вывода в окне по завершении. Команды описываются в файлах `commands.toml` — вручную или через форму `Добавить команду...`.

## Где хранятся команды

Файлов два, и меню показывает оба:

| Область | Файл |
|---------|------|
| Глобальные (для всех проектов) | `commands.toml` в каталоге конфигурации TermIDE |
| Проект | `<проект>/.termide/commands.toml` |

Каталог конфигурации зависит от платформы:

| Платформа | Глобальный файл |
|-----------|-----------------|
| Linux | `~/.config/termide/commands.toml` (или `$XDG_CONFIG_HOME/termide/commands.toml`) |
| macOS | `~/Library/Application Support/termide/commands.toml` |
| Windows | `%APPDATA%\termide\commands.toml` |

Файл проекта относится к текущему корню проекта, поэтому его можно закоммитить и разделить со всеми, кто работает с репозиторием.

Файлы не переопределяют друг друга: команда проекта и глобальная команда с одинаковым идентификатором — два отдельных пункта меню. Команды проекта идут первыми и выделены жирным.

## Формат файла

Каждая таблица TOML — одна команда; имя таблицы — идентификатор команды.

```toml
[build]
command = "cargo build --release"

[test]
name = "Run tests"
command = "cargo nextest run"
group = "cargo"
key = "Ctrl+Shift+T"

[clippy]
command = "cargo clippy --workspace -- -D warnings"
mode = "report"
group = "cargo"

[dev-server]
name = "Start dev server"
command = "npm run dev > /tmp/dev-server.log 2>&1"
mode = "background"
```

| Поле | Обязательное | Описание |
|------|--------------|----------|
| `command` | да | Строка оболочки для запуска |
| `name` | нет | Название в меню; если его нет, показывается идентификатор |
| `mode` | нет | `terminal` (по умолчанию), `background` или `report`, см. [Режимы запуска](#режимы-запуска) |
| `group` | нет | Помещает команду в подменю с этим именем |
| `key` | нет | Горячая клавиша, запускающая команду, например `Ctrl+Shift+D`, см. [Горячие клавиши](#горячие-клавиши) |
| `params` | нет | Значения, которые запрашиваются перед запуском, см. [Параметры](#параметры) |

Неизвестное значение `mode` означает `terminal`. Если файл не разбирается, ни одна из его команд не появится; причина пишется в лог.

## Меню «Команды»

Меню `Команды` в строке меню содержит сверху вниз:

1. `Добавить команду...` — открывает форму новой команды.
2. Команды проекта без группы, затем группы проекта (жирным).
3. Глобальные команды без группы, затем глобальные группы.

Внутри каждой части команды и группы отсортированы по идентификатору и имени группы. Группа открывает подменю со своими командами; повторный клик по заголовку группы закрывает его. Горячая клавиша команды показывается в колонке сочетаний. Если терминал поддерживает эмодзи, перед названием стоит значок режима: 💻 терминал, ⚙ фон, 📋 отчёт.

Клавиши на выбранной команде:

| Клавиша | Действие |
|---------|----------|
| `Enter` | Запустить команду |
| `F2` | Переименовать (изменить идентификатор) |
| `F4` | Редактировать в форме команды |
| `Delete` / `F8` | Удалить после подтверждения |

Меню перечитывает оба файла при каждом открытии, поэтому команды, добавленные в файл вручную, появляются без перезапуска.

## Добавление и редактирование команд

`Добавить команду...` и `F4` открывают одну и ту же форму:

| Поле | Назначение |
|------|------------|
| `Группа:` | Имя группы; предлагает существующие группы. Пустое — верхний уровень меню |
| `Пункт меню:` | Название в меню (`name`) |
| `Команда:` | Строка оболочки (`command`); обязательна при создании |
| `Режим:` | `Терминал`, `Фоновый` или `Отчёт`; переключается `←` / `→` или `1`–`3` |
| `Хоткей:` | Необязательная горячая клавиша (`key`) |
| `Команда проекта` | Отмечено — команда сохраняется в `.termide/commands.toml` проекта; не отмечено — в глобальный файл |

Идентификатор новой команды берётся из `Пункт меню:`, а если он пуст — из `Команда:`; символы `/ \ : * ? " < > | .` заменяются на `-`. Если команда с таким идентификатором уже есть, новая получает свободный вариант (`build-2`) и не заменяет её. Если при редактировании очистить `Пункт меню:`, метка удаляется, и меню показывает идентификатор. Переключение `Команда проекта` при редактировании переносит команду в другой файл. Форма не редактирует `params`: они остаются такими, как в файле. Переименование (`F2`) в идентификатор другой команды отклоняется.

Сохранение из формы, переименование и удаление правят `commands.toml` на месте: остальные команды, их порядок и комментарии вокруг остаются как были, переписываются только изменившиеся поля, а новая команда добавляется в конец. Переименованная команда переезжает в конец файла.

## Режимы запуска

Каждая команда запускается в рабочем каталоге панели в фокусе (например, в каталоге, открытом в файловом менеджере, или в текущем каталоге терминала), а если у панели его нет — в корне проекта.

| Режим | Как запускается | Вывод |
|-------|-----------------|-------|
| `terminal` | Открывается новая панель терминала, и строка команды вводится в её оболочку | В терминале; оболочка остаётся открытой после завершения команды |
| `background` | `sh -c "<команда>"` без панели | Отбрасывается |
| `report` | `sh -c "<команда>"` без панели | Перехватывается и показывается в окне по завершении |

Фоновые команды и команды-отчёты появляются в панели [Операции](operations.md), которая открывается при их запуске. Запись исчезает, когда процесс завершается; отмена записи там убивает процесс вместе с дочерними. Других сигналов о завершении фоновая команда не даёт, поэтому, если её вывод нужен, перенаправьте его в файл. В Unix при установленном `direnv` фоновые команды и команды-отчёты также получают окружение, которое `direnv export json` возвращает для рабочего каталога.

### Окно отчёта

Когда команда-отчёт завершается, окно с заголовком из метки команды и `✓` (код выхода 0) или `✗` (любой другой код) показывает её вывод: сначала стандартный вывод, затем стандартный поток ошибок. Отступы и пустые строки внутри вывода сохраняются, табуляции разворачиваются в четыре пробела, пустые строки в начале и конце каждого потока отбрасываются; команда без вывода показывает `(no output)`. Окно открывается в текущем проекте, каким бы он ни был; для команды, запущенной в другом проекте, к заголовку добавляется путь этого проекта. Если несколько команд-отчётов завершились одновременно, показывается окно только последней.

| Клавиша | Действие |
|---------|----------|
| `↑` / `↓` (`k` / `j`) | Прокрутка на строку |
| `PageUp` / `PageDown` | Прокрутка на страницу |
| `Home` / `End` | В начало / в конец |
| Колесо мыши | Прокрутка |
| `Enter` / `Escape` | Закрыть окно |

## Параметры

Команда может объявить параметры. Перед запуском TermIDE показывает форму с заголовком `Параметры: <идентификатор>`, по полю на каждый параметр, и кнопками `Запуск` и `Отмена`. Каждое значение передаётся команде в переменной окружения `TERMIDE_PARAM_<ИМЯ>`: имя в верхнем регистре, `-` заменён на `_`.

```toml
[deploy]
name = "Deploy"
command = "./deploy.sh \"$TERMIDE_PARAM_TARGET\" \"$TERMIDE_PARAM_DRY_RUN\""
mode = "report"
key = "Ctrl+Shift+D"

[[deploy.params]]
name = "target"
label = "Target environment"
type = "select"
options = ["staging", "production"]
default = "staging"

[[deploy.params]]
name = "dry-run"
label = "Dry run"
type = "bool"
default = true
```

| Поле | Описание |
|------|----------|
| `name` | Обязательное; переменная — `TERMIDE_PARAM_<ИМЯ>` |
| `label` | Подпись поля в форме; по умолчанию — `name` |
| `type` | `text` (по умолчанию), `number`, `bool` или `select` |
| `options` | Варианты для `select` |
| `default` | Начальное значение: строка, число или логическое значение |

| Тип | Поле | Передаваемое значение |
|-----|------|-----------------------|
| `text` | Текстовое поле | Текст как введён |
| `number` | Текстовое поле | Текст как введён; что это число, не проверяется |
| `bool` | Флажок, переключается `Space` / `Enter` или кликом | `true` или `false` |
| `select` | Выбор, переключается `←` / `→`; начинается с `default`, иначе с первого варианта | Выбранный вариант |

Форма показывается, как бы команда ни была запущена: из меню `Команды`, горячей клавишей или из командной палитры. Переменные доходят до команды в любом режиме; в режиме `terminal` они задаются в оболочке нового терминала и остаются в ней после завершения команды.

## Горячие клавиши

`key` записывается в той же нотации, что и сочетания в `config.toml` (см. [keybindings.md](keybindings.md)), например `Ctrl+Shift+D` или `Alt+F5`. `Ctrl+Shift+<буква>` доходит до TermIDE только в терминалах с протоколом клавиатуры Kitty (см. [Универсальные vs расширенные биндинги](keybindings.md#универсальные-vs-расширенные-биндинги)). Горячая клавиша команды проверяется вместе с глобальными сочетаниями TermIDE, поэтому работает независимо от того, какая панель в фокусе. Команда проекта и глобальная команда с одинаковым идентификатором сохраняют отдельные горячие клавиши.

Команды с горячей клавишей также перечислены в командной палитре (`Ctrl+P`) как `Run command: <название>`.

Поле `Хоткей:` в форме принимает `Ctrl`, `Alt` и `Shift` в сочетании с буквой, цифрой, `F1`–`F12` или именованной клавишей (`Enter`, `Tab`, `Space`, `Home`, `PageUp`, стрелки и т. д.) и отклоняет горячую клавишу, которую уже использует другая команда или глобальное сочетание TermIDE (`Этот хоткей уже используется`). Горячая клавиша, записанная в файл вручную, не проверяется: если она совпадает с глобальным сочетанием, срабатывает сочетание, и команда с клавиатуры не запускается никогда. Она начинает действовать при следующем открытии меню `Команды` или после сохранения файла из TermIDE.

## Советы

- Команды выполняются через `sh -c` (или оболочку терминала), поэтому конвейеры, `&&`, перенаправления и переменные окружения работают как в оболочке. В Windows для команд `background` и `report` нужен `sh` в `PATH`.
- Используйте `report` для коротких проверок, результат которых хочется прочитать (`git status`, линтер), `background` — для процессов, вывод которых не нужен, и `terminal` — для всего интерактивного или долгого, за чем хочется следить.
- Держите команды, относящиеся к проекту, в `.termide/commands.toml` в репозитории, а личные — в глобальном файле.
