# 应用程序窗口概览

**应用程序占据所有可用空间，垂直划分为以下元素：**
- 菜单栏
- 面板区域
- 状态栏

应用程序还使用弹出窗口：
- 帮助
- 设置
- 关闭应用确认

## 模态窗口

应用程序使用交互式模态窗口进行各种操作：
- **内嵌查找 / 替换栏**（`Ctrl+F` / `Ctrl+H`）- 停靠在编辑器、文件管理器和终端内的搜索与替换，带实时预览、匹配计数、`[Aa]` / `[.*]` 开关和导航按钮
- **输入模态框** - 用于文件操作（创建、重命名等）的各种提示
- **确认对话框** - 删除确认、未保存更改等

**模态框功能：**
- 模态框标题栏中的 `[X]` 关闭按钮（可用鼠标点击）
- 使用 Tab/Shift+Tab 进行键盘导航（在模态框字段/按钮之间）
- 所有按钮支持鼠标操作
- Escape 键关闭模态框；在选择列表、清单、输入提示、确认框或信息窗口之外单击也会同样关闭它
- 搜索/替换操作的实时预览
- 状态保持（保存上次输入的文本）

### 帮助窗口

`F1` 或 `Alt+H`（菜单 **Options → Help**）在面板上方打开一个窗口，列出 termide 绑定的所有按键（按配置中的设置）。它会定位到当前焦点面板的章节——从 git status 面板打开时显示其按键——通用按键位于其上方。

- 输入文字即可筛选：按键或描述包含该文字的条目保留，标题包含该文字的整个章节保留；`Backspace` 和 `Ctrl+U` 删除文字。
- `Tab` / `Shift+Tab` 跳到下一个或上一个章节；方向键、`PgUp` / `PgDn`、`Home` / `End` 和鼠标滚轮用于滚动。
- `F1`、`Alt+H`、`Esc` 或在窗口外点击可关闭它。

### 设置模态框（Settings）

通过 `Alt+P` 或菜单 **选项 → 设置** 打开。与之前的横向标签布局不同，现已改为 **侧边栏布局**：

**三个区域：**
- **左侧边栏**（宽 18 列）— 区块列表，使用 Up/Down 浏览
- **内容区**— 所选区块的字段，按 `── 分组 ──` 副标题归类并用空行分隔
- **底部按钮**— `存储：全局 / 项目`、`重置`、`关闭`

**保存。** 每项更改立即生效并保存：开关和下拉列表在选择时，文本和数字字段在按 `Enter` 时。没有"应用"按钮，也无需取消。

**设置存储位置。** 第一个按钮切换存储位置：
- **全局** — `~/.config/termide/config.toml`，所有项目共用。
- **项目** — `<项目>/.termide/config.toml`，只保存与全局设置不同的部分。切换时创建该文件，设置本身不变。
- 切换回全局会删除项目文件，并询问如何处理其设置：**丢弃**（使用全局设置）或**移至全局**（成为所有项目的全局设置）。

**重置**会先确认，并作用于当前存储位置：项目恢复为全局设置，全局设置恢复为默认值。

从菜单选择的主题、语言和 shell 存储在全局设置中，项目自身的主题或语言随之移除。若要为某个项目单独设置，请在此处以 `Stored: Project` 选择。

**只能由全局设置指定的内容。** 项目的文件随仓库而来，因此它不能指定 termide 启动的程序、写入的文件或密钥发送的地址，也不能放宽代理的限制：终端的默认 shell、日志文件、网络工具的浏览器、LSP 服务器或调试器的命令和参数、连接的基础 URL 和 API 密钥变量，以及代理的权限模式。设置存储在项目中时，这些字段显示其值并注明“在全局设置中设置”，且无法更改；若出现在项目文件中，则会被忽略，并在日志中记录一行。

**侧边栏区块：**
- General、Editor、File Manager、Terminal、LSP、Debug、Logging、VFS、AI、Plugins — 普通叶节点
- **Keybindings** — 可展开分组（▶/▼），位于列表末尾，包含 9 个子区块（Global、Editor、FileManager、GitStatus、GitDiff、GitLog、Terminal、Database、Viewer）

**布局与图标**（General 区块，`config.toml` 中的 `[general]`）：
- **图标模式**（`icon_mode`）— 面板标题中的图标：`auto`（默认）在终端能绘制时显示 emoji，`emoji` 始终显示，`unicode` 不显示
- **自动堆叠阈值**（`auto_stack_threshold`，默认 `80`）— 若新建一列会窄于该字符数，新面板放在活动面板下方而不是新的一列
- **面板最小宽度**（`min_panel_width`，默认 `20`）— 调整面板大小时最窄到此宽度

**导航：**

| 快捷键 | 操作 |
|--------|------|
| `Up` / `Down` | 在当前区域内移动（区块 / 字段 / 按钮） |
| `Tab` / `Shift+Tab` | 在区域之间循环切换焦点（Sidebar ↔ Content ↔ Buttons） |
| `Left` / `Right` | **不** 切换区域；用于修改值（枚举循环、布尔切换）、在按键绑定行内于各按键之间移动，以及在侧边栏中折叠 Keybindings 分组 |
| `Enter` / `Space` | 激活：在侧边栏中进入区块；在内容区中切换 bool/enum 或开始编辑数值/文本；在分组头上切换展开 |
| `Escape` / `Ctrl+S` | 关闭模态框（一切已保存）；在按钮行中，Escape 先取消待回答的问题 |
| 鼠标滚轮 | 滚动侧边栏 / 内容 |

**字段与指示符：**
- **Bool** — `[✓]`（开）或 `[ ]`（关），通过 `Enter`/`Space` 或 `Left`/`Right` 切换
- **Enum** — `< 值 >`，通过 `Left`/`Right` 循环
- **Number** / **OptionalText** — 按 `Enter` 进入内联编辑模式
- **LSP → Servers** — 服务器列表项以项目符号 `•` 开头；另外还有一行 `+ Add Server`

**Keybindings — 编辑绑定：**  
用 `Up/Down` 在列表中导航。每一行列出该操作接受的所有按键——`Alt+W, Alt+X, F10`——光标停在其中一个上：

| 快捷键 | 操作 |
|----------|--------|
| `Left` / `Right` | 在该行的各按键之间移动光标；越过最后一个按键时光标落到 `[+]` 按钮 |
| `Enter` | 为光标所在的槽位捕获一次按键——替换该按键，在 `[+]` 上则追加一个新的备选 |
| `Delete` | 移除光标所在的按键 |
| `Shift+Delete` / `Backspace` | 清除该操作的所有按键 |
| `Escape` | 离开列表，或放弃正在进行的捕获 |

获得焦点的行末尾画着 `[+]` 按钮：点击它，或在其上按 `Enter`，即开始捕获并把按键追加到末尾。点击某个按键会选中它，于是接下来的 `Enter` 或 `Delete` 作用于被点中的那个；双击某个按键则开始捕获。该操作已经接受的组合会被拒绝并说明原因；被其他操作占用的组合会写入，并警告它同时还绑在哪里。捕获按键期间该行仍然显示自己的按键，将被替换的那个以警告色标出。

当焦点离开侧边栏时，当前区块的高亮会取消——因为当前区块名已显示在内容区标题中，再双重高亮会让用户分不清真正的焦点位置。

## 菜单栏

菜单栏位于窗口顶部，包括：左侧的菜单项、其后已打开项目的按钮、系统资源指示器（网络速度、CPU、内存，以及有电池时的电量），以及右侧的 HH:MM 格式时钟。
菜单的激活/停用及各项目可通过鼠标点击或[键盘快捷键](#键盘导航和面板管理)访问。
下拉列表打开时不选中任何项——菜单项、项目按钮、面板的 `[≡]`（`Alt+K`）、操作以及 stash 按钮的下拉列表皆如此：`←`/`→` 沿菜单栏继续移动，`↓` 选中第一项，`↑` 选中最后一项，只有选中某项后 `Enter` 才会执行。从带 `▶` 的项打开的子菜单从其第一项开始。

**菜单项：**
- `书签` — 保存的位置（目录、文件、SSH、SFTP、网页链接）。打开时按类型路由：目录和远程路径在文件管理器中，HTML/Markdown/Mermaid/CSV/图片文件和 `http(s)` 链接在内置查看器中（见 [HTML 预览](html.md)；在那里按 `O` 可将页面交给浏览器），其他文本文件在编辑器中，SSH 在终端中，数据库在 DB 查看器中。点击分组标题可切换其子菜单，与命令菜单相同。
- `命令` — 用户自定义命令，项目命令（粗体）在前，支持分组子菜单；顶部的 `添加命令...` 用于新建命令。点击分组标题展开子菜单；再次点击同一标题则折叠（toggle）。参见[自定义命令](actions.md)。
- `窗口` — 面板创建子菜单：
  - 打开… — 通过带建议的提示打开文件、目录或 URL（`Ctrl+G`）
  - 终端 — 终端面板（有子菜单可选择 shell：列出系统中所有可用的 shell，默认 shell 以 ● 标记）
  - 文件 — 文件管理器面板
  - 编辑器 — 文本编辑器面板
  - Git 状态 — Git 状态面板
  - Git 日志 — 提交历史面板
  - 日志 — 应用日志面板；点击标题中的 `TRACE`…`ERROR` 标签或按 `1`…`5` 键可显示或隐藏对应级别
  - 诊断 — LSP 诊断面板
  - [操作](operations.md) — 后台操作面板
  - 大纲 — 代码结构导航面板
  - [代理](agent.md) — 编码代理面板
- `选项` — 设置子菜单：
  - 主题 — 主题选择（实时预览）
  - 语言 — 界面语言（实时预览）
  - 设置 — 打开设置模态框
  - 帮助 — 打开帮助窗口
  - 分离实例 — 让本实例在后台继续运行（仅在可分离时显示；参见[可分离实例](detached-instances.md)）
  - 退出 — 退出应用
- `AI` — 编码代理的代理、会话、技能和提示词，以及代理浏览器窗口的开关；参见 [AI 菜单](agent.md#ai-菜单)
- `项目` — 项目管理子菜单：
  - 新建项目 — 在其他目录中开始项目

    与在目录已不存在的项目上按 `F6`（见下文）一样，在目录树中选择目录：`→`/`←` 展开和折叠分支，`Enter` 进入目录，`Backspace` 返回上级目录，`.` 显示或隐藏隐藏目录，`Ctrl+Enter` 在任意位置确认

    文件管理器的按键在这里同样作用于目录：`create_dir`（`F7`/`D`，或 `新建文件夹` 按钮）会在光标所在条目旁边打开一个名称行——与它同级，而不是在它里面，即使它已展开；`rename`（`F2`/`R`）就地编辑名称；`delete`（`F8`/`Delete`）只删除空目录。`Enter` 应用名称，`Esc` 放弃；无法使用的名称会让该行保持打开，并在目录树上方说明原因
  - 重新打开上次运行的项目 (N) — 当上次运行中打开了不止一个项目时显示，直到您使用它或自行打开其他项目为止。它在后台打开这些项目，您仍停留在当前项目；每个项目在您第一次切换到它时加载布局（代理留下未完成工作的项目——中断或暂停的运行、`/goal` 或 `/loop`、等待重试的请求——会立即加载，使其卡片响铃并以 🔔 标记该项目），其终端中启动新的 shell。每当打开的项目集合发生变化时都会保存该列表，因此即使崩溃也不会丢失；从未打开第二个项目的运行不会改动它。同时运行多个实例时，以最后更改其项目集合的实例为准。另一个实例已打开的项目留给该实例，不会被重新打开。每次启动都会自动这样做（`restore_projects`，默认开启；设置 → 常规中的**重新打开上次运行的项目**）：启动所在的目录成为当前项目（若不在集合中则加入集合），上次运行的项目在其周围于后台打开；其中代理未完成的工作会等到您进入该项目时再继续。`--no-restore` 可跳过一次。`termide --restore`（`-r`）即使关闭该设置也会恢复，与菜单项相同，并在上次运行所在的项目中打开；若从该集合中的某个目录启动，则留在该目录，因此从别处启动不会把该目录加入集合。若没有已保存的集合，两者都照常启动；带路径的启动（作为 `$EDITOR` 的 `termide <文件>`，或 `termide <目录>`）从不恢复
  - 分隔线下方列出您使用过的所有项目。先是在此实例中已打开的项目，按您安排的顺序排列：新打开的排在最后，在面板组之间移动面板的按键会移动所选项目——`Alt+PgUp`/`Alt+PgDn` 上移或下移一位，`Alt+Home`/`Alt+End` 移到开头或末尾；也可用鼠标将其拖过其他项目，拖动时按 `Esc` 则放回原处；`goto_project_N` 按此顺序编号，重新打开时也会恢复此顺序；再隔一条分隔线是其余项目，最近使用的在上；列表较长时可滚动。每行与项目切换窗口中的显示相同：标记、未打开项目最后一次使用的时间（以暗色显示）、路径（过长时截去开头）和 🔔。● 标记当前项目，○ 标记在后台打开的项目，✗ 标记目录已不存在的项目（在 Termide 之外被移动或删除），🔔 标记有面板在等待您的项目（代理的提问或已完成的工作、终端响铃）；只要存在这样的项目且其按钮不在菜单栏上，`项目` 标题前也会显示 🔔。关闭 emoji 图标时，此处和面板标题中以 `!` 代替 🔔。`Enter` 或单击即切换。`Delete`/`F8` 对后台打开的项目是关闭它并停止其中运行的程序，对未打开的项目是删除 Termide 为它保存的一切——已保存的布局、未保存的缓冲区、日志以及授予它的权限——并将其从列表中移除（项目文件不受影响）；如果该项目有代理会话，询问时可选择一并删除或保留。两者都会先请求确认；在另一个实例中打开的项目不会被删除。对当前项目，则切换到您最后离开的项目并关闭当前项目，仅当其中有正在运行的程序或未保存的更改时才请求确认；若没有其他已打开的项目，当前项目不受影响
  - 切换到其他项目时，原先所在的项目会在后台保持打开：其终端中的程序继续运行，代理继续工作，未保存的修改保持原样。项目会一直保持打开，直到您关闭它或 Termide 退出。对已打开的目录执行“新建项目”会切换到该目录。退出时 Termide 会列出仍在运行程序的后台项目。`Alt+1`…`Alt+9` 按 `项目` 菜单中的排列顺序切换到对应编号的已打开项目；`prev_project` 和 `next_project` 依次切换，默认未绑定，参见[未绑定的操作](keybindings.md#未绑定的操作)
  - 同一时间一个项目只在一个 Termide 中打开，以免两个实例互相覆盖其布局，或重复运行其语言服务器和代理。切换到另一个实例已打开的目录、在其上新建项目或将项目移到那里都会被拒绝，状态栏会指明那个实例：它的 pid，或可接入的可分离实例。在这样的目录中启动 `termide` 会在界面出现前以同样的消息结束——若该项目由[可分离实例](detached-instances.md)持有且本次启动有终端，则会接入那个实例。重新打开但尚未进入的项目只在第一次加载时才被占用，因此另一个实例可以先打开它；此时它在菜单栏和项目列表中显示为删除线，进入它会以同样的消息被拒绝，项目仍留在列表中。项目在被关闭或其 Termide 结束时（无论以何种方式结束）释放。作为 `$EDITOR` 的启动（`termide <文件>`）、`--prompt` 和 `--recall` 不占用项目，也从不被拒绝
  - `Alt+\` 打开项目切换模态窗口。其中的项目与本菜单列出的方式相同，每个项目一行——标记、未打开项目最后一次使用的时间（以暗色显示）、路径和 🔔——光标所在行以反色显示。输入文字可按路径筛选列表。光标停在您最后离开的项目上：按 `Alt+\` 再按 `Enter` 即可返回该项目。`Delete`/`F8` 的作用与菜单中相同；筛选框为空时，移动已打开项目的按键也与菜单中相同
  - 在项目行上按 `F6` 移动项目，按 `F5` 复制项目——包括其目录和全部文件，以及 Termide 在别处为它保存的内容：带未保存缓冲区的已保存布局、带检查点的代理会话、断点，移动时还有授予该项目的权限。提示框与文件管理器的复制和移动提示相同，可编辑项目路径；目标不得已存在。文件由后台[操作](operations.md)传输，带进度和取消按钮。在此打开的项目会在移动期间关闭——若其中有正在运行的程序或未保存的更改会先询问——随后在新路径、列表中原来的位置重新打开；当前项目仍为当前项目，移动期间只显示操作面板。移动后会修复仓库与其 git worktree 之间的链接。副本是独立的项目：它在原项目之后于后台打开，其代理会话获得新的 id，原项目被授予的权限不会带给它。若目录内还有其他已打开的项目，或目标已在另一个实例中打开，则拒绝移动。操作失败或被取消时，项目会在原处重新打开，已到达目标的内容保留在那里
  - 对标记为 ✗ 的项目（其目录已在 Termide 之外被移走），`F6` 和 `Enter`——在此处和项目切换窗口中——改为询问它现在的位置，并在目录树中选择目录。Termide 为它保存的内容会像移动时一样转到那里：带路径的已保存布局、未保存的缓冲区、带检查点的代理会话、断点和权限，并修复仓库与其 git worktree 之间的链接；文件本身不会移动。已有自己项目的目录会被拒绝：请先删除那个项目或选择其他目录

**项目按钮：** 每个已打开的项目（即使只有一个）在菜单项和指示器之间都有一个按钮 `name`：项目的目录名，若两个已打开的项目同名则带上其父目录，正在等待的项目名称前还带 🔔。当前项目的按钮使用菜单项的颜色，其他按钮以暗色显示。它们按 `项目` 菜单的顺序排列，以暗色的 `" | "` 隔开——第一个之前和最后一个之后没有——并从最后一个菜单项 `项目` 之后两列处开始，使这组按钮自成一块。放不下时，名称会截去开头——短名称保持原宽度，长名称平分剩余空间；连截短的名称也放不下时，按钮依次隐去——被选中或正在拖动的最后隐去，在它之前是当前项目和正在等待的项目——`+N` 显示被隐藏的数量。按钮像菜单项打开下拉列表一样打开其项目的菜单：其他项目有 **切换到项目**，然后是 **移动项目…**（`F6`）、**复制项目…**（`F5`）以及 **关闭**（`F8`、`Delete`）——当前项目仅在还有其他项目打开时才有；关闭项目时菜单也随之关闭。单击切换到其他项目；单击当前项目的按钮打开其菜单，再次单击则关闭；沿菜单栏拖动按钮会移动其项目，拖动时按 `Esc` 则放回原处。在打开的菜单中，`←`/`→` 会在菜单项之后、指示器之前经过这些按钮，并依次打开各自的菜单，状态栏显示项目的完整路径（按钮上的名称可能被截短）。`Alt+PgUp`/`Alt+PgDn` 将选中的按钮左移或右移一位，`Alt+Home`/`Alt+End` 移到开头或末尾，与 `项目` 菜单中相同。

**系统资源指示器**（可点击的指示器会打开详情模态框）：

| 指示器 | 说明 | 点击打开 |
|--------|------|---------|
| `↓…/↑…` | 网络速度（↓ 下载，↑ 上传） | 网络活动前 10 的进程 |
| `CPU XX%` | CPU 使用率 | CPU 占用前 10 的进程 |
| `RAM X/YGB` | 内存使用 | 内存占用前 10 的进程 |
| `⚡NN%` / `🔋NN%` | 电池电量（⚡ = 已接通电源 / 充电中 / 已充满，🔋 = 使用电池）。没有电池的系统上隐藏。 | —（仅显示信息） |
| `设备 已用/总计GB`（状态栏） | 磁盘使用 | 磁盘占用前 10 的进程 + 文件系统分区 |

再次点击同一指示器会关闭其打开的窗口（toggle）；状态栏的磁盘指示器行为相同。

颜色编码（CPU / 内存）：绿色 < 50%，黄色 50–75%，红色 > 75%。电池使用反向的同一刻度（充电中或高于 50% 为绿色，低于 25% 为红色）。电池读数缓存 5 秒，因此每帧渲染路径从不访问 `/sys`。

这些指示器以及打开着的详情窗口每隔 `[general]` 中的 `resource_monitor_interval` 毫秒采样一次（默认 `2000`；设置中为 **常规 → 资源监视间隔 (ms)**）。

**网络活动模态框**显示：
- **Application** — 进程名
- **Ports** — 监听的 TCP 端口（例如 `80, 443`）
- **Conn** — 活动（ESTABLISHED）连接数

进程按连接数从多到少排序。

## 面板区域

面板区域填充菜单栏和状态栏之间的垂直空间，从左到右延伸至窗口边缘。
布局会根据终端宽度自适应，在更宽的屏幕上显示更多面板组。面板（终端、编辑器、Git）可以打开并排列在旁边。

**可打开的面板类型：**
- [文件管理器](file-manager.md) — `Alt+F`
- [终端](terminal.md) — `Alt+T`
- [文本编辑器](editor.md) — `Alt+E`
- Git 状态 — `Alt+G`；在 git 仓库之外，若版本控制插件提供状态面板则打开它（Perforce 的已打开文件）
- 大纲 — `Alt+O`
- 诊断 — `Alt+I`
- Git 日志 — `Alt+C`
- Git 差异
- [编码代理](agent.md) — `Alt+A`
- [操作](operations.md)
- 图片查看器
- 日志 — `Alt+L`

**Git 状态**面板顶部有两个选择器：仓库和分支。分支列表包含本地分支，以及没有对应
本地分支的远程分支；`●` 标记在仓库主副本中检出的分支，`⧉` 标记在关联工作树
（worktree）中检出的分支（工作树目录不会作为独立仓库列出）。选择分支永远不会检出
它——只会改变面板显示的内容：

- 在主副本或某个工作树中检出的分支，显示该工作副本的更改，暂存、提交、diff、
  推送和拉取都在其中执行；
- 未在任何地方检出的分支，显示它相对主副本分支领先和落后多少，并带有 `[Checkout]`
  按钮，可将其检出到主副本。当 git 拒绝时（例如有未提交的更改挡路），其消息会作为
  错误显示。

`[Log]` 在同一仓库和分支上打开 Git 日志。日志自己的分支选择器以同样方式标记分支，
只用于选择显示哪条历史；检出之后，跟随 HEAD 的日志会切换到新分支。

在已更改的文件上，`S` 暂存它（目录也可以），`U` 取消暂存，`F3` 打开查看，`F4` 在编辑器中打开，`Space` 或 `F12` 显示其属性，`Backspace` 或 `Delete` 在确认后丢弃其更改。`Ctrl+R` 重新读取状态并从远程获取。只要有任一文件夹展开，`Ctrl+O` 就折叠两个列表中所有层级的文件夹；全部折叠时则全部展开，之后刷新带来的新文件夹也随之。它们是 `[git_status.keybindings]` 下的 `stage`、`unstage`、`view`、`edit`、`info`、`revert`、`refresh` 和 `toggle_folds`。全局复制键（`Ctrl+C`）复制光标下文件或文件夹相对于仓库的路径。

**Git 日志**面板根据每个提交的父提交，用制表符伪图形（`● │ ├ ╮ ╯`）绘制提交图，
每条线各有颜色，便于按颜色追踪分支。如需改回 git 原生的 ASCII `--graph`，请在
`config.toml` 中设置：

```toml
[git_log]
unicode_graph = false
```

日志在滚动时读取历史：最初的提交会立即显示，当视图下方剩余不足两屏时会继续读取，
期间在最后一个提交下方显示 *Loading commits…* 行。`End` 会读到历史末尾（无论多长），
并在读取过程中保持选中最后一个提交。滚动条从一开始就覆盖整个历史。当日志重新加载时
——提交、检出、变基之后——选中的提交保持选中，并停留在屏幕上的同一位置。

在提交上，`Enter` 或 `D` 打开其 diff，`Space` 显示其详情；`Ctrl+R` 重新加载日志。除
`Enter` 外，这三者是 `[git_log.keybindings]` 下的 `info`、`view_diff` 和 `refresh`。
检出分支在 git status 面板中进行。

**Git diff** 面板（git status 中的 `[Diff]`）显示工作区的改动：先是未暂存的，再是标有
`[staged]` 的已暂存改动，并可按块或按行暂存或丢弃。光标按绘制顺序在各行间移动：在文件
标题上代表整个文件，在 `@@` 块标题上代表该块，在行上代表该行。`[` 和 `]` 在块之间跳转；
`V` 开始选择行，`Shift+↑↓` 在块内扩展选择，`Esc` 取消。

- `Space` 暂存光标所代表的内容；在已暂存一侧则取消暂存。选中的上下文行不会改变任何内容，
  面板会说明这一点。
- `D` 在确认后从工作区丢弃它；在已暂存一侧则改为取消暂存。`U` 在面板打开期间恢复上次
  丢弃的内容：文件会先保存在 git 的对象库中。
- 未跟踪、重命名和二进制文件只能整体处理。丢弃未跟踪文件会删除它，因此总会先询问。

面板从 git 当时写出的 diff 中切出每个补丁，因此回车符和缺失的末尾换行符得以保留；若文件
在绘制之后发生了变化，操作会被拒绝，面板重新加载。`Enter` 折叠文件，`E`/`F4` 打开它。
只要有任一文件展开，`Ctrl+O` 就折叠所有文件；全部折叠时则全部展开。之后刷新带来的新文件
也随之，手动折叠的文件在刷新后保持折叠。
提交或储藏（stash）的 diff 只显示改动，此时 `Space` 与 `Enter` 一样用于折叠。按键位于
`[git_diff.keybindings]`：`toggle_stage`、`discard`、`undo_discard`、`select_lines`、
`prev_hunk`、`next_hunk`、`toggle_collapse`、`toggle_folds`、`edit`、`refresh`、
`scroll_half_up` 和 `scroll_half_down`。`F5` 或 `Ctrl+R` 重新读取 diff，`Ctrl+U` / `Ctrl+D` 向上或向下滚动半屏。

同一个面板也用于审查代理的改动：在代理面板中输入 `/changes`，或在其菜单中选择**审查
更改**，会打开该面板，显示自你上次接受以来代理所做的改动，且仅此而已——你在两次请求之间
自己所做的编辑不在其中。每个请求都会把工作区快照存入 git（位于 `refs/termide/review/`
下的树，任何日志都不显示），因此 shell 命令和外部代理所做的改动同样涵盖在内。代理在此期间
继续工作；审查是事后进行的。

- `Space` 保留光标所代表的内容：它离开审查，留在文件中。暂存或提交某个改动同样会保留它。
- `D` 拒绝它：它在工作区中被撤销，代理会在下一个请求中得知——以一条附加在你的消息后的
  简短说明。`U` 收回上一次拒绝，且不会告知代理。
- `A` 保留全部；`X` 在确认后拒绝全部。
- 在两次请求之间你也编辑过的文件会标记为 `你也编辑过`：在其中拒绝会先询问，因为
  该块中可能有你的改动，而 `X` 不会动这些文件。

请求运行期间你所做的改动算作代理的改动。按键是 `[git_diff.keybindings]` 下的 `keep_all`
和 `reject_all`，并复用 `toggle_stage`、`discard`、`undo_discard` 和 `select_lines`。

打开**二进制文件**（在文件管理器中按 `Enter` 或 `F3`）会显示只读的**十六进制查看器**
——`偏移 │ 十六进制 │ ASCII`，行宽按 16 字节分段适应面板——而不是交给系统查看器。
十六进制区和 ASCII 区都显示字节光标（`Tab` 切换活动区）；方向键/`hjkl` 移动光标，
`Shift`+移动进行选择，`Ctrl+C` 复制选区（在十六进制区复制为十六进制，在 ASCII 区
复制为文本）。`Ctrl+F` 打开搜索栏，搜索 ASCII 子串，或——开启 `[hex]` 开关时——
搜索 `ff fe` 这样的十六进制字节序列；匹配项在两个区中都会高亮。

改用 `F4`（编辑）打开二进制文件则使其**可编辑**：输入会覆盖光标下的字节——在十六进制
区输入两个十六进制半字节，在 ASCII 区输入一个字符——而不改变文件长度。未保存的编辑
会在标题中显示 `*`；`Ctrl+S` 经确认后保存，保存前先将原文件备份为 `<file>.bak`；若该文件已存在，则备份为第一个可用的 `<file>.bak.N`，绝不覆盖已有备份。`Ctrl+E`（或 `Edit:` 字段）在编辑与查看之间切换；有未保存的修改时，会先询问是保存（并备份）、丢弃，还是继续编辑。

`Ctrl+L`（或状态栏中的 `[Hex]`/`[Text]` 标签）在十六进制和文本之间切换。对于真正的
文本文件，这会将面板原地替换为只读编辑器（编辑器自己的 `Ctrl+L` 可切换回十六进制）；
对于编辑器无法以文本打开的二进制文件，则切换为面板内的有损文本视图。该切换键可配置：

```toml
[viewer.keybindings]
toggle_hex = "Ctrl+L"
```

**可关闭面板的特点：**
- 面板标题中有 `[≡]` 操作按钮（点击打开上下文菜单：关闭 / 拆分 / 合并 / 移动）
- 可通过 Alt+W、Alt+X 或 F10 关闭；面板自身没有可退出的状态（搜索栏、选区、vim 插入模式）时也可用 Escape 关闭；运行中的终端把 Escape 交给其程序，代理面板从不因 Escape 关闭；关闭最后一个面板时，会在其位置打开位于项目根目录的文件管理器
- 列宽通过 `Alt+=` / `Alt+-` 调整
- 列内每个面板的高度通过 `Alt+Shift+=` / `Alt+Shift+-`（步长 1 行）、用鼠标拖动面板的下边框或在列内上下拖动面板标题进行调整
- `Alt+F11` 切换聚焦面板的全屏预设（一个面板占满整列，其余各自缩为一行标题）；再次按下恢复之前的高度
- 有些面板按内容自适应高度，而不是分得列的一份——操作面板就是其中之一——并在全屏预设期间保持该高度（聚焦这类面板时，已放大的面板保持原样）；手动调整这类面板的大小会让它获得普通的固定高度，直到它被关闭
- 可通过拖拽顶部边框来移动（参见下面的"鼠标交互"）

**面板操作上下文菜单：**

点击面板标题中的 `[≡]` 按钮（或在活动面板上按 `Alt+K` / `Shift+F10`）会打开下拉菜单：
- **上移 / 下移** — 在当前组内重新排序（当组内有多个面板时）
- **左移 / 右移** — 移动到相邻组（当有多个组时）
- **拆分 / 合并** — 从组中拆分出新组（当堆叠时），或将单独面板与相邻组合并
- **关闭** — 关闭面板（必要时带确认）

菜单项根据上下文过滤：例如，只有一个面板在一个组中时，*拆分/合并* 隐藏；单独面板时，*上移/下移* 隐藏。

**鼠标交互：**
- 点击标题区域激活面板；双击文件管理器标题打开目录选择器。
- **拖拽滚动条滑块**（面板右边框上的 `▌` 块，或绘有水平滚动条时下边框上的 `━` 块）
  可将面板滚动到对应位置。只有滑块会被这样抓取：滚动条轨道以及没有滚动条的边框仍按
  下文所述调整布局。拖拽未聚焦面板的滑块会原地滚动它而不移动焦点，与鼠标滚轮相同。
- **拖拽面板的底部边框** 在列内调整该面板的高度（实时 `━` 幽灵线
  预览新分隔线的位置，调整在释放时应用）。
- **拖拽面板的顶部边框（标题）** —— resize 或 reorder：
  - 在源面板主体或上方相邻面板的主体内释放 → 垂直 resize：
    被拖面板上方的分隔线跟随光标（列顶部的面板上方没有分隔线，
    会回退到移动模式）。
  - 在同组另一个面板的标题行上释放 → 重新排序：根据方向插入
    到目标的前面 / 后面。
  - 在另一列面板的主体上释放 → 移动到该组，并在 drop 行处分割
    目标面板。
  - 在两个组之间的 2 格间隙释放 → 在该位置创建新组。
  - 在最右组之外释放 → 作为新的最后一组追加。
  - 拖拽过程中，粗 `━` 线标记水平 drop 区（列内 resize / split），
    粗 `┃` 线标记垂直 drop 区（组之间的新列）。
  - 拖拽过程中按 `Escape` 取消。

## 状态栏

状态栏用于显示活动面板的附加工作信息。
根据活动面板的类型，显示相应的数据。
后台文件操作的进度和磁盘空间指示器靠右对齐；在较窄的终端中，面板自身的文本会被截断并以 `…` 结尾，以保证这些内容始终可见。

### 磁盘空间指示器

状态栏在右侧显示磁盘空间信息，格式为：`设备名 已用/总计GB (使用率%)`，根据使用水平进行颜色编码：

**颜色编码：**
- **绿色** 磁盘使用率 < 50%
- **黄色** 磁盘使用率 50-75%
- **红色** 磁盘使用率 > 75%

**格式：** `设备名 已用/总计 (使用率%)`

示例：`NVME0N1P2 386/467Gb (83%)`

设备名称从文件系统自动检测：
- Linux 上：显示分区名称，如 `NVME0N1P2`、`SDA1` 等
- macOS 上：显示磁盘容器标识符（例如 `DISK3`）
- 显示的设备对应当前目录所在的存储池

磁盘窗口每个存储池一行，第二列为文件系统类型。在 macOS 上，同一容器的所有 APFS 卷（`/`、`/System/Volumes/Data`、`Recovery`……）共享同一可用空间，因此合并为一行报告，而不是重复相同的数字。

## 键盘导航和面板管理

| 快捷键 | 操作 |
|-------------------|--------------------------------------------|

### 命令面板

`Ctrl+P` 列出所有命令。输入内容会按命令名称、类别和快捷键进行模糊匹配过滤，最佳匹配
在前，匹配的字母高亮显示：`gitlog` 会找到 *Open Git Log*。过滤器采用 fzf 语法——以
空格分隔的多个词必须全部匹配，`'word` 按字面匹配，`^word` 匹配开头，`word$` 匹配
结尾，`!word` 表示排除。小写字母匹配任意大小写；大写字母只匹配其本身。

### 打开提示

`Ctrl+G`（或 **窗口 ▸ 打开…**）要求输入文件路径、目录、数据库 URL 或 `http(s)://`
地址，并在对应的面板中打开。它在除两种面板外的所有面板中都可用：文件管理器将 `Ctrl+G`
留给自己的*转到路径*（提供相同的建议），终端则将其传给其中运行的程序。相对路径以
聚焦面板的目录为基准。

输入框下方的列表随输入而变化：

- 名称（`hpprov`）会与项目中的文件进行模糊匹配——git 忽略的文件和 `.git` 本身除外
  ——最佳匹配在前，语法与[命令面板](#命令面板)相同；
- 路径（`/`、`~/`、`./`、`../`）从其所在目录补全，目录在前；
- URL 不显示列表。

`↑` / `↓` 选择建议，`Tab` 将其填入输入框（目录随后会列出其内容），`Enter` 打开它
——列表为空时则打开输入的文本。单击可直接打开某个建议。

### Caps Lock

Termide 通过 `KeyboardEnhancementFlags::DISAMBIGUATE_ESCAPE_CODES | REPORT_ALTERNATE_KEYS | REPORT_EVENT_TYPES` 启用 [Kitty 键盘协议](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)。`REPORT_EVENT_TYPES` 会在每次按键事件中附带 `KeyEventState::CAPS_LOCK`，热键匹配器据此忽略 X11/Linux 终端在 Caps Lock 开启时强行附加的虚假 `Shift` 修饰符。

实际效果：

- 开启 Caps Lock 时 `Alt+T` 这类绑定依然生效（否则事件到达时是 `{Char('T'), Alt|Shift}`，无法匹配 `{Char('t'), Alt}`）。
- 真正的 `Shift+字母` 绑定（例如 `Ctrl+Shift+F` 用于内容搜索）仍与无 Shift 版本区分清楚——只在真的报告了 Caps Lock 时才剥离 Shift。
- 不支持 Kitty 协议的终端（不发送 Caps Lock 位）会回退到严格的修饰符比较，行为保持不变——在这些终端中建议关闭 Caps Lock 使用。

内嵌终端模拟器的方向键和 Home/End 的修饰编码见 [terminal.md](terminal.md#交互操作)。
