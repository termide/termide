# 密码库

TermIDE 将远程连接的密码保存在一个由主密码保护的加密密码库中，因此书签和已保存的布局都无需包含密码。

密码库用于：

- **远程文件系统** — SFTP、FTP、FTPS（参见 [VFS](vfs.md)）。
- **数据库** — PostgreSQL 和 MySQL（参见[数据库查看器](database.md)）。
- **通过 HTTPS 的 Git** — push、pull 和 fetch 所用的用户名和密码或令牌。
- **通过 SSH 的 Git** — SSH 密钥的密码短语。

## 工作方式

1. 连接被拒绝：SFTP 在尝试 SSH agent 和密钥之后，FTP 在匿名登录之后，数据库在无密码登录时，git 在没有凭据时。
2. 如果密码库中保存了该服务器和用户的密码，TermIDE 就使用它。密码库处于锁定状态时，会先询问主密码。
3. 否则 TermIDE 会询问密码。勾选 **保存到密码库** 即可保存它。
4. 要求保存的密码只有在服务器接受之后才会写入，因此输错的密码永远不会进入密码库。
5. 第一次保存时创建密码库。您设置主密码并输入两遍。

如果已保存的密码被拒绝（例如在服务器上已被修改），TermIDE 会再次询问。此时复选框已勾选，新密码会替换旧密码。

取消主密码提示并不会取消连接，TermIDE 会改为直接询问登录密码。

密码按服务器归档：scheme、主机和端口（省略默认端口）加上用户名。数据库密码属于服务器登录，而不属于某一个数据库，因此在面板中切换数据库时仍能找到它。git 使用的 SSH 密钥的密码短语保存为一个条目。

## URL 中带密码的书签

添加或编辑 URL 中包含密码的书签（`postgres://user:secret@host/db`）时，TermIDE 会提议将密码移入密码库。回答 **是**：

- 密码被保存到密码库；
- 保存成功后，书签会被改写为不含密码的 URL。

这样项目书签（`.termide/bookmarks.toml`）就可以放心提交。

## 锁定

已解锁的密码库在 15 分钟未使用后自动锁定。可在 **设置 → VFS → 密码库自动锁定时间** 中修改延迟，或在 `config.toml` 中设置：

```toml
[vault]
lock_after_mins = 15   # 0 表示在 termide 退出前保持解锁
```

命令面板中的 **锁定密码库** 会立即锁定它。

[可分离实例](detached-instances.md)将已解锁的密码库保存在服务器进程中；客户端永远不会收到它。

## 密码库文件

密码库是 `~/.config/termide/vault.toml`（仅所有者可访问）。每个用户只有一个密码库，不会按项目区分。

- **机密是加密的。** 它们使用临时 X25519、HKDF-SHA256 和 XChaCha20-Poly1305 密封到一个 X25519 密钥对。私钥使用由主密码经 Argon2id（64 MiB，3 轮）派生的密钥加密。
- **保存无需解锁。** 保存只用到公钥，因此 TermIDE 只在确实需要已保存的密码时才询问主密码。
- **元数据可读。** 类型、服务器和用户名以明文保存，因此 TermIDE 无需解锁即可判断是否存在密码。它们与加密的机密绑定：被篡改的条目会解密失败，而不会把密码发送到另一台主机。
- **并发写入是安全的。** 多个 TermIDE 进程可以共享密码库。写入是原子的，并由锁文件串行化。

**忘记的主密码无法找回。** 删除 `vault.toml` 即可重新开始；已保存的密码也随之丢失。

## 防护范围

密码库保护密码不被读取您的配置文件、备份、同步的 dotfiles 或提交了书签文件的仓库的人获取。

它无法防护在密码库解锁期间以您的用户身份运行的程序：这样的程序可以读取 TermIDE 的内存或记录您的按键。

## 限制

- 不含用户名的 FTP URL 会匿名登录，其提示只询问密码。请将用户写入 URL（`ftp://user@host`）。
- 目前还没有已保存条目的列表或编辑器。要删除条目，请删除密码库文件。
- 不保存加密压缩包的密码。
