# 编码代理

TermIDE 内置了一个编码代理：在这个面板里，你用自然语言描述任务，语言模型通过读取文件、编辑文件并在项目中运行 shell 命令来完成它。代理的每个可能改变内容的操作都会先征求你的许可。

用 `Alt+A`、**窗口 → 代理** 或命令面板（**打开代理**）打开它。

## 配置模型

代理通过**连接**访问模型：OpenAI 兼容端点、Anthropic Messages API 或 CLI 代理。OpenAI 协议覆盖本地服务器（llama.cpp、Ollama、vLLM、omlx）以及大多数托管网关，其中包括 OpenAI 和 OpenRouter。默认没有任何连接；在创建连接之前，面板拒绝打开并给出提示。

```toml
[ai]
connection = "local"               # 新会话使用的连接；未设置时按名称取第一个
max_tokens_per_turn = 0            # 默认：不限制，由模型决定
reasoning = "high"                 # 默认；off | minimal | low | medium | high | xhigh | max
fold_blocks = "immediately"        # immediately（默认）| on-finish | never
bell_on_attention = true           # 默认；不在视线内的面板等待你时响铃

[ai.connections.local]
provider = "openai_compatible"     # openai_compatible（默认）、anthropic_compatible、claude_code、codex、gemini_cli
base_url = "http://127.0.0.1:10000/v1"
model = "Qwen3.8-Flash-Next-oQ4e-mtp"  # 省略时：提供方列出的第一个模型
# api_key_env = "OPENAI_API_KEY"   # 变量名，绝不是密钥本身
# context_window_fallback = 32000  # 仅在服务器未报告窗口大小时使用
# prefill_progress = true          # 向 llama.cpp 服务器请求提示词处理进度
# reasoning_param = "enable_thinking"  # auto（默认）| reasoning_effort | enable_thinking | none

[ai.connections.cloud]
provider = "anthropic_compatible"
model = "claude-sonnet-5"
api_key_env = "ANTHROPIC_API_KEY"

[ai.connections.codex]
provider = "codex"                 # CLI 代理无需其他设置
```

连接包含 `provider`、`base_url`、`model`、`api_key_env`、`context_window_fallback`，以及 `openai_compatible` 专用的 `prefill_progress` 和 `reasoning_param`；省略的字段取其默认值。`prefill_progress` 会在每个请求中发送 `return_progress`，llama.cpp 以其提示词处理进度作答；它默认关闭，因为不认识该字段的服务器（包括 OpenAI 自己的 API）可能拒绝请求。`[ai]` 中的其他设置——输出上限、推理、权限、压缩等——无论会话使用哪个连接都生效。

`reasoning` 是新会话请求的推理级别：`off`、`minimal`、`low`、`medium`、`high`（默认）、`xhigh` 或 `max`。每个模型只提供其 API 接受的级别，缺少的级别会落到它拥有的最接近的级别：Claude Opus 5.5 和 Fable 无法停止思考，因此 `off` 得到它们的最低努力程度；在上限为 `high` 的模型上，`max` 变为 `high`。在 Messages API 上由模型决定形式：Claude 4.6 及更新版本使用自适应思考及其努力程度（并请求推理摘要，否则较新的模型不会返回），Claude 4.5 及更早版本以及网关自己的模型使用思考预算。OpenAI 兼容连接把级别放在其 `reasoning_param` 指定的字段中：`reasoning_effort`（OpenAI 的模型有各自的取值集合，其他模型为 `low`、`medium` 和 `high`）、`enable_thinking`——即 `chat_template_kwargs.enable_thinking`，vLLM 或 llama.cpp 上 Qwen3、GLM 和 DeepSeek 聊天模板的开关——或 `none`。默认值 `auto` 向 OpenAI、OpenRouter 和 Gemini API 发送 `reasoning_effort`，向本机或局域网内的服务器（`localhost`、`.local` 名称、回环或私有地址）发送 `enable_thinking`——本地模型因此也有 **Reasoning** 标签——对其他服务器不发送任何内容，因为它们可能拒绝不认识的字段；不被发送任何内容的模型按其服务器的设置进行推理，也没有 **Reasoning** 标签。旧的 `prefer_reasoning = true | false` 仍然可读，分别读作 `high` 或 `off`。

设置模态窗口（齿轮按钮或命令面板）在 **AI** 下包含全部设置。最前面是**连接**：每一行显示一个连接的名称、提供方和模型，新会话使用的那个标有 `●`。`Enter` 或单击会在独立页面中打开该连接——名称、提供方、基础 URL、API 密钥变量、模型、上下文窗口、**预填充进度（llama.cpp）**和**推理参数**（仅 OpenAI 兼容连接）以及**默认使用**（新会话使用它）——**[ 返回列表 ]**、`Esc` 或 `Backspace` 返回列表；**+ 添加连接** 添加一个 OpenAI 兼容连接，页面上的 **[ 删除连接 ]** 或其行上的 `Del` 删除连接。始终恰好有一个默认连接：第一个添加的连接即为默认，之后的连接只有在你打开其开关时才会接替；关闭开关（或删除默认连接）会把默认身份交给按名称排序的第一个其他连接。新连接在你命名之前以其提供方命名。模型是一个下拉列表：最前面是**自动（由提供方决定）**，然后是该连接的模型（页面打开时在后台获取），最后是“输入模型 ID…”，用于端点无法列出模型时手动输入。自动（即连接的模型留空）会使用提供方列出的第一个模型（CLI 代理则使用其自身的默认模型）；在列表返回之前发送的请求会带着提示停留在输入框中等待。文本字段的编辑方式与 termide 中所有输入框相同：光标按字符和单词移动，`Shift` 或鼠标拖动进行选择，`Ctrl+C`/`Ctrl+X`/`Ctrl+V`、`Ctrl+A` 和撤销均可用。

API 密钥从 `api_key_env` 指定的环境变量中读取，因此配置文件从不保存机密。本地服务器通常根本不需要密钥；不设置该变量即可。`fold_blocks` 决定推理和工具调用何时折叠为一行标题：`immediately` 在它们仍在运行时就折叠（运行中的推理块显示其最新一行），`on-finish` 在完成前完整显示，`never` 让所有块保持展开；无论哪种方式，选中的块都可以用 `Enter` 或再次单击展开。设置模态窗口中该项为**折叠区块**。旧的 `autofold = false` 读作 `never`，`true` 读作 `on-finish`。当 `max_tokens_per_turn` 为零或负数时，不发送输出上限，由模型决定回复长度；Anthropic API 要求必须提供上限，因此在那里它会变为宽裕的 32000。

在连接出现之前编写的配置，即 `provider`、`base_url`、`model`、`api_key_env` 或 `context_window_fallback` 直接位于 `[ai]` 下，会被读作一个名为 `default` 的连接，新会话使用它；下次从设置模态窗口保存时会以新格式写入。

横幅中的连接行和状态栏的 **Connection** 标签可将会话切换到另一个连接：其端点和模型替换当前使用的，代理在同一日志上重启并延续对话，委派的任务也随之切换。CLI 代理（`claude_code`、`codex`、`gemini_cli`）不会接管已有对话，因此切换到它或从它切换只能在首次请求之前进行。会话日志记录连接，因此重新打开的会话在该连接仍存在于配置中时会重新连接到它，否则连接到新会话使用的那个。

对于托管的 OpenAI 兼容端点，保持 `provider = "openai_compatible"`，并将连接的 `base_url` 和 `api_key_env` 指向它，例如 OpenAI 本身（`https://api.openai.com/v1`、`OPENAI_API_KEY`）、OpenRouter（`https://openrouter.ai/api/v1`、`OPENROUTER_API_KEY`）或 Gemini API（`https://generativelanguage.googleapis.com/v1beta/openai`、`GEMINI_API_KEY`）。模型为工具调用附加的签名（Gemini 的 thought signature，位于调用的 `extra_content` 中）会保存在会话日志里，并按端点的要求随该调用一并发回。对于 Anthropic 订阅，设置 `provider = "anthropic_compatible"`，去掉 `base_url`（API 根地址已内置；仅在使用网关时设置），并将 `api_key_env` 指向你的 `ANTHROPIC_API_KEY`；此时推理级别会让模型进行思考。**Model** 标签会列出各端点的模型。

`provider = "claude_code"`、`provider = "codex"` 和 `provider = "gemini_cli"` 在性质上不同：面板不是用内置循环与模型端点对话，而是通过 ACP 把该工具自己的 CLI 作为[外部代理](#外部代理)来驱动（`@agentclientprotocol/claude-agent-acp` / `@agentclientprotocol/codex-acp` / `@google/gemini-cli --acp`，最新版本，通过 `npx` 运行）。端点和登录由 CLI 负责——使用它自己的订阅或 API 密钥——因此连接的 `base_url`、`api_key_env` 和上下文窗口不适用；设置模态窗口会为这些提供方隐藏它们，并从文件中清除。`model` 保留：它是代理上**预选**的模型——会话启动后通过 ACP 应用——运行时 **Model** 标签会列出并切换该代理自己的模型。必须先安装该工具并登录（`npx` 需在 `PATH` 中）；termide 本身不执行登录，因此请先单独运行一次 Gemini CLI（`npx @google/gemini-cli`）并选择登录方式。

termide 会在这些代理允许的范围内尽量接管它们，使会话无论使用哪个连接都表现一致：

- **Claude Code** 使用 termide 的系统提示词代替它自己的，并调用 termide 的工具（通过本地 MCP 服务器提供）代替它自己的工具。它的内置工具和它自己的设置——其规则、钩子、`CLAUDE.md` 和 MCP 服务器——都不使用。每次调用都在 termide 中运行，经过与内置循环相同的检查：权限模式、规则、会话内的回答、计划模式以及 `/undo` 检查点。
- **Codex** 保留自己的系统提示词和工具；termide 把它置于与面板对应的模式（`ask`、`configured` 和 `auto`：请求批准；`plan`：同上并加上其计划协作模式；`edit`：替我批准；`all`：完全访问），并决定它询问的内容。
- **Gemini CLI** 同样保留自己的系统提示词和工具；termide 把它的批准模式设为与面板对应的模式（`ask`、`configured` 和 `auto`：`default`，在编辑和执行命令前询问；`plan`：`plan`，若 Gemini 未开启计划模式则为 `default`；`edit`：`autoEdit`；`all`：`yolo`），并决定它询问的内容。

三者都保留自己的对话循环：它们自行压缩上下文，运行不能在步骤之间暂停，也没有预填充和生成计时（令牌总数在代理报告时显示，Claude Code 会报告）。**权限** 标签对三者都有效。设置模态窗口在连接页面中也有同样的说明。

## 使用面板

会话占满面板，输入框位于底部，其上方带标题的边框显示代理名称（`─ default ─`），便于区分并行的多个代理面板。长行按面板宽度换行，输入框随之增高——最多到面板高度的一半——然后才开始滚动。与新终端一样，代理在打开它时拥有焦点的面板所在的目录中工作（文件管理器的目录、编辑器中文件所在的目录），否则在项目根目录中工作。面板标题是你的第一个请求，因此多个代理面板一眼就能区分；在你提问之前，标题显示工作目录。标题超出面板宽度时截去末尾，因此面板越宽显示得越多。通过面板的 `[≡]` 菜单 → **重命名会话** 给会话起一个自己的名字，此后标题就显示该名字。

新会话以横幅迎接你：左侧是一个小徽标，右侧是代理的配置。横幅的标题是代理的名称，定义中有描述时其下显示该描述（默认代理除非另有定义，描述为“代理”，即面板标题的标签）；再往下是它工作的目录、连接、模型和可用的工具，每项都位于随你设置的语言显示的标签下。代理名称、连接、模型和工具以强调色粗体显示：单击任一项都会打开与其状态栏标签相同的选择器，因此你可以在开始前配置会话。面板空闲时，目录也以这种方式显示：单击会打开目录选择器（在其中按 `.` 显示隐藏目录），面板就地移到所选目录——会话日志随之移动，因此已选的连接、模型和代理保持不变，而项目代理、技能、钩子以及下方的会话列表都换成该目录的。再往下，在会话标题下方，是本目录的其他会话列表，最新的在前，每个会话附有最后一次更改的本地日期和时间；列表从徽标所在的列开始，让标题能使用面板的全部宽度，占满面板可用的空间，其余部分用滚轮滚动。已在另一个面板中打开的会话不会列出，待那个面板释放它后才会回来。单击某个会话会打开它，取代空会话；用键盘时，`Tab` 进入列表，方向键、`PgUp`/`PgDn` 和 `Home`/`End` 在其中移动，`Enter` 打开光标处的会话，`F2` 重命名它，`F8` 或 `Delete` 在确认后删除它，`Tab` 或 `Esc` 返回输入框。在此之前面板报告的内容——某个 MCP 服务器已连接、某个 `/name` 被定义了两次——显示在横幅下方的虚线之后，最新的保持可见；会话列表会先为它们让出行。每个 MCP 服务器在那里只占一行，随变化就地改写：它的工具及其中开启了多少、正在连接、需要登录。发送第一条消息后，横幅即让位于对话，这些行留在对话开头；此后每次变化都单独占一行——服务器重新连接或更换了工具、应用了工具集（`mcp github：已启用 3/12 个工具`、`已关闭的工具：bash；已开启：—`）——因为从那里起模型拥有的是另一组工具。

**Tools** 标签（以及横幅中的工具行）会打开一个清单，列出会话可以使用的内容：内置工具、技能，以及每个 MCP 服务器连接后提供的工具。每个分组起初都折叠为标题行，标题显示其中已启用的项数（`▶ [-] MCP github  3/12`）：`→` 或单击箭头展开，`←` 折叠（在某一项上则跳到其分组标题）。分组标题上的复选框会一次性开启或关闭整个分组，无论是否展开，部分开启时显示 `[-]`。无论以何种方式关闭清单——`Enter`、`Esc` 或在窗口外单击——都会应用所选内容。每个已配置的 MCP 服务器都有一个标题，未连接的也有——名称旁显示其状态（“需要登录”、“失败：…”）——右端有按钮，排成一列：`[↻]` 重新连接它（在标题上按 `r`），使用 OAuth 登录的服务器上 `[⇥]` 登录或 `[⇤]` 退出（`l`）位于其左侧。按钮会像 `Enter` 一样应用勾选、关闭清单并执行相应操作。清单打开时连接上的服务器会当场出现在其中——其标题去掉状态说明，下面列出它的工具——不必关闭再打开清单就能看到服务器的状态；你已勾选的保持不变。在首次请求前取消勾选某项，会让它完全不进入模型的上下文——其描述和模式从不发送，既节省令牌，也移除了该能力。在会话后期取消勾选的项仍留在上下文中，以免丢弃提供方的提示缓存，但对它的每次调用都会被拒绝；它会在缓存反正要失效的下一个时刻离开上下文——压缩、切换代理或模型——并且在该会话中无法重新打开。该集合保存在会话日志中，因此重新打开的会话会恢复它。通过 ACP 接入的外部代理自带工具，因此没有这个清单。

面板的 `[≡]` 菜单只保留在别处没有入口的操作——**会话信息**（也可用 `F3` 和 `/usage`）、**重命名会话**、**将聊天保存为 Markdown…**（也可用 `Ctrl+S`）、**分叉会话**（也可用 `F5` 和 `/fork`）和 **删除会话**。组装后的系统提示词用 `/prompt` 打开。保存聊天会通过“另存为”对话框写出对话，文件以会话命名：每一天各有一个标题，其下你的每条消息和代理的每个回答都位于 🧑 或 🤖、作者名（自定义代理用自己的名字）和时间组成的标题下。推理、工具调用及其输出、面板的提示行都不包含；以 `/name args` 发送的消息按你输入的样子保存。保存的是整个分支，包括已压缩的部分。会话管理改在功能键和 AI 菜单中：`F7` 开始新会话，`F6` 打开本目录会话的选择器（最新的在前，当前会话标有 `●`），`F5` 分叉当前会话，`F8` 在确认后删除它，`F2` 重命名它。切换会等待当前任务结束：如果代理仍在工作，先用 `Esc` 停止它。分叉不需要运行做任何配合，因此代理忙碌时也可以进行。

分叉会复制会话日志，并在一个新的代理面板中打开副本；新面板从对话当时所处的位置接着进行——同样的消息、同样的代理和模型——而你分叉出它的那个面板继续在自己的日志上工作。两者在那一刻分开：各自继续写自己的文件，于是同一段对话现在在两处进行，你可以让代理并排尝试两种方案。副本有自己的名字——源会话的名字加上序号，`Refactor` 变为 `Refactor (2)`，然后是 `Refactor (3)`——因此两者在选择器和面板标题中都能区分；你随时可以重命名任一个。副本和其他会话一样：其面板释放它之后，它会出现在会话选择器和新面板的横幅中，你也可以切换回它。

在输入框中，`/new` 开始新会话（保留当前会话），`/fork` 把当前会话复制到新面板中，`/clear` 也开始新会话，但会先删除当前会话；`/rename`（或 `/name`）重命名会话。模型、代理和权限模式的选择器就是状态栏标签。

从未发送过任何内容的会话会在你切换离开或关闭面板时被丢弃，因此打开面板再关闭——或试几个新会话——不会在列表或磁盘上留下杂乱的空日志。命名过或发送过哪怕一条消息的会话始终会保留。

| 按键 | 操作 |
|---|---|
| `Enter` | 发送。代理工作时，文本改为排队到下一轮，并在输入框上方的状态条中等待 |
| `Shift+Enter`、`Alt+Enter`、`Ctrl+J` | 在输入框中换行 |
| `Esc` | 停止正在运行的任务；没有任务运行时清空输入；输入框也为空时，选择要回退到的消息（见[回退到某条消息](#回退到某条消息)）。`Esc` 从不关闭代理面板 |
| `Ctrl+O` | 展开或折叠所有块，之后的新块也随之 |
| `Tab` | 在输入框和对话之间移动焦点；在对话中，`↑`/`↓` 选择块，`Space`/`Enter` 折叠或展开它，`→`/`←` 像文件管理器的目录树一样展开或折叠它，`o` 在独立面板中打开它；在新会话的横幅上，`↑`/`↓` 选择最近的会话，`Enter` 打开它 |
| 单击块 | 聚焦对话并选中该块（选中的块反色显示，成功和错误颜色保持其色调）；再次单击折叠或展开 |
| Ctrl+单击 URL | 在浏览器中打开它 |

对话由一叠块组成，每个块以强调色标记开头：`› ` 表示你的消息和代理的回答，`@ ` 表示推理，`$ ` 表示 shell 调用，`< ` 表示读取文件，`> ` 表示写入，`± ` 表示编辑，`/ ` 表示技能，`& ` 表示子代理，`* ` 表示 MCP 工具，`¿ ` 表示向你提问，`# ` 表示系统提示词。回答完整显示；超过五行的用户消息或系统提示词会折叠为预览，保留第一行和最后几行，中间是 `… 还有 N 行` 的说明。五行及以下的块没有什么值得隐藏的，因此完整显示且没有折叠标记；展开后只占一行的已完成块也是如此。已完成的工具调用折叠为一行：只有其标题（shell 调用的第一行命令）；耗时（`🕒`）在展开后显示。单行不带 `✓`；失败的调用改为用错误颜色显示标题，其展开形式以 `✗` 结尾。时长从秒增长到分钟、小时和天（`2s`、`1m13s`、`2h5m`、`3d4h`）。已完成的推理以同样方式只折叠为第一行；展开后显示 `⏫`/`✍️` 两行。仍在进行中的块——流式输出中的推理、带实时输出的运行中工具调用——始终展开显示，只有完成后才折叠。你的消息以浅色背景上的普通文本显示；推理、系统提示词和工具输出是暗淡文本，但编辑的差异除外，其着色方式与 Git 差异面板相同。每个步骤以其类型符号和同一强调色的本地化动作开头，然后是其对象：推理显示为 `@ 思考` 和其文本，shell 调用显示为 `$ 执行` 和其命令（暗淡，按宽度换行），文件工具显示其路径（`< 读取 src/main.rs`、`> 写入`、`± 编辑`），网络工具显示 URL 或查询（`↓ 获取 https://docs.rs`、`? 搜索 ratatui scrollbar`），技能显示其名称和参数（`/ 使用技能 review src/x.rs`），子代理显示其名称和任务的第一行（`& 委派给 reviewer: check the diff`），MCP 工具显示其服务器、名称和 `key=value` 形式的参数（`* 使用 MCP github: create_issue title=Crash`）；其他工具显示其名称和摘要。推理是回答上方的独立块，其文本按宽度换行。只有系统提示词以一条暗淡的虚线开头，把它与前一个块隔开；注释行没有虚线，由其符号标记。你的消息之后有一个空行，回答之前也有一个，后面还有步骤的回答之后也有一个；其间的推理和工具调用紧密堆叠，没有间隔。折叠的块标有 `▸`，展开的标有 `▾`，紧跟在步骤的动作之后（`@ 思考 ▸`、`$ 执行 ▸`、`< 读取 ▸ src/main.rs`）或系统提示词的 `#` 之后（`# ▸`）。

运行期间，运行时钟右对齐位于最后一个块下方：一个动画 `✽` 和自发送请求以来的时间。它使用自己的符号而不是 `🕒`，因为每个块下方的数字只描述该块本身，而这个是整次运行的总计。运行结束时，时钟停在原处并变暗，因此静止的 `✻` 不会被误认为仍在工作。以回答结束的运行把它保留在回答的元信息中（`✻ 3m41s`），位于回答自身的时间和 `✓`/`✗` 下方——包括失败调用的错误。回答无法说明结束情况的运行（以工具调用结束，或在一次正常回答之后被中止）会把它作为最后一个块之后的结束行保留，附带结束时间和结束方式：`✻ 3m41s · 21:03:41 ✗`。

`/pause` 在当前进行中的工具调用或模型回复完成后立即生效——而不是在整个步骤结束时，因此获取多个页面的步骤会在当前页面之后停止。它留下未运行的调用会等待 `/continue`，后者会先运行它们；新的请求则会把它们作为未运行关闭。用 `/pause` 停止的运行改为显示暂停行 `‖ 1m12s`：它计算暂停已持续的时间，暂停期间 `‖` 高亮，运行继续后保留该时长并变暗。继续后的运行的时钟从原始请求开始计算，因此总时长包括暂停。运行控件位于输入框上边框的右端，无论对话记录如何滚动都可见：代理工作时，`[‖]` 暂停运行（同 `/pause`），`[■]` 停止运行（同 `Esc`）；一旦请求了暂停，`[▶]` 取代 `[‖]` 并撤回该请求（单击状态条中的相应提示或 `/continue` 也可以）；暂停期间，`[▶]` 继续运行（单击暂停行或 `/continue` 也可以），`[■]` 放弃已暂停的运行（它留下未运行的调用由下一个请求关闭）。Claude Code、Codex 和 Gemini CLI 运行自己的循环，无法在步骤之间停止：它们只显示 `[■]`，`/pause` 会说明这一点。控件静止时使用面板边框的强调色；`[▶]` 为绿色。一旦按下 `[■]`（或 `Esc`），停止就无法撤回：在运行真正停止之前，只保留一个红色的 `[■]`，再次按下不起作用。

结束行是注释的一种——注释是标记对话中某个时刻而不承载内容的行。其他注释是面板的提示：`·` 表示信息（切换模型、压缩完成），`!` 表示警告（目标已停止、代理忙），`✗` 表示块之外的错误（压缩失败、MCP 错误）。一轮中的错误留在其回答块中。注释从不折叠。提示的文本在其符号下按宽度换行；对话光标可以停在提示上，因此错误可以像块一样被选中和复制，而光标会跳过运行的结束行。

表示当前状态而非已发生事件的内容位于状态条中：这是对话和输入框之间的几行，只在有内容可显示时出现：待生效的暂停（`‖ 将在当前步骤后暂停；输入 /continue 取消`）——暂停生效后由对话记录中的 `‖` 行接替——以及代理工作期间排队的每条消息（`› …`，其第一行；超过三条时显示其余的数量）。所有排队内容会一次性发给代理，作为一条消息，各部分以空行连接——代理工作时输入的消息通常是对同一想法的补充——随后离开状态条，作为你的消息出现在对话中。在代理取走之前，在输入框第一行按 `↑` 会把队列取回输入框，放在已输入内容之前，以便发送前编辑。

生效的系统提示词在会话开始时显示为一个折叠的 `# ` 块，并在你下一条消息之前它发生变化时（例如切换代理或模式）再次显示，因此模型收到的指示始终可见。

你的消息和代理的回答各以一个暗淡、右对齐的时间和 `✓`/`✗` 状态结尾（`18:34:01 ✓`），放得下时位于文本最后一行的末尾；推理块和工具块只带其工作数据，不带时钟时间，并且只在展开后显示。工具调用显示其耗时（`🕒 6s`）和状态。等待过权限询问的调用会把这段等待单独放在前面，作为它本来的暂停：`‖ 12s 🕒 2s`，询问期间 `‖` 高亮并计时；`🕒` 只计算调用本身的运行时间。当一轮包含推理时，推理块承载该轮的开销——预填充阶段（`⏫ 6s (↑42k, 7k tok/s)`）和生成阶段（`✍️ 12s (↓5k, 420 tok/s)`），各带其时长（整秒）、令牌数和平均速度；大数字会缩写（`40k`、`1.2M`）。没有推理的轮次改为在回答上显示这些数据。一轮仍在运行时，同一右对齐元信息区域显示实时数据：在第一个令牌到来之前，是一行 `⏫` 预填充数据，包括模型已读取提示词的时长和提示词大小的估计（`⏫ 14s (↑~48k)`），或者对于报告进度的服务器（`prefill_progress`），显示一个进度条，带有已读取的令牌数和未由其缓存提供的令牌的速度（`⏫ 14s ▰▰▰▰▱▱▱▱ (↑24k/48k, 1k tok/s)`）；令牌开始流出后，是一行 `✍️` 生成数据，包括运行时长、估计令牌数和速度；两者之下都是运行时钟。准确的输入令牌数和预填充速度随完成的块显示。外部代理没有实时预填充行，因为其消息从第一段文本开始。重新打开对话会从日志中恢复每个块的时间、其推理、该轮的预填充/生成行以及每个工具调用的耗时。

展开一个块以查看全部内容：单击它，或按 `Tab` 进入对话并在 `↑`/`↓` 光标所在的块上按 `Space`/`Enter` 或 `→`（`←` 将其折叠回去）；`Ctrl+O` 一次展开全部，之后到来的块也保持展开；再按一次则全部折叠回去，新块重新按 `fold_blocks` 折叠（若其为 `never`，则在完成时折叠）。`o` 在独立的只读面板中打开选中的块以便查看（保存了完整日志的命令会打开该文件）。`Tab` 或再次单击输入框可将焦点返回输入框。面板跟随最新输出，直到你向上滚动；滚回底部时恢复跟随。

要复制整个块，选中它（单击或移动到它）并按 `Ctrl+C`。在输入框中，`Ctrl+C` 改为复制那里选中的内容——选中的文本反色显示，因此复制会取走什么一目了然。

鼠标选择在输入框内有效：按下放置光标，拖动选择（可跨越换行的行），松开，然后复制或剪切。在对话记录中，拖动像终端那样选择文本，从起始单元格到指针下的单元格，拖过边缘时会滚动；`Ctrl+C` 复制它，每行去掉末尾的填充。不拖动的单击（在松开时生效）则选中其下的块并清除文本选区。

代理运行的内容会被干净地提供给模型：颜色和光标转义序列、进度条重绘、旋转指示器帧以及大段几乎相同的构建输出行，在进入上下文前会被去除或合并，因此嘈杂的命令花费的令牌少得多。测试运行——Rust（`cargo test`、`cargo nextest`）、Python（`pytest`）、Go（`go test`）或 JS/TS（`jest`、`vitest`）——会丢弃通过和跳过的测试行，保留失败和结果摘要。完整、未经处理的日志仍会写入一个文件，工具会报告其路径，你在面板中也仍能实时看到原始输出流。

状态标签从左到右依次为：代理、权限模式、**Reasoning** 级别（无法请求推理的模型没有该标签）、带协议的连接（`local · OpenAI Compatible`）以及模型。会话的令牌总数和上下文窗口靠右对齐；在窄终端上被截断的是左侧的标签，而不是这些。总数中，`↑` 是按全价计费的提示令牌（未缓存的输入和写入提示缓存的部分），`↻` 是缓存提供的令牌（有了才显示），`↓` 是输出：`↑2.1k ↻48k ↓900`。窗口显示已用令牌数和填充条，`35k/262k ▰▰▱▱▱▱▱▱`；对于 Claude Code、Codex 和 Gemini CLI，两者都来自代理的报告，窗口在代理报告后显示。代理、模式、推理、连接和模型都是按钮。单击 **Reasoning** 会列出模型提供的级别（只有开关的模型则直接切换），所选级别从下一个请求起生效；该选择记录在会话中，因此恢复会话时会一并恢复，切换模型时也会保留，并落到新模型最接近的级别。代理此刻在做什么不会在状态栏中重复：每个对话块都在其署名行中显示。

输入 `/` 会在输入框上方打开匹配的提示词模板列表；`↑`/`↓` 在其中移动，`Tab` 或 `Enter` 补全高亮项，在完整输入的名称上按 `Enter` 则直接发送。

输入 `@` 会打开同样的列表，但列出的是面板目录下的文件和目录，因此输入路径只需几次按键：`@ma` 会找到 `src/main.rs`，字母不必相邻（`@srmain`）。git 忽略的内容不会列出，隐藏条目只有在输入 `.` 时才会列出。`Tab` 或 `Enter` 插入高亮项；目录以 `/` 结尾，并会重新打开列表显示其内容，便于逐级深入。代理会读取你指名的文件；`@` 只是快速输入路径，不会在背后附加任何内容。

大段粘贴（超过五行或 2000 个字符）不会涌入输入框，而是以简短的 `[#1 pasted 40 lines]` 占位符代替；发送时完整文本会替换回占位符的位置，因此模型仍能收到全部内容。再次粘贴同一段内容会取消遮盖：占位符让位于完整文本，可就地阅读或编辑。较小的粘贴按原样插入。

**Model** 会向端点询问其提供的模型并列出它们，当前模型标有 `●`；最后一项允许你改为输入 ID，端点无法列出模型时也是如此。切换在你的下一个请求时生效并随会话保留：它写入会话日志——连同其所用的提供方——因此重新打开该会话会恢复其模型和提供方，新会话则从面板当前所用的模型开始。与切换会话一样，切换模型会等待当前任务结束。

**上下文窗口。** 当端点报告模型的窗口时（vLLM 和 omlx 报告 `max_model_len`），面板总会采用它——在启动时和每次切换模型时——因此 `Context:` 与服务器实际允许的一致。配置的 `context_window_fallback` 只是一个**回退值**，在端点未报告窗口时使用；未设置时在设置模态窗口中显示 `(auto)`，在提供方已知之前（或无法得知时）使用内置默认值。

**权限** 标签提供下文描述的六种模式。`Shift+Tab` 无需选择器即可在它们之间循环。更改在代理的下一次工具调用时生效，因此你可以在长任务运行期间放宽模式，而不必一遍又一遍地回答同一个询问。这两种切换都不会修改配置文件；下次面板仍从 `[ai]` 开始。

### 自己运行命令

在空的输入框中输入 `$` 会把它切换为 shell 命令：`$` 取代 `›` 标记，`Enter` 立即运行你在那里输入的内容，不询问模型。每条命令都要重新开启该模式：运行之后、按 `Esc` 或在空输入框中按 `Backspace` 都会回到消息。在 shell 模式下，`↑` 和 `↓` 浏览你之前运行过的命令，而不是消息。只是以 `$` 开头的文本——粘贴的，或前面有空格的——仍然是消息。

命令在会话目录中通过代理使用的同一个 `bash` 运行，因此过长的输出保留开头和结尾，并把完整日志写入文件。它在对话记录中显示为 shell 调用块，与代理自己的一样——折叠时为 `$ git status --short`，附带耗时，失败时带 `✗`；展开后注明是你运行的——你下次提问时，代理会读到这条命令及其输出，因此你可以接着问“这对修复意味着什么”。`Esc` 停止仍在运行的命令；运行命令从不消耗模型调用，代理忙碌时也可以运行。

你输入什么就运行什么——没有权限卡片，因为命令是你写的。区别仅此而已：代理自己的命令仍由下文的模式和规则判断，而代理向你提议的命令（见 **suggest_command**）只有在你确认后才会运行。

### 撤销请求

`/undo` 会撤回上一个更改了文件的请求：面板中的卡片会列出这些文件，确认后，每个文件都会恢复到该请求之前的状态（请求创建的文件会被删除），对话也会回退到该请求之前，因此代理也不再记得做过它。打开的编辑器会重新加载恢复的文件。重复执行可逐步回退更早的请求；未更改任何内容的请求会被跳过。这是后退一步，而不是重做：被撤销的消息作为一条废弃分支留在会话日志中，文件较新的内容则不复存在。

在 `edit` 或 `write` 运行之前，面板会在会话目录下（`ai/sessions/<path>/checkpoints/<session id>/`）保存目标文件的副本，每个请求一个文件夹，请求被撤销后再删除。shell 命令不在覆盖范围内：`bash` 做出的更改只能靠 git 或你自己的备份来保留。

### 回退到某条消息

在空输入框中、没有任务运行时按 `Esc`，会在输入框正上方列出你在本会话中发送过的消息，形式与 `/command` 补全列表相同（`F4` 随时打开同一列表）。最新的消息紧挨输入框并被选中，`↑`/`↓` 在其他消息间移动，`Enter`（或单击）选定一条，`Esc` 或开始输入则关闭列表。代理在其后更改过文件的消息会在旁边列出这些文件。选定一条消息会把对话回退到它之前，并把该消息放回输入框，供编辑后重新发送——除非你已经开始输入别的内容。如果自那条消息以来有文件被更改，一张卡片会列出它们并询问要恢复什么：文件和对话、仅对话（文件保持当前内容），或仅文件（对话保持原样继续）。文件取自 `/undo` 使用的同一批检查点，无论哪种选择，被回退越过的请求的检查点都会用掉。与 `/undo` 一样，被回退的消息作为废弃分支留在会话日志中。

## 工具

代理的内置工具如下，另加其 MCP 服务器提供的工具（见 [MCP 服务器](#mcp-服务器)）。

- **read** 返回带行号的文件内容，文件较长时用偏移量分页。
- **edit** 替换文件中一段唯一的文本，并报告变更的差异。
- **write** 创建文件或替换其全部内容。
- **bash** 在项目目录中运行 shell 命令，流式输出结果。过长的输出保留开头和结尾，完整日志写入一个代理可以读取的文件。
- **web_search** 向搜索引擎查询，返回标题、链接和摘要。
- **fetch** 加载网页并以 markdown 形式返回其文本，内容较长时像 `read` 一样分页。
- **recall** 在项目以往的代理会话、git 历史和代码中查找过去的工作、决策及其原因；见 [Recall](#recall)。

按模式搜索项目文件通过 `bash` 使用你已有的工具（`rg`、`find`）完成，而不是通过单独的搜索工具。

定义了技能时，还会出现 **skill** 工具；见[技能](#技能)。

**question** 让代理在需要由你做决定时向你提问：采用哪种方案、含糊的需求是什么意思。它最多提出四个问题，以卡片形式在面板输入框上方逐个提问。标题表明是代理在提问，附带问题的主题，有多个问题时还附带其序号（`代理提问：方案 (1/2)`）；问题本身以暗淡文字位于标题下方，然后是选项，每个选项附有一行暗淡的含义说明。一个问题可以只选一个选项，也可以多选：多选时每个选项都有一个复选框，用 `Space`、`Enter` 或其数字切换，**提交** 发送所选内容。选项之后始终有 **输入自己的回答**——你输入的一行文字，替代选项，或在可多选时与选项一起提交。`↑`/`↓`、数字和单击的作用与权限卡片相同；**拒绝并停止运行** 或 `Esc` 会告诉代理你拒绝了并停止运行，以便你用自己的消息说明想要什么。等待回答计为该调用的暂停（`‖`），与权限询问一样。提问从不需要权限，在计划模式中也是如此。只有面板自己的代理有这个工具：子代理和 `termide --prompt` 运行没有可询问的人，会自行决定。`tools` 列表中不含 `question` 的代理也不会提问。

**suggest_command** 把命令交给你，而不是自己运行。代理把命令放在一张卡片上——完整、与实际运行时完全一致的命令、提议它的理由以及目录——并标明这是代理的建议。**运行** 通过与你输入的 [`$` 命令](#自己运行命令)相同的 shell 路径运行它，输出返回给代理；**先编辑** 把它作为 shell 模式的命令放入输入框，供你修改后运行；**复制** 只取走命令文本；**不运行**（或 `Esc`）拒绝它，代理会被告知命令没有运行，且不得再次提议。被阻止的调用最终就是这样处理的：拒绝消息让代理说明它需要运行什么，而这个工具把它变成一张卡片，而不是一行需要你重新输入的文字。代理也用它移交不应由自己完成的事——发布，以及任何需要你的凭据或判断的操作。

卡片从不自行运行任何东西，也无法让你绕过自己的规则：在计划模式中，或命令被 `deny` 规则覆盖时，**运行** 和 **先编辑** 不提供，只剩 **复制** 和 **不运行**。提议命令不需要权限——它本身不改变任何东西——因此代理总能通过这种方式找到你；只有你的确认才会到达 shell。与 `question` 一样，该工具只属于面板自己的代理。

### 网络

`web_search` 和 `fetch` 通过你机器上的 Chrome 系浏览器（Chrome、Chromium、Edge 或 Brave）工作，因为搜索引擎会拒绝脚本化的请求，而且许多页面是由 JavaScript 构建的。浏览器使用配置目录下 `ai/web/browser/` 中独立的配置文件，从不使用你日常的配置文件，因此代理没有你的任何登录状态。它在无窗口模式下运行，并以有窗口时同一浏览器的身份标识自己；一个浏览器服务于所有代理面板，空闲五分钟后退出。

当搜索引擎要求确认是真人在搜索时，一个显示该页面的窗口会出现在你面前，代理的工具调用会显示正在等待：完成验证后搜索就会继续。代理的配置文件会记住验证结果，因此不会每次搜索都要求验证；浏览器空闲一段时间后会恢复无窗口运行。

没有这样的浏览器时，`fetch` 仍通过普通 HTTP 读取页面（由 JavaScript 构建的页面此时返回的内容大多为空），而 `web_search` 不可用。

```toml
[ai.web]
backend = "auto"         # auto：找到浏览器时用浏览器，否则用普通 HTTP；chrome；http
engine = "duckduckgo"    # duckduckgo、bing、google、yandex，或你自己的引擎
chrome_path = ""         # 浏览器可执行文件；为空时在常见位置查找
display = "headless"     # headless（无窗口）；minimized；visible
```

`minimized` 给浏览器一个真实但保持最小化的窗口，用于仍能识别无窗口浏览器的搜索引擎。`visible` 让窗口留在屏幕上，以便观看代理工作：每个页面都在同一个标签页中打开，该标签页停留在代理读取的最后一个页面上，因此你可以查看它或在那里打开开发者工具。关闭该标签页没有问题；下一个页面会在新标签页中打开。若想观看一段时间而不更改设置，使用 **AI** 菜单中的 **显示浏览器窗口**：浏览器会立即以可见窗口重新启动并保持可见，无论是否空闲，直到选择 **隐藏浏览器窗口**——对所有代理面板都生效，因为它们共用一个浏览器。配置文件及其 cookie 会保留。在没有显示服务器的 Linux 上，无论设置如何，浏览器都以无窗口模式运行。

每个搜索引擎都是 `ai/web/engines/` 中的一个小文件：查询要发送到的地址，以及从页面中挑出结果的 CSS 选择器。termide 自带 `duckduckgo`、`bing`、`google` 和 `yandex`，并像其他自带文件一样保持更新。当某个搜索引擎更改其页面、搜索开始返回空结果时，需要更新其文件中的选择器；用新名称创建你自己的文件即可添加搜索引擎。各个键在自带文件中有说明。

在 `plan` 和 `edit` 中，这两个工具无需询问即可运行；在 `ask` 中，以及没有规则时的 `configured` 中，它们会询问；在 `auto` 中，搜索直接运行，而 URL 可能携带数据外传的 `fetch` 交给审查者。对 `fetch` 选择超出一次的“允许”会覆盖整个站点（`https://docs.rs/*`），对 `web_search` 则覆盖所有查询。

代理编辑的文件如果正在编辑器中打开，会立即在那里重新加载，保留光标和滚动位置，除非该编辑器有未保存的更改；此时编辑器保留这些更改并标记冲突，与磁盘上的任何变更一样（见[磁盘上的变更](../en/editor.md#changes-on-disk)）。

### Recall

`recall` 搜索项目已经知道的内容——以往代理会话的日志、git 历史和文件——并把结果放在一起排序。代理借此找到以前决定、尝试或讨论过的事情（“为什么放弃了 tokio”“压缩相关的工作停在了哪里”），而无需维护一套单独的记忆：日志、提交和文件本身就是记录，该工具不写入任何内容。它同样适用于由笔记和文档组成的项目和代码项目。

- **会话**：项目在 `ai/sessions/` 下的日志（项目根目录及其下的目录），沿每个日志的活动分支搜索——被 `/undo` 或回退撤销的内容不搜索，被压缩总结过的内容仍能找到。你的消息、代理的回答、压缩摘要和交接简报权重最高，工具调用次之，推理和工具输出最低（输出只搜索前 4 KB）。面板当前所在的会话只搜索被压缩移出上下文的部分：其余内容已在上下文中。会话中执行的 `git commit` 会关联到对应的提交。
- **Git**：消息中含有查询词的提交，以及添加或删除了查询中提到的标识符的提交（`git log -S`），覆盖项目包含的所有仓库——项目所在的仓库、其子模块，或仅包含仓库的文件夹中的各个仓库，与 git 面板的发现方式相同。如果项目只是更大仓库中的一个目录，则只看到该目录的历史。
- **文件**：项目中含有查询词的笔记、文档和代码。文本文件（Markdown、纯文本、reStructuredText、Org、AsciiDoc）按散文处理：Markdown 按标题分节搜索，因此长文件的每一节——决策日志的每一条——都是独立的结果，并以其标题标注；匹配以整个段落显示，最近修改的文件排在长期未变的文件之前。其他文件按代码处理：每个文件一个结果，以匹配的行显示。与 ripgrep 一样，跳过隐藏条目、被忽略的文件和二进制文件，遍历不跨越文件系统（项目下挂载的磁盘或虚拟机的文件不会被读取）；任意大小的文件都逐行读取。项目中嵌套的每个仓库都按其自己的 `.gitignore` 遍历，因此被外层仓库忽略的仓库也会被搜索；会话日志不会被当作文件读取。

移到项目之外某个目录的面板也会搜索该目录——它的会话日志、仓库和文件——并以路径命名在那里找到的内容。

单词按词干匹配（英语和俄语），标识符按其组成部分匹配，因此 `split_command_line`、`splitCommandLine` 和 “split the command line” 能互相匹配，“сессия” 也能找到 “сессии”；俄语单词还会按去掉格词尾的词干匹配，因此词干提取器不认识的名称（“сомбала”“сомбалу”）在任何格中都能找到。以大写输入的两个字母缩写（“CI”“UI”）按整词匹配，而不会匹配更长单词的一部分。代理会传入所查内容的多种表述，每种表述单独排序：结果需要覆盖某一种表述的大部分权重，而罕见词的权重远高于常见词。每个结果都带有一个引用——`session:<id>#<entry>`、`commit:<repo>@<sha>` 或 `file:<path>:<line>`——代理再次调用 `recall` 并把 `open` 设为该引用，即可查看会话结果周围的条目或该提交本身，文件则从给出的行开始读取。搜索可以用 `sources`（`sessions`、`git`、`files`）、`paths`（路径或 glob，与代理给出的任何路径一样相对于面板目录）和 `since`（日期，用于会话和提交）缩小范围。文件结果也以同样方式给出路径，因此代理可以直接读取。

`recall` 只读，因此从不请求权限，计划模式中也是如此；子代理和 `termide --prompt` 运行同样拥有它，代理的 `tools` 列表也可以像其他工具一样把它排除。

开启求解器后，会再进行一次模型调用：读取结果并据此回答问题、注明引用，结果附在回答之后，供代理核对。默认关闭。

三个来源并行搜索，各有自己的时间限制（默认一分钟）：某个来源在其时限内找到的内容与其他结果一起排序，结果会说明哪个来源被停止——当一条缓慢的命令（例如对很长历史执行的 `git log -S`）用尽时限时，git 也包括在内。因此，某个来源很慢的项目（例如根目录在主目录的项目的文件）不会占用其他来源的时间，一次搜索的时长等于最慢的那个来源。

```toml
[ai.recall]
sessions_timeout_secs = 60   # 每个来源最多可搜索的时间
git_timeout_secs = 60
files_timeout_secs = 60
solver = false               # 用一次模型调用根据结果作答
connection = ""              # 由哪个连接的模型作答；留空则使用会话的模型
```

求解器的指示是 `system/recall.md`（见[服务提示词](#服务提示词)）。

## 权限

任何改变你项目的操作都不会未经你同意而发生。当代理想做尚未被允许的事情时，面板输入框上方会出现一张卡片。其标题是意图——“代理想要运行 bash：”——下方以暗淡文字准确显示具体内容（命令或路径）；过长的内容折叠为五行，单击可展开。随后是各行选项：允许一次、本次会话内允许，在 `configured` 和 `auto` 模式下还有在此项目中始终允许和在所有地方始终允许，然后是拒绝、本会话中拒绝、**拒绝并告知代理原因**（你输入一句话，作为原因返回给模型，使其可以换一种方式），以及 **停止运行**。效力超出本次调用的行会显示它们记录的模式（`cargo build *`、某个站点、某个路径）。`↑`/`↓` 加 `Enter`，或该行的数字，用于回答；单击选中一行，再次单击（或 `Enter`）确认，因此误点不会作出回答；`Esc` 停止运行。状态行也会宣布该询问，因此未获得焦点的面板不会在无人察觉时提问；这种面板的标题栏会变为警告色，直到面板获得焦点，运行结束时也是如此。除非该面板正是你眼前、且终端窗口拥有焦点的那个，询问还会响起终端铃声；耗时十秒及以上的运行结束时也会响铃（你主动停止的除外）。在你查看面板之前只响一次；在 `[ai]` 中设置 `bell_on_attention = false` 可关闭铃声。“在此项目中”把规则追加到项目的 `.termide/config.toml`，“在所有地方”追加到全局配置；本会话内的回答一直有效到面板关闭。

每次调用都会保存是谁做出的决定——记录在会话日志中，因此恢复会话后依然可见：规则、计划模式、钩子、附带原因的 auto 模式审查者、无人（没有可询问对象的子代理或无界面运行），或者你——连同你给出的回答及其有效期限。展开的调用会单独用一行显示（`✓ 你在本会话中允许了`、`✗ auto 模式审查者已阻止：…`）；规则无需询问即允许的调用是常见情况，不显示任何内容。规则的拒绝会告诉模型这些规则是你设定的，因此它不会去寻找达到同一目的的其他途径。每种拒绝（规则、计划模式、审查者、你的拒绝、无人可询问的运行）时模型读到的内容位于配置层级代理目录中的 `system/permissions.md`，每种情况一行；编辑它即可按你的方式措辞。

规则按工具分别设置。在匹配的规则中，最严格的胜出，因此 `deny` 总是胜过 `allow`：

```toml
[ai.permissions]
mode = "auto"       # ask | plan | edit | configured | auto（默认）| all — 新会话的初始模式

[ai.permissions.bash]
"cargo *"     = "allow"
"git status*" = "allow"
"git push*"   = "ask"
"rm -rf *"    = "deny"

[ai.permissions.edit]
"src/**" = "allow"
".env"   = "deny"

[ai.permissions.read]
"**/.env*" = "deny"
```

在模式中，`*` 代表任意文本，开头的 `**/` 可省略，因此 `**/.env*` 也匹配项目根目录中的 `.env`。shell 命令按部分匹配：`cargo build && rm -rf target` 需要两半都被允许，任一半被拒绝都会阻止整个命令。shell 自身的关键字不算部分：在 `if [ -f x ]; then make; fi` 中，部分是 `[ -f x ]` 和 `make`，而 `for … in` 头部或结尾的 `fi`、`done` 根本不算部分。命令替换（`$(…)`、反引号）从不会被自动允许，并且只询问携带它的那一部分，而不询问相邻的部分，因此 `cd x && ls && echo $(date)` 只询问 `echo`；替换内部的运算符属于替换本身，不再进一步切分该行。内联脚本是一条命令，而不是其各行所代表的多条命令：带引号的脚本（包括转义引号）和 here-document 的正文（`python3 - <<'EOF'`）都是该命令的数据。

命令的各部分在其运行的目录中判断：termide 会在整行中跟踪 `cd`、`pushd` 和 `popd`，通过路径指定的程序既按书写形式匹配，也按解析后的路径匹配——项目内为相对项目的路径，项目外为绝对路径——因此 `cd /tmp && ./venv/bin/pip install x` 会匹配 `/tmp/venv/bin/pip *`。卡片只询问没有规则或只读默认值能决定的部分，并在命令下方列出它们；本会话内或始终生效的回答会为每个部分记录一条规则。无法确定目录的部分（在 `cd $DIR`、`cd -` 或子 shell 之后）或运行了命令替换的部分会标记为“仅此一次”：不会为其记录规则；当没有任何部分可以记录规则时，卡片只提供允许一次和拒绝。

效力超出本次调用的回答，是在看不到它将覆盖的其余调用的情况下作出的决定，因此卡片只在规则说得足够可信的地方提供它。**始终允许**只为一条其模式界定了作用范围的命令出现：不为由若干部分组成、你一次性作答的命令出现；不为销毁其所触及之物的命令出现（`rm`、`git clean`、`git push`、`git stash drop`、安装或发布软件包）；不为运行*另一*个程序的命令出现，其名称不会被模式显示（`env rm`、`xargs rm`、`./deploy.sh`、`sh -c …`、`python3 -c …`、`make`、`nix run`）。**本次会话内允许**只对销毁性的命令撤回：会话不长，且随面板关闭而结束。因此销毁性的命令每次只允许一次——`all` 才是让整轮运行不经询问通过的模式。**本会话中拒绝**始终提供：它不信任任何事物。撤回的行是消失而非变暗，所以你给出的回答就是被记录的回答。

模式决定哪些规则有效，以及对任何规则都未涵盖的操作如何处理。配置中的 `mode` 是每个新会话的起点（除非你更改，否则为 `auto`），也可以在设置模态窗口 **AI** 部分的权限下设置；面板的 **权限** 标签和 `Shift+Tab` 只更改当前面板的模式。

- **ask** 对所有操作都询问；配置的 `allow` 规则不生效，只有你在本会话中的回答生效。
- **plan** 可以读取和使用网络，拒绝任何可能改变内容的操作；代理以计划作答。见下文。
- **edit** 还可以不经询问地编辑和创建项目内的文件；命令、MCP 工具和项目外的文件会询问。配置的 `allow` 规则不生效。
- **configured** 遵循配置的规则和你在本会话中的回答，对其余操作询问，并提供“始终允许”。
- **auto**（默认）遵循配置的规则（宽泛的 `allow` 规则除外），不经询问地编辑项目内的文件，并把原本需要询问的操作交给审查模型，由它代你允许或阻止。见下文。
- **all** 允许一切。

| | ask | plan | edit | configured | auto | all |
|---|---|---|---|---|---|---|
| 读取项目内文件 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 读取项目外文件 | ? | ? | ? | 规则 / ? | 规则 / R | ✓ |
| 网络搜索 | ? | ✓ | ✓ | 规则 / ? | ✓ | ✓ |
| 获取网页 | ? | ✓ | ✓ | 规则 / ? | 规则 / R | ✓ |
| 编辑项目内文件 | ? | ✗ | ✓ | 规则 / ? | ✓ | ✓ |
| 编辑项目外文件 | ? | ✗ | ? | 规则 / ? | 规则 / R | ✓ |
| 只读命令 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 其他命令、MCP 工具 | ? | ✗ | ? | 规则 / ? | 规则 / R | ✓ |

✓ 表示运行，? 表示询问，✗ 表示拒绝，R 表示由审查者决定，“规则 / ?”表示遵循匹配的规则，没有规则时询问。无论哪种模式，规则的 `deny` 都会拒绝，其 `ask` 都会询问：各模式搁置的是配置的 `allow` 规则，而从不是拒绝规则。你在本会话中的回答在除 `all` 之外的所有模式中都有效。

只读命令是一份只查看内容的简短列表（`ls`、`cat`、`rg`、`git status`、`git log`、`find`、`cd` 等）；重定向到文件会使其失去资格，而把一个流指向另一个流（`2>&1`）或 `/dev/null` 则不会。让这类命令写入文件或运行其他程序的参数同样会使其失去资格：`env` 只有在不带要运行的命令时才算，`git branch` 和 `git remote` 只有在列出时才算，`find` 只有在不带 `-delete`、`-exec`、`-ok`、`-fprint` 或 `-fls` 时才算，而 `sort -o`、带输出文件的 `uniq`、`tree -o`/`-R`、`rg --pre` 和 `git diff --output` 会询问。加载技能从不询问。

### 计划模式

对于希望在改动任何一行之前先看到完整思路的任务，切换到 **plan**（通过标签、`Shift+Tab`，或 `AGENT.md` 中写有 `mode: plan` 的代理）。开启期间，`system/plan.md` 中的指示会加入系统提示词，每个可能改变内容的工具调用都会被拒绝，并附上一条模型会读取的消息，无论规则、本会话的回答或钩子的批准如何：`edit`、`write`、MCP 工具，以及任何不在只读列表中的 shell 命令。读取项目内文件、网络和 `skill` 无需询问即可运行；读取项目外文件会询问。

代理作答后，一张卡片会询问如何处理该计划：

```
┌ 计划模式：执行该计划？ ─┐
│ 1. 是，接受修改         │
│ 2. 是，按配置的规则     │
│ 3. 继续规划             │
└─────────────────────────┘
```

前两项会退出计划模式，分别进入 edit 或 configured，并发送 `system/plan.md` 前置元数据中指定的请求（`request:`），使同一会话在保留计划上下文的情况下继续执行它；第三项（或 `Esc`）保持计划模式，你接下来输入的任何内容都会用于完善计划。计划就是代理在会话中的回答，不会写入任何文件；随后的更改由 `/undo` 检查点覆盖。

### auto 模式

**auto** 适用于你信任其方向、但不想一张接一张回答卡片的运行。规则或安全默认值能决定的，按 `configured` 的方式决定；其余所有原本会弹出卡片的操作都交给审查者——一次单独的模型调用，由它判断该操作是朝你所要求目标的合理一步，还是超出了范围。被允许的调用会运行；被阻止的调用不会运行，模型会读到原因，并被建议改走更安全的路线或告诉你它需要什么。Claude Code 的 auto 模式和 Codex 的 auto-review 也是这样工作的。

审查者看到你在会话中写下的内容和代理发起的调用，但从不看到这些调用的结果，也不看到代理自己的文字。结果是文件和网页中的恶意内容进入上下文的途径，而代理也不应能说服审查者，因此两者都不会到达审查者。你设定的界限（“不要 push”“等我审查”）在你解除之前一直有效，并且在上下文压缩后依然保留：审查者对你的话的记录与模型看到的上下文分开保存。

有些操作从不交给审查者，而是像 `configured` 中那样询问：

- 被 `ask` 规则覆盖的调用；
- 删除文件系统根目录、主目录、工作目录或其上层目录（`rm -rf ~`、`rm -rf .`、`rm -rf *`）；
- 当审查者连续阻止三次或在会话中累计阻止二十次后的一切操作：问题回到你手中，允许其中一个就会把决定权交还给审查者；
- 审查者无法决定的调用：请求失败、超时，或回答中没有结论。

规则的 `deny` 在任何模式下都会拒绝。宽泛的 `allow` 规则——针对整个工具（`"*" = "allow"`）、在解释器、脚本运行器或包装器之后带通配符（`python3*`、`npm run *`、`make*`、`env *`）、针对 `task` 的 `allow`——会被搁置，因为它们会让任何程序绕过审查者运行；像 `"cargo test*"` 这样的窄规则仍然无需审查即可通过。

审查者收到的说明位于配置层级代理目录中的 `system/classify.md`：允许什么、阻止什么，以及结论的格式。编辑它可以向审查者介绍你的基础设施或习惯。默认由会话自身的模型审查；`[ai]` 下的 `auto_reviewer`（设置模态窗口“权限”下的 **auto 模式审查模型**）可以指定另一个连接来审查，通常选一个小而快的模型。每次审查都是在它所决定的操作之前多一次模型调用；读取、项目内的编辑和只读命令从不经过它，不产生任何开销。

```toml
[ai]
auto_reviewer = "haiku"   # 连接名称；留空则由会话的模型审查
```

审查者同样审查委派的工作：子代理的调用会依据你的话和交给它的任务（标记为另一个代理的话）来审查。无界面运行也以同样方式使用它，只是在面板会询问的地方改为拒绝。外部（带 `command` 的）代理把对话留在自己那里，因此在 `auto` 中它的请求像 `configured` 中那样询问。

## AI 菜单

顶部菜单栏中的 **AI** 菜单（位于 **项目** 之后）无需打开面板即可管理代理的资源。它有四个部分——**代理**、**会话**、**技能**、**提示词**——每个部分打开一个用 `↑`/`↓` 浏览的列表；方向键、`Enter` 和鼠标的用法与 **命令** 菜单相同。来自项目（粗体）和全局配置的项合并显示在一起（见[代理目录](#代理目录)）。

- `Enter`（或 `F4`）用于编辑：它在编辑器中打开技能的 `SKILL.md` 或提示词的 `.md`；代理同样打开其 `AGENT.md`；会话则恢复——聚焦已显示它的面板，没有时打开一个新的代理面板。
- `Delete` 删除该项（需确认）；`F2` 重命名它（对会话而言是设置其显示名称）。会话的确认框会显示会话名称（其显示名称、第一个提示或“无标题”）及其 ID。
- 代理、技能和提示词的前两行用于创建新项——**新建（项目内）…** 位于 `.termide/ai/` 下，**新建（全局）…** 位于配置目录下——询问名称并打开新文件。会话通过运行代理创建，因此没有创建行。
- 每个会话行右侧以暗淡文字显示最后一次工作的时间（例如“2 小时前”）。
- 带描述的代理、技能或提示词显示为 `名称 · 描述`（取 `AGENT.md`、`SKILL.md` 或提示词 front matter 中的 `description`）；菜单放不下的行以 `…` 结尾。

在各部分下方，打开过代理面板后，**显示浏览器窗口** 会把代理的网络浏览器显示在屏幕上以便观看其工作（见[网络](#网络)），**隐藏浏览器窗口** 则再次将其隐藏。

## 代理目录

代理自己的文件位于一个 `ai` 目录中，该目录存在于三个层级，优先级从高到低：

1. 面板工作目录中的 `.termide/ai/`；
2. TermIDE 项目根目录中的 `.termide/ai/`（当它是另一个目录时）；
3. TermIDE 配置目录中的 `ai/`（Linux 上为 `~/.config/termide/ai/`，macOS 上为 `~/Library/Application Support/termide/ai/`）。

单个文件取自第一个拥有它的层级。由命名条目组成的目录（代理、技能和提示词模板）是所有层级的并集，较高层级定义的名称会遮蔽较低层级的同名条目。

```
ai/
  agents/default/AGENT.md  默认代理（仅配置层级）
  agents/<name>/AGENT.md   其他代理：设置和提示词模板
  skills/<name>/SKILL.md   技能，见下文
  prompts/<name>.md        提示词模板，以 /name 输入
  commands/<name>          命令脚本，以 /name 输入，见下文
  shims/<command>          命令垫片（仅配置层级），见下文
  mcp.toml                 MCP 服务器，见下文
  mcp-auth.json            MCP 服务器的登录信息（仅配置层级），见 MCP 服务器
  hooks.toml               命令钩子，见下文
  system/compact.md        代理如何总结长会话
  system/compacted.md      总结在上下文中的措辞
  system/plan.md           计划模式告诉代理的内容，以及接受计划时发送的内容
  system/goal.md           评审如何判定 /goal 是否达成
  system/handoff.md        /handoff 如何整理未完成工作的简报
  system/recall.md         recall 的求解器如何根据结果作答
  system/classify.md       auto 模式审查者允许和阻止的内容
  system/permissions.md    调用被拒绝时模型读到的内容
  tools/<name>.md          模型被告知的内置工具的作用
  web/engines/<name>.toml  web_search 的搜索引擎，见“网络”
  web/browser/             网络工具的浏览器配置文件（仅配置层级）
```

面板首次打开时，会布置配置层级：默认代理的 `AGENT.md`、`system/` 和 `tools/` 文件以及搜索引擎写入自带的文本，`skills/`、`prompts/`、`commands/` 和 `shims/` 创建为空目录。旧版本留在 `ai/AGENTS.md` 中的默认代理模板此时会移到 `agents/default/AGENT.md`。termide 会记录它提供的内容（在 `.seeds.toml` 中），并在之后启动时保持这些文件为最新：你从未编辑过的文件会在自带版本变化时刷新，因此升级内容能到达你这里；你编辑过的文件保持不动，新的默认内容写在它旁边的 `<file>.new` 中，供你随时比较和合并。删除某个文件即可恢复自带版本。

### 代理

代理是 `agents/` 下的一个目录。`default` 是面板启动时使用的代理；只有配置层级定义它，因此项目无法改变每个面板启动时使用的代理。任何带有 `AGENT.md` 的目录都定义一个代理（空文件即可；没有该文件的目录不定义代理），你可以通过 **Agent** 状态标签切换到它；选择器会显示每个代理的描述。代理就是它的 `AGENT.md`：front matter 设置它与默认值的不同之处（所有字段均为可选），正文是它自己的提示词模板。没有正文的 `AGENT.md` 使用默认代理的模板，但不采用它的设置；默认代理本身没有正文时使用自带模板。`prompt: none` 表示完全没有系统提示词：模型仍然获得工具，但没有指示。目录中的其余内容归该代理所有：其提示词引用的脚本或检查清单。

```markdown
---
description: Reviews diffs and points at risks
model: Qwen3.8-27B-MTPLX-Optimized-Quality
mode: edit
tools: read, bash
---
You review the changes you are given. …

{{tools}}
```

front matter 由 `键: 值` 行组成；以 `#` 开头的行是注释，值可以加引号。`model` 是配置端点上的模型 id；`mode` 是代理启动时的权限模式（`ask`、`plan`、`edit`、`configured`、`auto` 或 `all`）；`tools` 以逗号分隔列出代理保留的内置工具（列表也可以放在方括号中，或在 `tools:` 下写成 `- 名称` 行的 YAML 列表），包括 `task`；没有该字段时代理拥有全部工具，`tools: []` 则一个也不保留。termide 不读取的键（例如拼写错误的 `descripton:`）会在面板打开时显示在横幅下方。

在会话中途切换代理会为下一个请求替换提示词和工具；只有当定义中指定了模型和模式时，它们才会改变。会话日志会记录这次切换，与 **Model** 标签的切换一样。重新打开的会话会以它最后运行时的代理身份恢复，保存的布局也会记住它。

### 子代理

当有多个代理时，每个使用内置循环的代理都会获得一个 `task` 工具，用于把一项自包含的工作交给另一个代理。受托代理运行自己的循环直到结束——使用自己的提示词、自己的工具、自己的模型——其最终回答作为该工具的结果返回；它沿途的步骤和读取的文件都不会进入主对话。这让简洁的审查者或专注的搜索者可以完成工作而不填满会话，类似于 Claude Code 的 `Task` 工具和 OpenCode 的子会话。

受托代理看不到对话，因此调用方代理必须把一切都写进提示中。它在会话的当前模式下运行（除非其 `AGENT.md` 指定了模式），且没有可询问的人，因此只能做规则和该模式已经允许的事：任何原本需要询问的操作都会被拒绝，并附上它会读取的原因；在 `auto` 中，这些调用改由审查者决定。外部代理（带 `command` 的）不能作为受托代理，子代理本身也没有 `task` 工具，因此委派不会嵌套。停不下来的运行会在五十次模型调用后被截断。

### 外部代理

代理也可以完全是另一个程序：在其 `AGENT.md` 的 front matter 中写入 `command`，面板就会通过 [Agent Client Protocol](https://agentclientprotocol.com) 驱动它，而不是运行内置循环。Claude Code、Codex 和 Gemini CLI 都有 ACP 适配器或原生支持该协议：

```markdown
---
description: Claude Code through its ACP adapter
command: npx -y @agentclientprotocol/claude-agent-acp
---
```

`command` 是程序及其参数，按 shell 的方式拆分为单词（引号保留参数中的空格），但不经过 shell 运行，因此其中的内容不会被展开。程序继承 TermIDE 的环境；每个变量一行 `env.<NAME>: value`，用于添加或覆盖变量，值中的 `$NAME` 和 `${NAME}` 取自 TermIDE 的环境（`env.ANTHROPIC_BASE_URL: http://localhost:8080`）。`timeout` 是等待其启动的秒数，默认 120。

切换到该代理时，程序在后台启动；第一个请求会等待它。它的回答、思考和工具调用像内置代理一样出现在会话中，它通过 TermIDE 读写文件，因此打开的编辑器会跟随它的编辑。它的权限请求按与内置代理相同的规则判断：只读命令，或已被 `[ai.permissions]` 规则或会话授权覆盖的请求，无需卡片即可通过，只有剩下的才会交给你——因此已授权或只读的命令从不会被询问两次。外部代理活动期间 **权限** 标签会消失：它有自己的模式，TermIDE 的模式不会为它循环切换。当代理通过 ACP 公布其模型时，**Model** 标签保留——此时它会列出这些模型并用 `session/set_model` 切换，因此你可以在 TermIDE 中选择代理的模型；不公布模型的代理不显示该标签。技能、提示词模板和 MCP 服务器同样由代理自行负责；其 `AGENT.md` 中的 `model`、`mode`、`tools` 和正文均不适用。切换代理会在同一会话日志上重建对话：之前的消息仍显示在屏幕上，但外部代理并不知道它们，面板会说明这一点。

### 系统提示词

模型收到的提示词由文件组装而成：默认代理 `ai/agents/default/AGENT.md` 的正文，即带有由代理填充的占位符的模板。TermIDE 中没有内置任何提示词文本；下面的模板作为数据文件（`crates/agent-core/assets/agents/default/AGENT.md`）提供，首次使用时写入配置层级，此后以该文件为准。它是所有代理的后备模板，因此项目中的 `.termide/ai/agents/default/` 会被忽略，只有当你选择一个 `AGENT.md` 带有正文的代理时模板才会改变。项目自身的约定写在其 `AGENTS.md` 中，模板会将其作为项目说明纳入（见下文）：

```markdown
You are a coding agent working inside termide, an all-in-one terminal workspace (editor, file manager, terminal, git). You help with software tasks in the current project: you read code, make targeted edits, run commands and report what you did and what you found.

# Tools
{{if tools}}
{{tools}}
{{else}}
No tool is described here. Call only what you are actually offered, and say what you could not check.
{{/if}}

# Guidelines
- Read a file before you change it, and keep edits small and targeted.
- Name file paths clearly when you talk about files.
- Be concise.
- Check the facts of the moment with a tool rather than guess them: run `date` for today's date, read a file for its contents, `git log` for history. State plainly when you did not check.
{{guidelines}}

{{if skills}}
# Skills
When a task matches one of these, load it with the `skill` tool before starting.
{{skills}}
{{/if}}

# Environment
{{environment}}

{{project_instructions}}
```

`{{tools}}` 是每个工具一行的工具列表，`{{guidelines}}` 是工具自身提供的规则，`{{skills}}` 是技能的名称和描述，`{{environment}}` 是工作目录、平台以及是否为 git 仓库，`{{project_instructions}}` 是下文描述的指令文件。提示词有意不带日期：会话会持续数小时，日期会在其中悄悄过期，所以模板改为让模型用工具去核实应时的信息——今日日期用 `date`——而不是凭记忆作答。

`{{if tools}} … {{else}} … {{/if}}` 在没有内容可展示时把该部分从提示词中移除：该名称有内容时保留 `{{if}}` 分支，否则保留 `{{else}}` 分支；不写 `{{else}}` 时整个块消失。因此没有技能的会话不会向模型谈及技能，也不会诱使它调用并不存在的 `skill` 工具。条件标签必须独占一行——行中间的标签、或被填充值内部的标签都保持为普通文本——并且块不能嵌套。块外单独的 `{{name}}` 仍然只是取值，空列表时为 `(none)`，所以在使用块之前写下的模板依旧有效。

你可以改写该文件、删除某个部分或添加自己的内容；省略的占位符就不会发送。`/prompt` 会在查看器中打开组装后的结果，让你准确看到模型收到了什么。

### 服务提示词

TermIDE 自己的提示词也是文件，位于 `system/` 下，并像默认代理的 `AGENT.md` 一样在首次使用时写入。只读取配置层级的 `system/`：项目中的同名目录会被忽略，因此检出的仓库无法改写 termide 的总结、计划和评审方式。压缩（用总结替换长会话中较早部分）使用其中两个：`compact.md` 是总结调用的系统提示词，其前置元数据（`request:`）中是最后的用户轮次，`{{focus}}` 处放入传给 `/compact` 的文字；`compacted.md` 是总结在上下文中变成的消息，`{{summary}}` 代表模型的文本。编辑它们可以改变总结保留的内容或其引入方式。

```
/compact              立即总结
/compact the API      立即总结，侧重于 API
```

`/compact` 是内置命令，与你的模板一起出现在 `/` 列表中；与其他切换一样，它会等待正在运行的任务。会话接近上下文窗口时的自动压缩使用同样的文件。何时开始以及保留多少在 `config.toml` 中设置；省略的键保持默认值：

```toml
[ai.compaction]
enabled = true              # 接近窗口时自动压缩
reserve_tokens = 16384      # 当上下文超过窗口减去此值时开始
keep_recent_tokens = 4096   # 原样保留的最近消息（最多为窗口的四分之一）
```

[计划模式](#计划模式)使用 `plan.md`：模式开启期间，其正文会追加到系统提示词中，其前置元数据中的 `request:` 是接受计划时发送的消息。改写正文可以改变计划必须包含的内容，改写请求可以改变告诉代理继续执行的方式。

`/goal <what to achieve>` 使用 `goal.md`：代理朝目标工作，每轮之后由一个评审——一次独立的只读模型调用——判定目标是否达成。`goal.md` 是该评审的系统提示词，`{{goal}}` 代表目标文本，判定问题位于其前置元数据中（`request:`）。评审回答 `DONE` 或 `CONTINUE` 并附一行理由；若为 `CONTINUE`，代理会带着仍缺少的内容被送回继续工作，直到评审判定完成、某一轮出错或达到五十轮的安全上限。`/goal stop`、`Esc` 或停止运行都会结束它。改写 `goal.md` 可以改变判定目标的严格程度。

```
/goal get the test suite green    工作到评审同意已完成为止
/goal stop                        结束当前目标
```

`/handoff` 使用 `handoff.md`：一次只读模型调用把对话记录提炼成面向后续的简报——目标、已完成的内容、剩余的工作、关键决策、相关文件以及验证方法——供新会话或另一个代理从零接手；这与 `/compact` 不同，后者总结整个对话以便就地继续。`handoff.md` 是该调用的系统提示词，请求位于其前置元数据中。简报就绪后，一张卡片提供两个选项：**保存到 HANDOFF.md 并停止**，保存在面板目录中（另一个代理，即便是读取文件的外部代理，也能接手——请将其加入 `.gitignore`）；或 **以它开始新会话**，用简报作为新会话的开端。改写 `handoff.md` 可以改变简报包含的内容。

[Recall](#recall) 的求解器使用 `recall.md`：根据搜索结果作答的那次调用的系统提示词，问题行位于其前置元数据中（`request:`，`{{question}}` 表示查询）；结果跟在其后。改写它可以改变答案的得出和引用方式。

### 工具文本

模型被告知的每个内置工具的说明同样是文件：`read`、`edit`、`write`、`bash`、`question`、`suggest_command`、`task`、`skill`、`fetch`、`web_search` 和 `recall` 各有一个 `tools/<name>.md`，像 `system/` 文件一样写入并保持最新，且只从配置层级读取。正文是模型随工具看到的描述；前置元数据中的 `snippet:` 是它在系统提示词工具列表中的那一行（省略则该工具不进入列表，但仍可调用），`guideline.1:`、`guideline.2:`……是按顺序加入提示词准则的规则。在 `task.md` 中，`{{agents}}` 处列出可以委派的代理。改写文件即可改变代理使用该工具的方式；工具本身、它的参数和返回内容保持不变。其他键或不以内置工具命名的文件会在面板打开时显示在横幅下方。

```markdown
---
snippet: read a file as numbered lines, paged with offset/limit
guideline.1: Use `read` instead of `cat`, `head` or `sed -n` to look at files.
---
Read a text file. Returns lines prefixed with their 1-based line number. …
```

### 技能

技能是一个包含 `SKILL.md` 的目录，采用 [agentskills.io](https://agentskills.io) 的格式：带 `name` 和 `description` 的 YAML 前置元数据，然后是指令，另加指令引用的任何文件（脚本、检查清单、示例）：

```markdown
---
name: release
description: Cut a release: version bump, changelog, tag, packages
---
# Release

1. Run `scripts/check.sh` …
```

技能从 `ai` 目录三个层级的 `skills/` 中读取，也从面板目录和项目根目录中的 `.agents/skills/` 读取——这是其他代理共用的目录，因此为 Claude Code、Codex 或 pi 编写的技能无需修改即可使用。较高层级的同名技能会遮蔽较低层级的。

进入提示词的只有名称和描述，在 `{{skills}}` 下每个技能一行；指令本身在模型用 `skill` 工具加载技能时才进入对话，该工具返回 `SKILL.md` 的文本，并列出它旁边的文件供模型 `read`。加载技能从不需要权限。只有至少存在一个技能时才会有该工具，并且它不受代理 `tools` 列表的限制。

技能可以像[提示词模板](#提示词模板)一样接受参数：前置元数据中的 `argument-hint` 说明要传入什么，并列在名称之后（`- review <path>: Review a file`），模型随名称一起传入参数，正文中的 `$ARGUMENTS` 和 `$1`…`$9` 会被填充；没有占位符的正文会把参数追加在单独的一行上。

你也可以自己发送技能，形式为 `/name args` 或 `/skill:name args`：其文本（填入参数并列出其文件）会像模板那样作为你的请求发出。在工具集中关闭的技能仍可以这样使用——关闭它只是让它不进入模型的上下文，而不是让你无法使用。

### 提示词模板

提示词模板是一个 Markdown 文件 `prompts/<name>.md`，可以位于三个层级中的任何一个，你以 `/name` 加参数的形式发送它。前置元数据是可选的：`description` 用于选择器，`argument-hint` 说明名称后应输入什么。在正文中，`$ARGUMENTS` 代表名称之后的全部内容，`$1`…`$9` 代表其中的各个单词；没有占位符的正文会把参数追加在单独的一行上。

```markdown
---
description: Review a file for bugs and risks
argument-hint: <path>
---
Review $1. Point at bugs first, style last, and quote the lines you mean.
```

之后 `/review src/parser.rs` 会发送展开后的文本。在会话中，消息以你输入的内容 `/review src/parser.rs` 为标题，模型实际收到的文本折叠在其下；`↑` 调出的是命令而不是文本。输入 `/` 会列出模板，选中一个即把 `/name ` 放入输入框。以 `/` 开头但没有指向任何模板的消息不会被发送；像 `/usr/bin/ls` 这样的路径是普通文本。

### 命令脚本

模板是固定文本，而命令脚本会构建请求：它是 `commands/<name>` 中的可执行文件，以 `/name args` 运行，参数作为其 argv，面板目录作为其工作目录，其标准输出被发送给模型。例如收集 `git diff --staged` 的 `/review`、运行测试并粘贴失败内容的 `/failing`、获取工单的 `/issue 123`。任何语言都可以；头部注释描述它：

```sh
#!/bin/sh
# description: Review the staged changes
# argument-hint: [focus]
# timeout: 30
printf 'Review this diff%s:\n\n' "${1:+ with attention to $1}"
git diff --staged
```

输出作为你的请求出现在会话中，像模板文本一样折叠在命令之下，因此模型收到的内容点一下即可查看。以错误退出、什么都没输出或超时（默认 60 秒）的脚本不会发送任何内容，并报告原因。来自配置层级的脚本是你自己的，会立即运行；随项目或目录附带的脚本会先询问，卡片形式与权限询问相同：运行一次、本次会话内运行、始终运行（写入一条 `[ai.permissions.command]` 规则）或不运行。

内置命令、模板、脚本和技能共用 `/` 名称。当多者定义了同一个名称时，内置命令优先，然后是模板，然后是脚本，最后是技能：项目无法接管 `/clear`，为在 `/` 后输入而写的内容胜过为模型而写的内容。`/skill:name` 总是指向技能，`/` 列表会以这种写法提供名称被占用的技能。多次定义的名称会在面板打开时报告：在欢迎屏幕上显示为 **shadowed** 行，单击后会给出解释；或在恢复的会话下显示为警告。同一类中同一名称出现在多个层级的情况不会报告——较高层级遮蔽较低层级正是层级的工作方式。

### MCP 服务器

来自 [MCP](https://modelcontextprotocol.io) 服务器的工具会加入内置工具。服务器是 `mcp.toml` 中的一个表，可以位于三个层级中的任何一个；较高层级的同名表会替换较低层级的，在较高层级设置 `enabled = false` 可以为某个项目或目录关闭服务器。

```toml
[github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { GITHUB_PERSONAL_ACCESS_TOKEN = "$GITHUB_TOKEN" }   # $NAME 取自你的环境变量
tools = ["search_issues", "get_issue", "create_issue"]      # 可选：子集
timeout_secs = 60                                            # 启动和单次调用
```

服务器要么是 TermIDE 启动并通过 stdio 通信的程序，要么是 TermIDE 以 Streamable HTTP 访问的 URL（每个请求一个 POST，密钥放在 `headers` 里，其中的 `$NAME` 与 `env` 一样取自你的环境）。非 `https` 的 URL 会被拒绝，loopback 除外——这些服务器携带令牌。两种情况下面板都在打开时于后台连接，并在会话中报告已连接或未连接的原因。其工具以 `<server>__<tool>` 的形式出现（例如 `github__search_issues`），这是 OpenAI 兼容端点接受的格式；它们不会列在系统提示词中，模型直接看到它们的模式。每个请求都会携带所有模式，因此对于拥有数十个工具的服务器，值得用 `tools` 缩小范围；当服务器有二十个以上工具且没有这样的列表时，日志会提示这一点。

服务器可以在运行中更换工具。程序在自己的管道上告知；URL 服务器则通过握手后 TermIDE 保持打开的流告知，流断开时会重新打开。两种情况下都会重新列出工具，会话换上新的一组，并用一行提示说明。和任何工具变化一样，这会让下一个请求失去提示词缓存。

配置在面板打开时读取。`/mcp reload` 会在所有层级、从所有 `.mcp.json` 重新读取：不再配置的服务器连同其工具一起离开，新的或改动过的服务器开始连接，失败过的再试一次，已连接且未改动的保持原样。`/mcp reload <server>` 只对一个服务器这样做，即使没有改动也会重新连接它——与工具清单中其标题上的 `[↻]` 相同。单独的 `/mcp` 列出各服务器及其状态。

`headers` 中没有 `Authorization`、却回答 `401` 的 URL 服务器需要 OAuth 登录，会话会提示这一点。`/mcp login <server>` 在浏览器中打开服务器的授权页面；你同意之后，浏览器回到 `127.0.0.1` 上的一次性监听器，服务器随即连接。端点来自服务器自身的元数据；服务器允许时，TermIDE 会把自己注册为客户端；交换使用 PKCE。登录信息保存在配置 `ai/` 目录下的 `mcp-auth.json` 中，仅你可读，按服务器 URL 存放——因此配置了同一 URL 的所有面板和项目共用它——并在过期时续期。`/mcp logout <server>` 会忘记它。浏览器没有打开时（例如通过 SSH），会话会显示地址供手动打开；此时浏览器必须能访问监听器，因此请转发其端口并用 `callback_port` 固定它。不自行注册客户端的服务器需要手动注册的客户端：

```toml
[jira]
url = "https://mcp.example.com/mcp"
oauth = { client_id = "termide", client_secret = "$JIRA_SECRET", scopes = ["read"], callback_port = 8765 }
```

面板工作目录、其上任意一级目录或项目根目录下的 `.mcp.json` 会与它们一并读取，为 Claude Code、Cursor 或 VS Code 配置的仓库无需改动即可带来自己的服务器——这与读取 `CLAUDE.md` 和 `.agents/skills/` 是同样的姿态。这个文件没有标准：MCP 规范把配置留给每个客户端。因此只接受与 termide 相符的部分：`command`、`args`、`env`、`cwd` 和 `tools`，或带 `headers` 和 `oauth`（`clientId`、`clientSecret`、`scopes`、`callbackPort`）的 `url`；根键两者皆可（`mcpServers`，或 VS Code 的 `servers`）；`disabled` 与 `enabled = false` 都读作关闭；`${workspaceFolder}`、`${userHome}` 和 `${env:NAME}` 会被展开。`sse` 服务器会跳过——那是较早的传输方式，请求要发往流先给出的地址，TermIDE 不使用它——带 `${input:…}` 引用的同样跳过：那个引用由另一个工具向你索要密钥，而 termide 只会带着空的密钥启动它。每次跳过都记入日志。同一目录内同名时 `mcp.toml` 胜出；离面板更近的目录优先于两者。因此放在一组仓库之上的一个 `.mcp.json` 会服务于在其中打开的每个面板，这与 Claude Code 的读取方式相同。

MCP 工具像命令一样请求权限：在 `all` 中运行，在 `plan` 中被拒绝，在 `auto` 中交给审查者，在其他模式中询问，除非在 `configured` 中有规则覆盖它。“始终允许”会为该工具名称写入一条规则：

```toml
[ai.permissions.github__search_issues]
"*" = "allow"
```

### 钩子

钩子是 TermIDE 在工具调用前后运行的程序，在 `hooks.toml` 中声明，可以位于三个层级中的任何一个（合并方式与 MCP 服务器相同）。它从标准输入获得 JSON 格式的事件，并在标准输出上以 JSON 回答，这是 Claude Code、Gemini CLI 和 Cursor 共用的格式：

```toml
[no-force-push]
event = "before_tool_call"      # 或 after_tool_call
tools = ["bash"]                # 模式；省略时匹配所有工具
command = "scripts/guard.sh"    # 在面板目录中运行
timeout_secs = 30
```

调用之前，输入为 `{"event","hook","cwd","tool","arguments"}`。程序可以输出 `{"decision": "block", "reason": "…"}` 跳过该调用（原因会交给模型），输出 `{"decision": "allow"}` 不经权限询问直接运行，或输出 `{"arguments": {…}}` 以其他参数运行；没有决定或为 `"ask"` 时由权限规则决定。以代码 2 退出同样会阻止调用，并以标准错误作为原因。调用之后，输入还带有 `"result": {"text", "is_error"}`，`{"text": "…"}` 会改写模型看到的内容；退出代码 2 会把结果变为错误，并以标准错误作为其文本。钩子按名称顺序在权限规则之前运行；以其他方式失败或超时的钩子会被记录并忽略，因此出故障的钩子永远不会让代理停止。

### 命令垫片

垫片（shim）是 `shims/` 中以某个命令命名的可执行文件。内置代理运行 shell 命令时，`shims/` 会被加到 `bash` 工具的 `PATH` 前面，因此垫片会遮蔽真正的命令——包括在管道中（`… | grep …`）。这是由你手动扩展的节省令牌的层：一个运行更精简搜索的 `shims/grep`、一个裁剪噪声的 `shims/cat`，各自输出模型读取的紧凑结果。（`bash` 工具本身也会清理输出；垫片是由你控制的那部分。）

```sh
# ~/.config/termide/ai/shims/rg  (chmod +x)
#!/bin/sh
# 限制 ripgrep 每个文件只输出少量匹配，其余交给真正的 rg。
exec /usr/bin/rg --max-count 5 "$@"
```

由于垫片会在每个匹配的命令上静默运行，只有配置层级的 `shims/` 会被采用——从不采用项目或工作目录中的，因此检出的代码无法植入垫片。垫片是任何语言编写的普通可执行文件；通过绝对路径（或 `PATH= command <tool>`）调用真正的工具，以免调用到自己。外部（ACP）代理运行自己的命令，不经过垫片。

### 项目指令

代理会从文件系统根目录到面板工作目录之间的每个目录读取 `AGENTS.md`（或同一目录中的 `CLAUDE.md`），越具体的越靠后，因此面板目录中的文件优先于项目的文件。即使面板在项目之外工作，项目根目录的文件也会被包含。把你的约定放在那里，代理就会遵循；全局规则则写进模板——默认代理的 `AGENT.md`——本身。超过 32 KiB 的文件会被跳过。

## 会话历史

每个会话都以 JSON Lines 格式写入日志，每个会话一个文件，位于 TermIDE 配置目录中的 `ai/sessions/<面板目录的路径>/` 下，与代理并列。日志记录会话开始时的模型和代理以及每次切换，因此重新打开的会话会在最后使用的模型上、以最后使用的代理身份继续。当会话接近模型的上下文窗口时，代理会用自己写的总结替换较早的部分，并原样保留最近的消息；面板会在发生时提示，`/compact` 可按需执行（见[服务提示词](#服务提示词)）。`/undo` 和回退都会写入一条 `rewind` 条目：日志保留所有消息，但分支从被撤销的请求之前继续，重新打开时也是如此。

当 TermIDE 重新打开保存的布局时，代理面板会随之恢复，并继续它原来所在的会话，使用该会话的模型和代理。如果日志已被删除，面板会开始一个新会话；如果不再配置任何模型，该面板会从布局中省略。

## 从命令行使用

`termide --prompt "<prompt>"` 不打开界面运行一个代理任务，把回答打印到 stdout，然后退出。它就是面板的代理——相同的 `ai` 目录、代理、工具和权限规则——以无界面方式驱动，适用于脚本、管道和 CI。

```
termide --prompt "summarise what changed in src/main.rs"
git diff | termide --prompt -          # 从 stdin 读取提示
termide --prompt "run the tests and report failures" --agent runner
```

回答是 stdout 上唯一的内容，因此可以干净地用于管道；工具活动和错误输出到 stderr。`--agent` 选择已定义的代理之一，否则使用默认代理。成功时退出代码为 `0`，失败时为 `1`，被中断时为 `130`。

如需机器可读的结果，添加 `--output json`：它不再流式输出，而是在结束时打印一个 JSON 对象，包含回答、令牌用量、运行中进行的工具调用及其状态。`--output stream-json` 则在运行过程中每行打印一个 JSON 对象——每个工具一个 `tool_use` 和 `tool_result`，每个回答一个 `message`，以及最后一行 `result`，其字段与 `json` 相同——适合需要实时跟踪长时间运行的调用方。

```
termide --prompt "count the TODOs in src" --output json
# {"ok":true,"answer":"7","stop_reason":"stop","model":"…","provider":"…",
#  "usage":{"input":…,"output":…,"cache_read":…,"cache_write":…},
#  "tools":[{"name":"bash","subject":"rg -c TODO src","error":false}],"error":null}
```

没有人在旁回答权限卡片，因此无界面运行只做规则和模式已经允许的事：任何需要询问的操作都会被拒绝，并附上模型会读取的原因。在默认的 `auto` 模式下，规则未决定的操作由审查者决定，它无法决定的调用会被拒绝；在 `configured` 中，为任务所需的确切命令和路径添加 `allow` 规则，或为无人值守的工作设置 `mode = "all"`。计划模式脱离面板没有意义，被视为 `auto`；外部（带 `command` 的）代理不能以这种方式运行。

`termide --recall "<查询>"` 在不打开界面的情况下执行 [recall](#recall) 搜索并打印结果——即代理会读到的文本——或者配合 `--output json` 打印一个包含结果（以及开启时求解器的回答）的对象。什么也没找到时退出码为 `1`。其他代理可以通过自己的 shell 调用它，你也可以用它快速查看 `recall` 对某个问题能找到什么。

```
termide --recall "why did we drop tokio"
termide --recall "compaction summary" --output json
```
