guideline.1: Close a terminal session with `terminals` once you no longer need it — a server you no longer test against, a shell you are done with — rather than leaving it open; it ends everything that runs in it.
guideline.2: To drive an interactive program — a REPL, a debugger, a prompt asking for confirmation — start it with `shell` and `background`, then talk to it with `terminals` `send`, waiting for its prompt with `wait_for`.
---
Your terminal sessions: the shells `shell` opened for `session` and `background`. Without `action`, or with `list`, lists them with what each is doing. `read` returns what `session` printed since you last read it (a command's own output counts as read). `send` types `input` into it — a line break inside it is Enter, so press Enter in `keys` to submit the line — then presses `keys` (`Enter`, `Tab`, `Esc`, `Up`, `Ctrl+C`, `Alt+b`…), and waits: until `wait_for` appears in the output, until the shell finishes a command typed at its prompt (which comes back with its exit code), until the output stops for `quiet_ms` (500 ms when neither is given), or `timeout` seconds at most (default 10, a backstop for programs like REPLs that report nothing); it returns what came after the input, or the screen when a full-screen program has it. `screen` returns what the terminal shows now, with the cursor. `interrupt` sends it Ctrl+C; `close` ends it and everything running in it. A session ends with your session, too.
